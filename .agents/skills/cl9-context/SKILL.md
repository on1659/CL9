# CL9 프로젝트 맥락 읽기

CL9의 기존 기획과 설계를 찾아 읽고, 사용자 요청을 그 맥락에 맞춰 처리한다.
이 스킬은 프로젝트 문서의 읽기 경로를 제공한다. 상세 기획과 진행 상태는 원문에서 확인한다.

## 프로젝트 루트

이 스킬 폴더에서 `../../..`가 프로젝트 루트다. 아래 경로는 모두 프로젝트 루트 기준이다.
현재 작업 폴더가 하위 디렉터리여도 이 루트를 기준으로 문서를 찾는다.

## 콘셉트 확인

`CLAUDE.md`, `docs/plan/overview.md`, `docs/plan/README.md`를 읽는다.
이미 문서가 컨텍스트에 있고 변경되지 않았다면 그 내용을 재사용한다.
사용자가 "우리 프로젝트", "우리 콘셉트", "기획 보여?"라고 물으면 이 문서를 먼저 확인한다.

콘셉트 설명은 `overview.md`를 근거로 작성하고, 현재 문서에서 확인한 사실과
새로 제안하는 아이디어를 구분한다. 문서가 없거나 읽을 수 없으면 누락된 경로를 알리고
게임 장르·규칙·진행 상태를 추측하지 않는다.

## 요청별 추가 문서

| 필요한 맥락 | 문서 |
|---|---|
| 하루의 게임 루프 | `docs/plan/loop.md` |
| 경제·가격·밸런스 관계 | `docs/plan/economy.md`와 `docs/plan/README.md`가 안내하는 관련 데이터 문서 |
| 목적지·아이템·몬스터 등 세부 기획 | `docs/plan/README.md`에서 해당 데이터 문서 선택 |
| 다음 작업·진행 상태·구현 착수 | `docs/plan/build-order.md`와 관련 git 이력 |
| UE 구현 방향 | `docs/conventions.md`, `docs/systems/README.md`와 관련 시스템 문서 |
| 모델·애니메이션·에셋 제작 | `docs/asset/README.md` |
| 에디터·빌드·PIE·세션 조율 | `docs/workflow/sessions.md` |
| 기존 결정과 문서 충돌 | `docs/decisions.md`와 충돌한 문서 |

관련 문서만 추가로 읽는다. 구현하거나 작업 순서를 제안하기 전에는 `build-order.md`를
확인하고, 체크리스트와 실제 코드·git 이력을 대조해 완료 여부를 판단한다.
문서에 없는 구현을 완료된 것으로 설명하지 않는다.

## 정본 유지

기획은 `docs/plan/`, UE 설계는 `docs/conventions.md`와 `docs/systems/`를 근거로 삼는다.
문서 간 충돌이 있으면 `docs/decisions.md`의 관련 결정을 확인한다. 해결되지 않은 충돌은
사용자에게 구체적으로 알린다. 새 제안을 기존 결정으로 취급하지 않는다.

이 스킬과 `AGENTS.md`에는 상세 규칙·수치·진행 상태를 쌓지 않는다.
사용자가 기획 변경을 요청하면 해당 정본 문서를 수정하고, 필요한 경우 색인만 갱신한다.
