## 0. 전체 목록을 확정 가능한 작업으로 바꾸기

첫 실행에서 `docs/asset/catalog.md`를 만들고, 기획·현재 데이터 행·소비 코드·기존 에셋과 대조한다.
인덱스만 읽고 나머지를 추정하지 않는다. 아이템의 상태별 변형과 필요한 클립도 하위 목록으로 기록한다.

각 행: ID / 분류 / Alias·SubAlias / 등장 위치·근거 / 신규·수정·재사용 / 모델 상태 /
리깅 상태 / 필요한 클립과 상태 / 재질·텍스처 / 충돌·LOD / UE 연결 / QA 증거 /
파일 경로 / 차단 사유 / 다음 행동.
해당 없는 리깅/클립은 `N/A`와 이유를 적는다. 미제작을 N/A로 덮지 않는다.

포함 대상:

- 재료·요리·장비·도구·운반물과 날것/익음/탐·필요한 균열/파손 표현.
- 벽·바닥·천장·문·울타리·계단 관련 조각·둥지·가구·배치 소품·트럭·조리대·반납 시설.
- 기획/데이터에 존재하는 동물 종과 실제 상태가 요구하는 이동·경직·잡기·경보·죽음 등.
- 선택 가능한 플레이어 외형, 슬롯 색, 풀바디와 1인칭 팔, 운반/사용/피격 동작.

첫 실행 시점의 기획/실제 등장 자산을 기준 목록으로 삼고 변경을 기록한다. 단순 미래 예시인
벌집 등은 미정 후보로 분리한다. 실제 게임에 필요한 항목의 누락은 발견 즉시 목록에 보충한다.
목록을 작게 줄여 완료를 선언하거나 합의 없는 신규 종·스테이지로 범위를 늘리지 않는다.
재사용은 외형/호환성/라이선스/검수 근거가 있는 경우에 기록하며, 구매 팩이 있다는 이유로
신규 제작 요청 전체를 완료 처리하지 않는다. 외부 유료 서비스·구매는 별도 허용 없이는 쓰지 않는다.

## 반복 단위 — 작은 묶음 하나를 끝까지

매 반복마다 `docs/asset/iterations/NNN.md` 하나에 계획·수행·검수·후속 행동을 기록한다.

1. **선택:** 목록에서 다음 미완료 묶음을 선택. 이전 묶음의 실패 수정이 우선이다.
2. **카드:** `docs/asset/<분류>/<id>.md`에 외형·실제 cm·피벗·리그·클립·UE 소비처를 명시.
3. **제작:** MCP 씬 조회 → 기존 작업 보존 → 모델/UV/재질 → 필요한 리깅/애니메이션.
4. **Blender 검수:** 실측·노멀·UV·가중치·변형·루프·발 접지. 중립광/야간/손전등 화면으로 시각 확인.
5. **내보내기:** `.blend`, 개별 FBX, 사용 텍스처/머티리얼 값, 미리보기, manifest 저장.
6. **UE 검수:** 단위·축·크기·충돌·리그·클립·재질·LOD를 확인하고 데이터/BP로 연결.
7. **실사용 검수:** 운반/요리/추격/캐릭터 시점/모듈 조립 등 해당 시나리오와 필요한 2인 PIE 확인.
8. **감사:** 요구사항 대비 누락·품질 문제·파일 존재·증거를 확인. 실패한 필수 항목은 수정 후 다시 검수.
9. **갱신:** catalog, 제작 카드, 진행 기록, 검증된 규격을 업데이트하고 바로 다음 묶음으로 진행.

계획·문서·샘플 렌더에서 멈추지 않는다. 일반적인 디자인/수치 초안 선택은 이유를 기록하고 진행한다.
기존 씬을 파괴하거나 스켈레톤 계약을 깨야 하는 등 되돌리기 어려운 결정은 현재 사용자 권한 범위부터 확인한다.
사용자가 답해야만 풀리는 질문이 있어도 독립적으로 가능한 나머지 제작은 계속한다.

## 단계 감지와 순서

| 파일/상태 | 다음 행동 |
|---|---|
| catalog 없음 | 전체 목록 작성 후 첫 제작/검수로 진입 |
| 기존 원본 있고 검수 없음 | 원본 조회·실측부터, 재생성하지 않음 |
| Blender 통과, UE 미검수 | 해당 에셋의 첫 UE 왕복 검수 |
| 필수 QA 실패 | 원인을 고치고 실패한 검사 재실행 |
| 묶음 통과, 감사 없음 | 증거 기반 감사 작성 |
| 감사 완료 | 다음 미완료 묶음 선택 |
| 전체 필수 행과 검수 완료 | 최종 누락 감사 후 goal 완료 |

순서 초안은 양계장 샘플의 UE 왕복 → 계란 상태 체인 → 닭 한 종의 전체 리그/클립 →
플레이어 풀바디/팔의 대표 운반 동작 → 양계장 전체 조각/소품 → 나머지 아이템/종/외형이다.
다음 묶음은 실제 의존성과 감사 결과로 조정한다. 모든 맵을 만든 뒤 리그 문제를 처음 발견하지 않게 한다.
현재 씬/에셋이 연결되지 않는다면 먼저 테스트용 에셋으로 검수하고 검증된 변경만 실제 행에 적용한다.

## UE5 실사용 테스트 — 매 묶음 필수

2026-09-10 사용자 요청: **제작한 에셋을 UE5에서 실제 테스트한다.** 파일 임포트 성공,
에셋 미리보기나 Blender 렌더만으로 검수를 끝내지 않는다. 모든 제작을 마친 뒤 몰아서
테스트하지 않고, 첫 대표 에셋부터 PIE까지 왕복하여 같은 문제를 대량 복제하지 않는다.

엔진은 `CLAUDE.md`에 지정된 **UE 5.8**을 사용한다. 프로젝트 연결만 보고 다른 설치 버전으로 열지 않는다.
에디터의 실행 상태·로드된 프로젝트·미저장 작업을 먼저 확인한다. UE 도구의 실제 기능을 조회하고
가능한 MCP/에디터 자동화로 수행한다. 지원되지 않는 테스트는 수행했다고 쓰지 않는다.
기본 절차와 키/치트는 [PIE 시나리오](../testing/pie-scenarios.md)를 따른다.

| 분류 | 실제 UE5 테스트 | 통과 조건 |
|---|---|---|
| 아이템 | 실제 데이터 행으로 스폰 → 줍기/놓기 → 품 교체 → 던지기 → 해당 요리/파손/납품 | 자동 배율 후 크기·피벗·손 위치가 맞고, 바닥 관통/과도한 떠 있음/상태 외형 누락이 없음 |
| 맵 | 조각 표/모듈에 연결 → 서로 다른 시드로 생성 → 직접 이동·문 통과·계단·운반 → 손전등/정전 | 이음매·두께·개구부·층간 바닥/천장·충돌·시야 가림이 실제 동선과 일치 |
| 몬스터 | 실제 종 스폰 → 배회/추격/방향 전환 → 경직/종별 잡기·경보 → 죽음 | 정면·발 접지·재생 속도·루프·상태 전환·예고가 맞고 메시가 늘어나거나 잘못 회전하지 않음 |
| 캐릭터 | 1인칭/타인 시점에서 걷기·달리기·점프·운반·사용·피격·넘어짐 | 팔과 몸 가시성, 그립, 슬롯 색, 카메라 클리핑과 관절 변형이 정상 |
| 공통 | 대표 동시 노출 장면과 2인 리슨 PIE | 호스트/클라이언트 표현과 부착이 일치하고 새 에셋 적용으로 뚜렷한 성능 저하/오류가 없음 |

테스트 전에 대상 데이터 행·기대 치수·시나리오·확인할 화면을 정하고, 결과에는 날짜·엔진/빌드·
레벨·시드(맵)·참가 인원·입력/상태·관찰·로그·스크린샷/영상 경로를 남긴다.
성능은 같은 장면/설정에서 변경 전후를 비교한다. 플랫폼 성능 목표가 없으면 임의의 FPS 보증을 만들지 않는다.
새 종류의 대표 테스트를 통과하면 단순 색 변형 등은 영향 범위에 맞춰 검수를 줄일 수 있다.

**실패 → Blender/내보내기/데이터·AnimBP 중 원인을 수정 → 재임포트 → 실패 시나리오 재실행**을 반복한다.
파일을 연결한 후 다시 원본을 바꿨다면 이전 UE 통과 기록은 그 변경에 대해 재검증한다.
에디터/도구 문제로 PIE가 불가능하면 `UE 테스트 차단`으로 기록하고 전체 완료를 선언하지 않는다.

## 완료 게이트

필수 행마다 아래를 만족해야 `완료`다.

- 편집 가능한 원본·실제 납품 파일·출처·제작 카드가 있고 상대경로/누락 리소스 문제가 없다.
- 해당 애니메이션이 모두 있으며, 실제 행동 시간을 따르고 Root Motion/Notify가 판정을 바꾸지 않는다.
- 중립광/야간에서 형태·재질이 의도대로 보이고, 손/발/관절·카메라·반복 이음매가 깨지지 않는다.
- UE에서 임포트와 소비 경로를 검수했다. 아이템 자동 배율, 캐릭터 기존 Yaw, 몬스터 바닥 원점 등 실제 계약을 지킨다.
- 적용 가능한 충돌/LOD/대표 동시 노출 성능과 상태 복제를 검수했다. 미실행은 통과가 아니다.
- 검수에서 발견한 필수 결함이 0개다. 새 장식 취향만으로 통과한 에셋을 무한 재작업하지 않는다.

최종적으로 catalog의 필수 미완료 행 0, 누락 클립/상태 0, 필수 QA 실패 0이어야 한다.
`docs/asset/final-audit.md`(미작성 — 2026-09-21 확인; 실재하는 진행·목록 문서는 `docs/asset/production-progress.md`·`docs/asset/catalog.md`)에 카테고리별 개수·파일·검수 증거·잔여 선택 개선을 적는다.
검수 불가 항목을 완료로 올리거나 기준을 낮춰 목표를 끝내지 않는다.

## 작업 경계와 복구

- 사용자가 편집 중인 씬·레벨·다른 변경을 보존한다. 시작 시 dirty 상태를 확인하고 자신이 만든 변경을 추적한다.
- Blender 원본은 에셋별 저장, 공유 데이터 수정은 인스턴스 영향 확인. 장시간 렌더 전에 저장한다.
- MCP 실패 시 실제 연결/로그/현재 씬을 조회하고 가능한 복구를 수행한다. 승인 거부를 다른 경로로 우회하지 않는다.
- 도구/엔진이 막혀도 모델·리깅·문서 등 독립 작업을 진행. UE 미검수는 별도 상태로 유지한다.
- 실행 불가 상태가 반복되고 독립 작업도 없으면 진행 기록에 오류·시도·재개 조건을 남기고 사용자에게 알린다.
  active goal 상태 변경은 런타임 도구의 차단 조건을 따른다. 사용자 중지/일시정지는 즉시 존중한다.
- 새 세션/컨텍스트 축약 뒤에는 기록과 실제 파일을 대조해 재개한다. 같은 완료 묶음을 처음부터 만들지 않는다.
- 아트 연결을 위한 데이터/BP/AnimBP 작업은 범위에 포함. 게임 밸런스·네트워크·맵 생성기 개편은 범위 밖이다.
  큰 런타임 변경이 필요하면 그 의존성을 기록하고 다른 가능한 자산을 진행한다.
- 커밋/푸시/배포, 외부 구매, 모델 변경, 별도 자동화/하위 에이전트 생성은 이 문서만으로 수행하지 않는다.
- 문서 변경은 링크/UTF-8 검사와 `git diff --check`. C++ 변경이 별도로 허용된 경우 저장소 빌드/PIE 규칙을 따른다.

## 진행 보고 형식

각 묶음 종료 시: 완료 ID / Blender·UE 각각의 검수 / 남은 필수 개수 / 다음 ID를 짧게 보고한다.
시각 결과를 미리보기로 보여 주고 다음 묶음을 계속한다. 동일 상태를 반복 보고하지 않는다.
진행 기록에는 현재 파일·씬·미완료 명령·오류·다음에 실행할 구체적 동작을 남긴다.

## 붙여 넣을 실행 프롬프트

```text
/goal D:\Work\unreal\CL9\docs\goal\asset-production-loop.md를 실행 지침으로 삼아 CL9의 현재 기획과 실제 게임에 등장하는 모든 아이템·맵 조각/소품·몬스터·캐릭터의 모델링, 재질/텍스처, 필요한 리깅과 애니메이션, UE 연결 검수를 완료하라. 먼저 전체 에셋 catalog를 만들고 기존 양계장 샘플을 이어 써라. Blender MCP로 제작 → 시각·기술 검수 → FBX 납품 → UE 실사용 검수 → 규격/진행 기록 갱신 → 다음 미완료 묶음을 반복하라. 매 묶음마다 계속할지 묻거나 계획만 작성하고 끝내지 말라. 전체 필수 행과 클립이 검수 통과할 때까지 진행하되, 막힌 항목은 완료 처리하지 말고 독립 작업을 계속하라. 사용자 입력 없이는 더 진행할 수 없거나 런타임 제한에 도달하면 정확한 재개 지점을 남겨라.
```

goal 시작/조회/일시정지/재개는 [공식 Follow a goal 안내](https://learn.chatgpt.com/use-cases/follow-goals)를 따른다.
실행은 앱·도구 연결과 사용량 제한의 영향을 받는다. 이 문서는 PC 종료 중 실행이나 제한 없는 계속 실행을 보장하지 않는다.
