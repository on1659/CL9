## 한 줄 목표

세션이 빌드 전에 다른 활성 세션을 전부 뒤져 가며 협상하던 것을 없애고, **빌드는 로컬 브로커 하나에 요청만 하게 한다.**
브로커가 큐·묶음·실행·기록을 맡고, 사용자는 대기·시작 시각을 직접 제어하며, 아무 일이 없으면 브로커는 스스로 꺼진다.

## 배경

지금 절차([docs/workflow/sessions.md](../workflow/sessions.md) "빌드 — 복사해서 쓰는 절차")는 빌드하려는 세션이
`ListAgents` → 에디터 쓰는 세션마다 `SendMessage` → 2분 무응답이면 진행 → `cl9_lock.py acquire` 를 직접 한다.
세션이 늘수록 느리고, 무응답 세션이 있으면 판단이 갈리며, 사용자는 끼어들 수 없다. 사용자 지시(2026-10-15):

- 빌드는 새로 만드는 창구에 물어봐서, 사용자가 **대기할지·얼마나 할지** 제어할 수 있게 한다.
- 빌드 에러가 나면 어느 세션 오류인지 **판단**해서 각 세션이 고치고 **다시 빌드를 요청**하게 한다.
- 아무 일도 없으면 꺼진다. 세션이 쓰기 좋은 방식이면 형태는 상관없다.
- 브로커 자체는 토큰을 쓰지 않는다(파이썬 프로세스). 판단은 오류를 받은 세션(LLM)이 한다.

## 하지 않는 것 (이 목표 밖)

- 브로커가 `save_assets` 를 대신 부르는 것 — **요청 전에 자기 에셋을 저장하는 건 요청 세션 몫**이다(클라이언트가 상기 문구를 출력).
- 브로커가 오류를 스스로 고치거나 LLM 을 부르는 것(`claude -p` 분류는 필요해질 때 따로).
- 에디터를 쓰는 세션에 대한 `SendMessage` 통지 — 임대가 살아 있는 동안은 브로커가 시작하지 않고 이유를 큐에 보여 준다.
- 훅 변경.

## 성공 기준 (검증 가능)

1. 같은 종류 요청 3건(세션 2개)이 묶음 대기 안에 들어오면 실행기는 **한 번** 불리고 3개 티켓이 모두 같은 결과를 받는다.
2. 보류 중에는 시작하지 않고, 재개하면 시작한다. "N분 뒤"는 그 시각 전에 시작하지 않는다. "지금"은 셋을 모두 무시한다.
3. 실행기가 `blocked`(남의 잠금)를 돌려주면 티켓은 큐에 남고 사유가 보이며 다음 틱에 재시도한다.
4. 실패 시 결과에 오류 항목마다 `file · line · code · owns · shared · dirty · newer_than_last_ok` 가 있다.
5. 같은 오류 서명이 연속 2회 실패하면 `needs_user` 가 켜진다. 성공하면 꺼진다.
6. 큐가 비고 `idle_exit_s` 가 지나면 종료 신호가 선다. 큐가 있으면 서지 않는다.
7. `builds.jsonl` 에 묶음마다 한 줄이 남고, 요청 세션·사유·HEAD·수정 파일이 있다.
8. HTTP: 요청 → 장기 대기 조회 → 제어 동작이 동작하고, `Host` 가 로컬이 아니거나 JSON 이 아닌 POST 는 거부된다.
9. 실제 UBT 실행은 `compile` 종류로 한 번 돌려 본다(`COMPILE OK`와 같은 결과). 정식 `build`(에디터 종료)는 에디터를 쓰는 사용자 환경에 영향이 크므로 사용자 확인 후 한 번 돌린다.
