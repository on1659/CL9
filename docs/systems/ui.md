# UI/UX 설계 (HUD 레이아웃)

> 화면에 무엇을 띄우고 무엇을 띄우지 않는가. 미니맵 표시는 전역 금지가 아니라
> **개체별 값(`bShowOnMinimap`)**으로 제어한다. 스태미나는 흔들림과 HUD 바를 함께 쓴다
> (2026-09-05 번복 — rules.md의 "바 없이 흔들림만" 규칙의 유일한 예외다).

## HUD 방침

- **미니맵 표시는 개체별 값이다** — 몬스터·아이템의 `bShowOnMinimap`(기본 false)을 미니맵
  시스템이 읽는다. 전역 금지 원칙이 아니라 표에서 켜고 끈다
- **스태미나는 바 + 화면 흔들림 둘 다** (2026-09-05 번복 — decisions.md). 남은 양과 탈진
  래치 해제 시점이 흔들림만으로는 안 읽혀서다. 운반 흔들림은 여전히 바 없음
- 능력 바(회피/공격/아이템) 없음 — 그런 조작이 없다
- **WBP의 모든 텍스트는 String Table `CL9` 키 참조**다 — 텍스트 칸에 한글을 직접 치지 않는다. C++이
  덮어쓰는 자리표시자도 같은 키. 키 규칙·추가 절차는 [localization.md](localization.md) (2026-09-12)
- 라운드 목표금액·달성률 표시 없음 — 정산은 이틀 주기 기간 수입이다
- HP 표시는 **하트 칸**이다 (2026-09-08 사용자: "나중에 바꿀 수만 있으면 된다"). 좌상단
  `HpBox`의 **자식 하나가 HP 하나**이고, 남은 만큼 앞에서부터 켜고 나머지는 접는다. **칸 안에
  무엇이 들어 있는지 C++은 모른다** — 지금은 칸마다 오버레이 안에 글자 ♥가 들어 있고, 하트
  이미지가 생기면 같은 오버레이에 Image를 얹기만 하면 된다(코드는 그대로 두고 WBP_HUD만
  고친다). 칸보다 HP가 많거나 칸이 아예 없으면 `HpText`의 숫자("HP 12")로 물러선다.
  바·퍼센트는 쓰지 않는다 (관리 자원화 방지 — 흔들림 규칙과 같은 결)

## 게임 중 HUD

HUD는 CL9 GameState·PlayerState가 도착해 배선(`TryWire`)된 뒤에야 보인다 — 그 전에는, 그리고 시작 레벨에서는 끝까지
접혀 있다(2026-10-05, [ui_system.md](ui_system.md) 데이터 연결).

```
┌─────────────────────────────────────────────────┐
│ [상단] N일차 · 밤 시계 (NightLength 잔여)        │
│        장소 알림 (조리대 근처 — "부엌", 2.5초)   │
│ [좌상단] HP · 스태미나 바 · 이더 (판 공유 자금)  │
│                       [우상단] 마이크 아이콘 · 말하는 사람 │
│                                                 │
│              [게임 플레이 화면 (3D)]             │
│                                                 │
│ [좌하단] 진행 중 주문 (남은 재료 · 마감 일수)    │
│ [하단 중앙] 퀵슬롯 4칸 (프롬프트 위)             │
│            첫 줍기 힌트 (처음 한 번, 4초)        │
│            상호작용 프롬프트 · 던지기 차징       │
│ [우하단] 머리 장비 (헤드램프)                    │
└─────────────────────────────────────────────────┘
```

### 퀵슬롯 (2026-09-13)

**리썰식이다** (`docs/reference/image/player/lethal_hud.jpeg` — 2026-09-13 사용자 "리썰처럼"): 정사각 칸이 하단 중앙에
나란히, 검은 반투명 바탕에 얇은 흰 테두리, 칸 안에는 든 아이템의 아이콘뿐 — 번호도 이름도 없다. **든 칸만 밝고(흰색 100%)
나머지는 흐리다(흰색 40%)** — 노란 강조·색 구분은 폐기. 상태별 아이콘 구분(들었을 때/아닐 때 다른 그림)은 없다.

```
WBP_HUD
  └─ QuickSlotBox (HorizontalBox, BindWidgetOptional — 하단 중앙, PromptText 위)
       ├─ WBP_QuickSlot ×4   ← C++이 QuickSlotClass로 런타임에 만들어 붙인다
       │    (UCL9QuickSlotWidget)
       │    └─ SizeBox 64×64 (정사각)
       │         └─ Frame (Border, BindWidget — 흰 얇은 테두리 브러시 2px, 배경 없음. 브러시 색 = 밝기)
       │              └─ Background (Border — 검정 α0.5)
       │                   └─ Overlay
       │                        ├─ Icon (Image 48×48 가운데, BindWidgetOptional — 텍스처는 C++이 세팅)
       │                        └─ NameText (TextBlock 12pt 가운데 줄바꿈, BindWidget — 아이콘 없는 행의 폴백)
```

| `UCL9QuickSlotWidget` 프로퍼티 (Category `QuickSlot`) | 기본 | 뜻 |
|---|---|---|
| `ActiveColor` | (1, 1, 1, 1) | 손에 들린(활성) 칸 — 테두리·아이콘·이름에 같이 건다 |
| `InactiveColor` | (1, 1, 1, 0.4) | 나머지 칸 |

- **칸 수는 규칙이 정한다** — HUD가 `CL9Rules.QuickSlots`개를 `QuickSlotClass`(WBP_HUD 프로퍼티, `WBP_QuickSlot`)로
  만들어 `QuickSlotBox`에 붙인다. 디자이너에 칸을 미리 놓지 않는다(HP 하트 칸과 반대 — 하트는 칸 수가 표현이고, 퀵슬롯은
  칸 수가 규칙이라서). 수가 달라질 때만 다시 만들고 그 뒤로는 내용만 갱신한다.
- **갱신은 `PlayerState.OnCarryChanged` 한 곳** — `Refresh(Name, Icon, bActive)`. `Slots[i]`가 차 있으면 아이템 행의
  `Icon`(`UCL9DefBase::Icon`, 소프트 참조)을 넘긴다 — **그 칸의 행이 바뀔 때만 `LoadSynchronous()`** 하고, 같은 행이면
  로드해 둔 텍스처를 다시 쓴다. 아이콘이 있으면 `Icon`만 보이고 `NameText`는 접히며, 아이콘이 없는 행은 반대로
  `DisplayName`(없으면 별칭)만 보인다. 빈 칸은 둘 다 접힌다. `i == ActiveSlot`인 칸은 `ActiveColor`, 나머지는
  `InactiveColor`를 `Frame` 브러시 색·`Icon` ColorAndOpacity·`NameText` 색에 같이 건다. 클라에서는 `Slots`가 복제되기
  전에 잠시 빈 채로 그려졌다가 첫 `OnCarryChanged`에서 채워진다 — 정상이다.
- 칸의 크기·테두리 두께·배경·글꼴은 전부 `WBP_QuickSlot`이 정한다 — C++은 아이콘·이름의 표시 여부와 밝기만 만진다.
  `QuickSlotBox`가 없거나 `QuickSlotClass`가 비어 있으면 퀵슬롯을 그리지 않는다.
- 빈 칸을 활성으로 고른 상태(= 빈손)도 그 칸의 테두리가 밝다 — 어느 칸이 손인지는 늘 보여야 한다.
- 조작(휠·숫자키·G)은 [input.md](input.md), 칸 규칙(잠금·값 보존)은 [inventory.md](inventory.md).

### 첫 줍기 힌트 (2026-09-13)

게임이 처음인 사람이 프라이팬을 처음 주웠을 때 좌클이 무슨 뜻인지 알려주는 튜토리얼 한 줄 — 들고 있다고 늘 뜨는
"[E] 놓기" 같은 프롬프트는 없앴고(사용자: "E 놓기 UI가 뜨면 안 된다"), 대신 처음 한 번만 잠깐 보였다 사라진다.

```
WBP_HUD
  └─ HintText (TextBlock, BindWidgetOptional — PromptText 위 2~3줄, 가운데 정렬, 기본 Collapsed)
     HintDuration (float 프로퍼티, 기본 4.0초)
```

- **대상** — 활성 칸의 아이템 행이 `UCL9ItemDef::HasUseHint()`인 것: `UseAction != None`(프라이팬·손전등)이거나
  `ItemType == Dish`(요리 — 먹기). 계란·냄비처럼 설명할 조작이 없는 것은 안 뜬다(사용자: "설명이 필요해 보이는 것만").
- **언제** — `PlayerState.OnCarryChanged`에서 **활성 칸의 아이템(별칭·하위 별칭)이 바뀌었을 때만** 판단한다. 다른 칸이나
  머리 장비만 바뀐 경우는 건드리지 않는다. 힌트가 뜬 채로 다른 것을 들면 바로 접는다 — 남의 설명이 된다.
- **한 번만** — 종류별(`Alias`)로 이 PC의 `UCL9GameUserSettings`(`HasSeenItemHint`/`MarkItemHintSeen`)에 남는다. 보이는
  순간 기록하므로 4초를 다 보지 않아도 다시는 안 뜬다. PIE를 다시 켜도 안 뜬다(`GameUserSettings.ini`) — 다시 보려면
  거기서 지운다. 호스트 세이브가 아니라 로컬이다: 튜토리얼은 사람에게 붙는 것이지 판에 붙는 것이 아니라서
  ([settings.md](settings.md)). 익은 계란은 `egg`로 기록되므로 탄 계란도 함께 본 것이 된다.
- **시간** — `HintDuration`(WBP_HUD 프로퍼티, 4.0초) 뒤 `Collapsed`. 애니메이션 없음 — "번쩍임은 밤 만료 경고에만"(아래
  UI 애니메이션)이라 그냥 나타났다 그냥 사라진다.
- **문구** — String Table `Hint.*`를 행에 따라 1~3줄 `\n`으로 잇는다. `{0}`=사용 키(`ACL9Character::GetUseAction()`),
  `{1}`=스캔 키(`GetScanAction()`) — 지금 바인딩된 키 표기(`CL9Input::GetActionKeyText`, [input.md](input.md) 키 표기)라
  키를 바꾸면 힌트도 따라간다.

  | 행 | 줄 | 키 |
  |---|---|---|
  | `UseAction == Swing` | "[{0}] 살짝 누르기 — 바로 휘두르기" / "[{0}] 꾹 누르기 — 들고 있다가 떼는 순간 휘두르기" | `Hint.UseTap.Swing` · `Hint.UseHold.Swing` |
  | `UseAction == ToggleLight` | "[{0}] 살짝 누르기 — 켜고 끄기" | `Hint.UseTap.ToggleLight` |
  | `ItemType == Dish` (위에 더해) | "[{1}] 꾹 누르기 — 먹기" | `Hint.ScanHold.Eat` |

- `HintText`가 없으면 힌트를 그리지 않는다. 글꼴·위치·정렬은 WBP_HUD가 정한다.

### 장소 알림 (2026-10-09)

조리대가 "그냥 흔한 책상"으로 읽혀 요리하는 곳인지 모른다는 신고(2026-10-09)에 대한 답 중 화면 쪽 한 조각 —
지나가면 부엌이라고 알려 준다. 모델·불꽃·소리는 [../goal/kitchen-identity.md](../goal/kitchen-identity.md).

```
WBP_HUD
  └─ PlaceText (TextBlock, BindWidgetOptional — CanvasPanel 슬롯: 앵커 (0.5, 0.22), 정렬 (0.5, 0.5), 위치 0, 크기에 맞춤.
     30 Bold 흰색 + 그림자, 가운데 정렬. 상단 시계·그 밑 밤 만료 경고와 겹치지 않는 자리, 기본 Visibility 숨김)
     KitchenNoticeRadius (float 프로퍼티, 기본 600 cm)
     PlaceNoticeDuration (float 프로퍼티, 기본 2.5초)
     PlaceNoticeFadeTime (float 프로퍼티, 기본 0.35초)
```

- **판정** — `RefreshCookGauges`가 이미 하는 `ACL9Kitchen` 순회(상한: 판에 몇 개 — performance.md UI 예외 범위) 안에서
  **로컬 폰과 가장 가까운 조리대까지의 수평(XY) 거리**를 함께 구한다. 거리는 조리대 가운데가 아니라 **몸체 바닥 면적
  (300×120)의 가장 가까운 점**까지다 — 300cm 길이의 끝자리에서도 맞게. 면적은 조리대 루트 컴포넌트 `Bounds`의
  세계축 상자(XY)라 `ACL9Kitchen`이 열 구역을 잡는 것과 같고, 면적 안이면 거리 0이다.
- **들어섬** — 어느 조리대에서든 `KitchenNoticeRadius × 1.25` 밖이던 상태("밖")에서 어느 조리대든 `KitchenNoticeRadius`
  안으로 들어오면 **한 번** 띄운다. 처음 상태는 "밖"이라 반경 안에서 스폰해도 한 번 뜬다. 안에 머무는 동안 다시 뜨지 않고,
  1.25배 밖으로 나갔다 와야 다시 뜬다(경계에서 들락날락해도 반복되지 않게 하는 여유). 1.25는 코드 상수(`KitchenNoticeExitScale`)다.
- **누구에게 안 띄우나** — 로컬 폰이 `ACL9Character`가 아니거나(관전 폰 포함) `IsDead()`이거나 `IsIntroLocked()`(전원 인트로
  카메라 비행 중)이면 판정하지 않는다. 판정하지 않는 동안은 상태를 "밖"으로 돌리고 떠 있던 알림은 접는다 — 풀린 뒤에 반경
  안이면 들어선 것으로 쳐서 한 번 뜬다(스폰과 같은 취급).
- **표시** — `LOCTABLE("CL9","Hud.PlaceKitchen")`("부엌")을 `PlaceNoticeDuration` 동안: 불투명도 0 → 1(`PlaceNoticeFadeTime`) →
  유지 → 1 → 0. 총 시간이 짧으면 페이드가 절반씩을 넘지 못하게 줄인다. "번쩍임"이 아니라 한 번 나타났다 사라지는 것이라
  아래 "UI 애니메이션" 금지에 걸리지 않는다. `PlaceText`가 없으면 화면만 비고 판정은 그대로 돈다.
- **로그** — 띄울 때마다 `LogCL9`에 한 줄: `Kitchen notice: <거리> cm from the nearest kitchen (radius <반경>, PlaceText bound|missing)`.
  QA가 위젯 유무와 상관없이 판정을 검증하는 용도.
- **로컬이다** — 각자 화면에서 각자 판정한다. 복제도 RPC도 없다. 몬스터는 이 알림과 무관하다.
- `KitchenNoticeRadius`·`PlaceNoticeDuration`·`PlaceNoticeFadeTime`은 WBP_HUD에서 편집하는 **표현 값**이다(`CookGaugeLift`와
  같은 꼴) — `CL9Rules` 밸런스 셀이 아니다.

### 조리대 놓기 안내 (2026-10-09)

들고만 있을 때는 아무 프롬프트도 안 뜬다는 규칙("놓기 프롬프트는 없다", 2026-09-13 사용자 — "E 놓기 UI가 뜨면 안 된다")의 **유일한 예외**다.
익힐 수 있는 재료(행에 `CookResult` 또는 `BurnResult`가 있는 것)를 들고 조리대 `PickRadius` 안에서 조리대를 바라보면
**"[G] 올려서 익히기"**(`Prompt.KitchenPlace`)가 뜬다 — 요리하려면 어디에 놓아야 하는지 처음 하는 사람이 화면만 보고 알게 하려는 것이다.

- **키는 놓기 키(G)** — `{0}`은 지금 바인딩된 놓기 키 표기(`CL9Input::GetActionKeyText`)라 키를 바꾸면 문구도 따라간다.
- **그리는 쪽은 기존 `PromptText` 경로 그대로다** — 문구는 캐릭터 `GetFocusPrompt()`가 조립하고(gameplay 몫:
  `GetFocusPromptPattern`), HUD는 `OnFocusPromptChanged`로 받아 `PromptText`에 넣을 뿐이다. 새 위젯·새 델리게이트 없음.
- **우선순위** — 기존 프롬프트가 먼저다(착용 > 줍기 > 상호작용). 이 안내는 그 다음, 수레 놓기보다 앞이다.
- 프라이팬처럼 익는 행이 없는 것을 들었거나 빈손이면 뜨지 않는다. 위의 첫 줍기 힌트가 "늘 뜨는 놓기 프롬프트"를 없앤 것과
  모순되지 않는다 — 이 문구는 조리대를 바라보는 동안만, 익힐 수 있는 재료를 들었을 때만 뜬다.

## 화면 전환 — WBP_Main 하위

레이어에 배타적으로 연다 ([ui_system.md](ui_system.md) — 2026-09-05 구조 결정).

### 타이틀 (시작 레벨, 2026-10-05)

`UCL9TitleWidget`(UI 표 `Title` 행, Screen 레이어, **루트 화면**). 시작 레벨(`Lvl_Start`)의 컨트롤러가 메뉴 GameMode의
`TitleUIRow`로 연다(start-lobby L2). 루트 화면이라 M·[X]로 닫히지 않고, 커서는 열린 Screen 규칙대로 보인다.
시작 레벨에서는 HUD가 배선되지 않아 접힌 채다 — 타이틀 뒤에 시계·HP가 비치지 않는다.

```
            CL9
       [ 방 만들기 ]          →      어디로 갈까요?
       [ 참가하기 ]  (개발 빌드)      [ 양계장 ]
       [   설정   ]                  [  …    ]
       [   종료   ]                  [  뒤로  ]
```

- 바탕은 **불투명한 어두운 색**이다 — 시작 레벨은 비어 있어서 뒤에 보여 줄 것이 없다.
- [방 만들기]를 누르면 **같은 화면 안에서** 목적지 목록으로 바뀐다(별도 화면 행이 없다). 목록은 레벨이 지정된 사이트 행마다
  버튼 하나(`UCL9GameInstance::GetHostableSites()`, 표 순서), 라벨은 사이트 행의 `DisplayName`이다. 누르면
  `HostGame(alias)`가 그 레벨을 연다(개발 빌드는 리슨) — 레벨이 바뀌면 새 월드의 컨트롤러가 UI를 다시 짓는다.
  [뒤로]는 첫 메뉴로.
- [설정]은 기존 설정 화면을 연다. 설정이 타이틀을 대체하고 히스토리에 쌓이므로 닫으면(M·[X]) 타이틀로 돌아온다
  (첫 메뉴 상태로 새로 열린다).
- [종료]는 Quit Game.
- [참가하기]는 주소 접속을 쓸 수 있는 빌드(`IsJoinAvailable()` — Shipping이 아닌 빌드)에서만 보인다. 누르면 같은 화면 안에서
  참가 칸으로 바뀐다: "주소" 이름표 · 주소 칸(기본 `127.0.0.1`, WBP 값 `DefaultJoinAddress`) · [접속] · [뒤로]. [접속]은
  `JoinGame(주소)`를 부르고, 접속 시도 중(`IsJoining()` — 틱에서 본다)에는 칸이 "접속 중…"과 [취소](`CancelJoin()`)로
  바뀐다. 붙으면 레벨이 바뀌어 화면이 사라진다. 주소 칸에 키보드 포커스가 있는 동안 M·Tab이 먹지 않는 것은 정상이다
  (키가 게임 뷰포트에 닿지 않는다). 제품의 참가 길은 Steam 층이 들어오면 같은 함수의 속이 바뀐다([session.md](session.md)).
- WBP에 아무것도 없어도 C++이 트리를 짓는다 — [ui_system.md](ui_system.md) "스스로 짓는 위젯". 글자: 게임 이름 30 Bold,
  목적지 질문 20 Bold(흐린 색), 버튼 20 Regular, 버튼 320×56.

`UCL9GameOverWidget`(UI 표 `GameOver` 행, Screen 레이어, **루트 화면**). 밤에 전원이 쓰러져 판이 끝나면(규칙 표

### 새벽 결과 화면

`WBP_Dawn`(UCL9DawnWidget, UI 표 `Dawn` 행, Screen 레이어). 밤이 끝날 때마다 게임 쪽이 연다
(`ACL9GameMode::DawnUIRow`, 비우면 안 연다) — 정산 결과를 보여주는 자리다.

```
3일차 정산
이번 기간 1,240 / 목표 800 이더
통과 — 다음 기간이 시작된다
[계속]
```

미달이면 붉은 글씨로 "미달 — 판이 끝났다. 3일차까지 버텼다"가 뜨고 버튼이 [새 판으로]가 된다.
정산일이 아닌 새벽에는 견줄 목표가 없으므로 "N일차 새벽 · 이번 기간 X 이더"만 띄운다.

**숫자는 `OnSettled(Day, Earned, Target, bPassed)`가 실어다 주는 것을 쓴다.** 정산은 값을
정리하면서 기간 수입을 0으로 되돌리고 미달이면 1일차로 보내므로, 화면이 그 뒤에 GameState를
조회하면 보여줄 것이 남아 있지 않다. 그래서 신호는 **되돌리기 전에** 발동한다(2026-09-07).

클라이언트에서는 화면 열기(컨트롤러 RPC)와 정산(GameState 멀티캐스트)이 서로 다른 채널이라
도착 순서가 보장되지 않는다. 그래서 위젯은 붙는 순간 복제된 `GetLastSettlement()`를 한 번 읽고
(그날 것이면 그대로 표시), 그 뒤에 오는 신호로 갱신한다 — 순서와 무관하게 같은 숫자가 뜬다.

**트럭에 못 탄 사람 줄 (2026-10-06).** 판이 끝날 때 트럭 밖에 있던 사람은 죽는다
([round-start-truck-intro](../goal/round-start-truck-intro.md) K5). `GameState->GetLeftBehindNames()`가 비어 있지
않으면 결과 줄(`ResultText`) 끝에 한 줄 `트럭에 못 탄 사람: 이름, 이름`(`Dawn.LeftBehind`·`Dawn.LeftBehindSep`)을 덧붙인다 —
`ShowWaiting`(정산일이 아닌 새벽)과 `HandleSettled`(정산일) 둘 다. 새 BindWidget을 두지 않는다(기존 WBP 컴파일이
깨진다). 이 목록은 정산이 되돌리지 않는 복제 값이라 `OnSettled`와 달리 화면이 직접 읽어도 되고, 열 때 현재 값을 읽은 뒤
`OnLeftBehindChanged`로 갱신한다(호스트는 직접 발동, 클라이언트는 OnRep).

**전멸 줄 (2026-10-12, [loop-7a-wipe-penalty](../goal/loop-7a-wipe-penalty.md)).** 전멸로 온 새벽이면(`GameState->GetWipePenalty().bActive`)
결과 줄 끝에 `전멸 — 이더 N 차감`(`Dawn.WipePenalty`, N = 실제로 깎인 이더 — 잔액이 0 이면 0)을 덧붙인다. 남겨진 사람 줄과 같은
방식(복제 값을 직접 읽고 `OnWipePenaltyChanged`로 갱신)이고, 둘 다 있으면 남겨진 사람 줄 다음이다.
2026-10-12 이름 바꿈(7f): 판 안 화폐의 화면 단위가 **코인**이라 이 줄도 `전멸 — 코인 N 차감`이다.

**지갑 줄 — 바깥 재화 "이더" (2026-10-12, [loop-7f-out-game-currency](../goal/loop-7f-out-game-currency.md)).** 결과 줄 맨 끝에 늘 한 줄 —
이 머신의 `UCL9WalletSubsystem` 을 읽어, 이번 판에 받았으면 `이더 +N (보유 M)`(`Dawn.Wallet`), 아니면 `보유 이더 M`(`Dawn.WalletBalance`).
임포스터가 있던 판이면 누구였고 어떻게 끝났는지 한 줄을 모두에게 보인다(`GameState->GetImposterResult()`, 7g — [../goal/loop-7g-imposter.md](../goal/loop-7g-imposter.md)): `임포스터: 이름 — 성공`(`Dawn.ImposterWon`) / `… — 처치한 사람에게 처치됨`(`Dawn.ImposterKilled`) / `… — 실패`(`Dawn.ImposterFailed`). 임포스터가 없던 판은 줄이 없다.
처치 기여가 있던 판이면 한 건마다 `거위에게 당한 이름 — 깨운 사람 이름`(`Dawn.Contribution`, `GameState->GetContributions()`, 7h — [../goal/loop-7h-kill-contribution.md](../goal/loop-7h-kill-contribution.md)).
정산 미달(7i)이면 판정 줄이 `미달 — N일차 목표를 못 채웠다. 판은 이어진다`(`Dawn.Failed` ko 문구 변경, 닫기 `계속`)이고 `목표 미달 — 코인 N 차감`(`Dawn.QuotaPenalty`, `GameState->GetQuotaPenalty()`) 줄이 붙는다.
정산일 로비(회사가 있을 때)면 `오늘은 정산일 — 출발 레버를 당기면 회사로 간다`(`Dawn.CompanyDue`, 페이즈가 바뀔 때도 다시 짠다). 회사 레벨에서는 HUD 가 도착 뒤 정산 화면을 한 번 연다(`CompanyScreenRow`, 7i — [../goal/loop-7i-company.md](../goal/loop-7i-company.md)).
스테이지 별(7l — [../goal/loop-7l-stage-stars.md](../goal/loop-7l-stage-stars.md))을 매긴 정산이면 결과 줄 바로 아래에 `이번 목적지: 양계장 ★★☆`(`Dawn.StageStars`)와, 새로 열렸으면 `다음 목적지가 열렸다: 대농장 — 목적지 판에서 고른다`(`Dawn.StageOpened`). 복제된 지난 정산(`FCL9SettlementResult.Stars/Site/OpenedSite`)에서 읽는다.
`OnWalletChanged` 로 갱신한다. 지급 RPC 가 화면 열기 RPC 보다 먼저 같은 채널로 오므로 화면이 서는 순간 숫자가 맞다.
**타이틀**도 게임 이름 아래에 `보유 이더 M`(`Title.Wallet`)을 한 줄 띄운다(빌드할 때 한 번 읽는다).
판 안 화폐를 보여 주는 ko 문구 11개(HUD 돈·주문·창구, 스캔 라벨 값, 상점 돈·가격, 주문 카드, 새벽 기간·정산, 전멸 줄)는 "이더" → **"코인"**(en 열은 번역 때).

### 트럭 패널 (구매 화면)

`WBP_Shop`(UCL9ShopWidget, UI 표 `Shop` 행, Screen 레이어). 품목 기준·가격식은
[shop.md](shop.md)에 있고, 여기는 화면이 무엇을 보여주는지다.

```
트럭 패널
보유 1,240 이더
┌──────────────────────────┐
│ 프라이팬                  │
│ 200 이더 · 1/3 보유       │
└──────────────────────────┘
[닫기]
```

- 카드는 장비 표에서 런타임에 만든다 — `bPhysicalProp`인 행만(파는 것은 실물뿐이다).
  이름과 상세를 **다른 위젯 두 개**로 나눠 위계를 준다(글자 위계 절).
- 상세 줄은 `가격 · (상한이 있으면) N/M 보유 · (못 사면) 사유` 순으로 이어 붙인다.
  사유 문구는 화면이 만들지만 **판정은 만들지 않는다** — `ACL9GameState::CanBuy()` 하나를
  읽어서 버튼을 끄고 그 결과를 문구로 옮길 뿐이다. 화면이 규칙을 다시 구현하면 어긋나는
  순간 거짓말을 한다(창구 재고·주문 진행도와 같은 원칙).
- **클라이언트도 산다.** 그래서 판정이 GameMode가 아니라 복제되는 GameState에 있다
  (2026-09-07: 처음에 GameMode에 있어 클라 화면이 아무것도 못 읽던 것을 옮겼다).
  누가 사든 같은 지갑에서 나가므로 `OnMoneyChanged`가 오면 화면 전체를 다시 칠한다.
- 거절은 누른 사람에게만 온다(`OnBuyRejected`) — 안내 줄에 "프라이팬: 잔액 부족"처럼 뜬다.
- 화면을 여는 것은 트럭 패널 액터다. 상호작용한 사람에게 Client RPC로 연다 — 로비 주문
  화면과 달리 상태에서 파생시킬 것이 없어서, 누르면 곧바로 열린다.

### 메뉴

[계속] [설정] [로비로 나가기] [게임 종료].

**일시정지는 없다** (2026-09-06 사용자 확정). 온라인 협동 게임이라 한 사람이 세계를 멈출 수
없다 — 메뉴를 열어도 몬스터는 계속 쫓아오고 밤 시계도 계속 흐른다. 끊기는 것은 내 조작뿐이라
**메뉴를 여는 동안 캐릭터는 그 자리에 선 채 무방비다.** 이것이 밤중에 메뉴를 여는 값이다.

`WBP_Pause`(UI 표 `Pause` 행, Screen 레이어)는 화면을 검게 덮고 가운데에 패널을 띄운다. 여는 키는 M 과 Esc
(Esc 는 2026-10-23 부터, 코드 바인딩 — [input.md](input.md)). 겉모습은 2026-10-22 결정한 "먼지 낀 유리" 룩으로 맞춘다
(시안: 데이터 패널 `/uilook` T 절 — 검은 덮개 대신 먼지·검댕 덮개, 테두리 없는 패널, 뼈색 60% 글자, 종료만 탁한 붉은색).
에셋·입력 액션 이름의 `Pause`는 열고 닫는 키를 가리키는 옛 이름일 뿐 멈춤을 뜻하지 않는다.
[계속]은 `CloseSelf`, [설정]은 `OpenWidget(Settings)`, [게임 종료]는 Quit Game으로 배선돼 있다.
[로비로 나가기]는 갈 곳이 아직 없어서(타이틀/세션 UI 미구현) 비활성이며, 왜 눌리지 않는지를 패널 맨 아래
안내 한 줄(`Pause.LobbyNotReady` "로비 나가기는 준비 중입니다")이 설명한다. 세션 UI가 생기면 비활성을 풀고
세션 종료로 잇는다.

**화면은 스택이다** (2026-09-12 사용자 "레이어가 쌓이면 한 번에 닫히는 게 아니라 하나씩 뒤로") — 메뉴에서 [설정]을
열고 M(또는 [X])을 누르면 메뉴로, 다시 누르면 게임으로 돌아온다. 관전 중이면 관전 화면으로 돌아온다. 구현은
[ui_system.md](ui_system.md) "화면 히스토리".

### 설정

`WBP_Settings`(UI 표 `Settings` 행, Screen 레이어, `UCL9SettingsWidget`). 메뉴 [설정]에서 연다. 검은 덮개 위 가운데
패널, 오른쪽 위 [X], 스크롤되는 한 열에 섹션 넷 — **키 · 마우스 · 오디오 · 언어** — 과 맨 아래 힌트 줄.

- 키 섹션: 동작 이름 + 현재 키 버튼이 한 줄씩(`IMC_Gameplay` → `IMC_Spectate` 순서), 섹션 헤더 오른쪽에 [키 초기화].
  키 버튼을 누르면 문구가 "키를 누르세요…"(`Settings.PressKey`)로 바뀌고 다음 키·마우스 버튼이 그 동작에 들어간다.
  Esc 또는 5초 무입력이면 취소. 이미 다른 동작이 쓰는 키면 **둘을 맞바꾸고** 힌트 줄에
  "손전등: E · 줍기: F"(`Settings.KeySwapped`)처럼 알린다. 게임패드·휠·Esc 같은 거부 키는 "쓸 수 없는 키"
  (`Settings.KeyRejected`) 힌트만 띄우고 계속 기다린다. 규칙 전문: [input.md](input.md) 리바인딩.
- 마우스: 감도 슬라이더(정수 퍼센트) · Y축 반전 체크.
- 오디오: 전체·효과음·UI·배경음·음악·음성 슬라이더 여섯, 이어서 음성 채팅 네 줄 — 사용 토글 · 말하기 방식(음성 감지 / 눌러서 말하기) ·
  마이크 증폭 · 음성 채팅 볼륨 ([settings.md](settings.md) 오디오 절, [voice.md](voice.md)). "마이크 감도"와 마이크 레벨 막대는 2026-10-12 에 뺐다(EOS 에 음성 감지 문턱·입력 레벨 값이 없다).
- 언어: [한국어 | English] 세그먼트 — 누르는 즉시 화면 전체가 바뀐다.
- 값은 바꾸는 순간 적용·저장된다 — [적용]·[확인] 버튼이 없다. 항목·저장 위치는 [settings.md](settings.md).
- 힌트 줄은 다음 캡처를 시작할 때 지운다. 글자 위계: 섹션 헤더 = 강조, 행 = 목록.

### 디버그 패널 (개발용, 2026-10-05 · 2026-10-21 SlateIM 창 하나로 합침)

**Tab**(`IA_DebugPanel`)으로 여닫는 개발용 창이다. 사용자 요청은 "tab 누르면 디버그 패널 나와서 몬스터들 바로 소환"(10-05)과
"몬스터 소환도 옆 탭으로, 띄워도 움직임이 멈추지 않게, 길어지면 스크롤, 카테고리별 탭"(10-21)이다. 출시(Shipping) 빌드에는 없다.
UMG 가 아니라 엔진의 **SlateIM**(즉시 모드 Slate, `Engine/Plugins/Experimental/SlateIM`, 디버그 도구용)으로 뷰포트 **오른쪽 끝**에
그린다 — `FCL9ScreenDebugger`(`Source/CL9/UI/CL9ScreenDebugger.*`), 로컬 `ACL9PlayerController` 가 하나 가진다.

```
디버그 패널                                   [닫기 (Tab)]
[ 화면 ][ 몬스터 소환 ][ 플레이어 ]             ← 위 탭
☐ 프리셋: 맵 그대로                             ← 화면 탭 맨 위
[레트로][색 보정][조명][안개 모양]              ← 화면 탭의 아래 탭
┌ 스크롤 ─────────────────────────────┐
│ 이름 칸(150px)   손잡이(슬라이더 + 숫자 칸)  [-][+][↺] │
└─────────────────────────────────────┘
[처음 값으로] [값 저장] [표에 덮어쓰기]
안내 줄
```

- **게임 입력을 막지 않는다.** UI 매니저의 화면(Screen 레이어)이 아니어서 `IMC_Gameplay` 가 그대로 살아 있으므로, 패널을 연 채로 걷고 뛸 수 있다.
  `ACL9PlayerController::SetDebugPanelOpen` 은 커서만 켜고(`GameAndUI`, 마우스 잠금 없음) 닫을 때 `GameOnly` 로 되돌린다.
  메뉴 같은 UI 매니저 화면이 떠 있으면 커서와 입력 모드는 그 화면이 정한다. 그 화면이 닫혀 커서가 꺼지면 패널이 다음 프레임에 다시 켠다.
- 높이는 뷰포트 위아래 16px 여백까지 늘어난다. 칸이 넘치면 안쪽 목록만 스크롤되고 탭 줄과 버튼 줄은 고정된다.
- 모든 손잡이 줄은 같은 폭(150px)의 이름 칸으로 시작하므로 왼쪽 끝이 맞는다. 탭 버튼은 같은 폭으로 나뉘고 고른 탭만 강조색이다.
  닫았다 열어도 마지막에 고른 탭이 유지된다.
- 탭이나 버튼을 누르면 키보드 포커스를 게임 뷰포트로 돌려준다. 버튼에 포커스가 남으면 Tab과 WASD 가 위젯에 먹히기 때문이다.
- 관전 중에는 Tab이 `IMC_Spectate`(관전 대상 전환)에 먼저 잡혀 패널이 열리지 않는다.
- 예전 UMG 패널 `WBP_DebugPanel`(`UCL9DebugPanelWidget`, UI 표 `DebugPanel` 행)은 더 이상 Tab 으로 열리지 않는다.

#### 몬스터 소환 탭

- 몬스터 버튼은 몬스터 표(`GetMonsters()`)에서 매 프레임 만든다. 표에 행을 더하면 버튼도 생긴다. 한 줄에 같은 폭으로 두 칸씩 놓인다.
  버튼 글자 "이름  (alias)" 에서 괄호 안은 콘솔에 칠 때 쓰는 이름(변형 행이면 `alias+subalias`)이라 번역하지 않는다.
- 누르면 `cl9.addmonster <alias> <마리 수>`를 그대로 콘솔로 친다. 판정·스폰 자리·복제는 치트와 같다([cheats.md](cheats.md)).
  클라가 누르면 호스트로 올라간다. 마리 수는 1~20 숫자 칸이다(`cl9.addmonster` 의 상한).
- [몬스터 모두 지우기]는 `cl9.clearmonsters`를 친다. 레벨에 놓인 몬스터까지 전부 지운다. 안내 줄의 "몬스터 N마리 지움"은
  누른 머신에 보이는 수다(호스트에서는 지운 수와 같다).

#### 플레이어 탭 (2026-10-21)

- 사용자 요청: "무적 모드도 만들어 줘. 무적이면 투명화가 되는데 그때는 아무 어그로도 안 끌리는 거야."
- [무적 (투명 · 어그로 없음)] 체크는 `cl9.god 1|0` 을 콘솔로 친다([cheats.md](cheats.md)). 체크 표시는 복제된 `ACL9Character::IsGodMode()` 를 읽는다.
- 무적이면 피해를 받지 않는다(`OnDamage` 관문, `cl9.damage` 도 막힌다). 몸(3인칭 메시)이 모든 머신에서 숨는다 — 그림자도 사라져 본인 화면에서도 켜진 것이 보인다. 1인칭 팔과 손에 든 물건은 보인다.
- 몬스터는 무적인 사람을 보지도 듣지도 않는다. 타깃 고르기, 기상, 잡기, 덮침, 처형, 도둑 추격, 도망, 근접 울음, 응시 판정, 양의 "혼자" 판정, 쥐 떼 발동에서 빠진다. 쫓던 몬스터는 켜는 순간 놓는다.
- 몬스터를 때리면 그 자리 소리(타격 소음)에는 반응한다. 소리 난 곳을 보러 올 뿐 무적인 사람을 찾지는 못한다.
- [처음부터 다시]는 `cl9.restart` 를 친다(2026-10-23 사용자 "게임재시작해서 처음으로 돌아가기... 시간부터 다시할수있게"). 지금 맵을 다시 열어
  판 시각·몬스터·아이템이 처음 상태로 돌아간다. 일차·코인은 이어지지 않는다. 호스트만 된다.

#### 파동 탭 (2026-10-22)

- 사용자 요청: "파동 모양을 여러 개 만들어서 디버그 패널에서 내가 골라서 볼 수 있게 한 10개 정도 만들어 줘."
- 파동 표 `Styles` 의 벌 목록을 버튼으로 늘어놓는다 — 맨 위 **[표 기본값 (벌 N)]**(표 `DefaultStyle`, 평소 그림), **[전역 점만 (벌 없이)]**, 그 아래 벌마다
  String Table 키(`Debug.Wave.Style1`…)의 이름. 고른 것만 강조색. 누르면 `cl9.wavestyle N` 을 콘솔로 친다([cheats.md](cheats.md)) — 이 머신만, 저장하지
  않으며, 살아 있는 파면도 다음 틱부터 그 벌이다 ([wave.md](wave.md) 모양 벌).
- 맨 아래 **[시험 파동 (발밑)]** 은 `cl9.wave land`(착지 핑, 호스트 판정)를 쳐서 걷지 않고도 벌을 비교한다.

#### 화면 탭 ([../goal/screen-debugger.md](../goal/screen-debugger.md))

맨 위 **[프리셋: 맵 그대로]** 체크는 룩 표가 화면에 거는 것을 모두 걷어 맵에 배치된 그대로 보이게 한다(`UCL9LookDef::SetLevelAsPlaced`, 2026-10-21 사용자 "맵마다 지금 배치되어 있는 상태, 그거 세팅 그대로").
색 보정·레트로 후처리(`UCL9LookModifier`)와 저해상도 콘솔 변수가 빠진다. 조명 액터(`ACL9NightLighting`)는 태양·하늘빛·대기·안개(밀도·색·모양)·하늘 구 재질·구름을
BeginPlay 때 레벨에 놓여 있던 값으로 되돌리고 노출 고정을 끈다. 표 값은 그대로라 끄면 돌아온다. 켜 있는 동안 아래 손잡이는 화면에 걸리지 않는다. 이 머신만, 저장하지 않는다.

룩 표(`UCL9LookDef`)의 손잡이를 모은 탭이다. 사용자 요청은 "화면 포스트프로세싱, 노이즈·안개 등 다 세팅할 수 있게"였다. 아래 탭은 넷이다.

| 아래 탭 | 손잡이 |
|---|---|
| 레트로 | 레트로 켜기 · 내부 해상도 · 안티에일리어싱 · 픽셀 크기 · 픽셀화 시작 거리 · 밝기 단계 · 밝기 단계 섞기 · 색 단계 · 디더 무늬 · 디더 세기 · 팔레트 · 팔레트 섞기 · 노이즈 |
| 색 보정 | 채도 · 대비 · 감마 · 게인 · 색온도 · 색조 · 그림자 색 · 하이라이트 색 · 비네트 · 블룸 · 색수차 · 샤픈 · 모션 블러 |
| 조명 | 페이즈 [자동 ▼] (프로필 · 판) 노출 · 태양 밝기/색 · 하늘빛 밝기/색 · 하늘빛 누수 · 하늘 밝기 · 하늘빛 산란 · 안개 밀도/색 · 안개 하늘빛 |
| 안개 모양 | (-1 = 레벨 값) 높이 감쇠 · 시작 거리 · 최대 불투명도 · 볼류메트릭 · 볼류메트릭 짙기/거리 |

- 값은 레지스트리의 룩 표 애셋에 바로 쓰고, 바뀐 프레임에 `ApplyNow` 로 판을 올린다 — 해상도 콘솔 변수·안개 모양처럼 판을 보는 쪽도 따라온다.
  에디터 PIE 에서는 그 애셋이 에디터의 것이라 PIE 를 끝내도 값이 남는다(더티). [표에 덮어쓰기]가 룩 표 애셋 그 파일에 덮어쓴다(에디터만).
- [처음 값으로]: 패널을 연 순간 떠 둔 사본으로 표 전체를 되돌린다.
- [값 저장]: 이름 칸이 뜨고, [저장]이면 화면 탭이 고치는 값 전부(레트로·색 보정·안개 모양 + 프로필마다 세 페이즈의 조명)를
  `Saved/LookPresets/<이름>.csv`(키,값 두 열, 맨 위에 _Name·_Map·_SavedAt)로 새로 쓴다. 이름이 비면 시각, 같은 이름이 있으면 뒤에 번호 —
  덮어쓰지 않는다. 표 애셋은 건드리지 않는다. 패키지 빌드에서도 된다 (2026-10-23 사용자 "게임하다가 이거 값괜찮은데? 하고 저장해두고싶음").
- 수 줄 끝 버튼 (2026-10-22, 사용자 "수치 바꾸는 게 더 편리했으면, 조작이 좀 어려워" — 미세 조절·글자 입력·줄 되돌리기를 골랐다):
  [-]·[+]는 한 칸씩 움직인다. 한 칸은 손잡이 범위의 1/50을 1·2·5 단위로 둥글린 값이고(0~1 이면 0.02, 내부 해상도 120~2160 이면 50),
  Shift를 누른 채 누르면 열 배 잘게(정수 줄은 1씩) 움직인다. [↺]는 그 줄만 패널을 연 순간의 값으로 되돌리고, 값이 그대로면 꺼져 있다.
  색 줄에는 [↺]만 붙는다. 되돌릴 값은 줄을 처음 그린 순간에 값의 주소로 기억하고, 열 때·[처음 값으로]·[표에 덮어쓰기] 때 비운다.
- 숫자 칸에 글자를 치는 동안(키보드 포커스가 `SEditableText`)은 이 패널 주인의 게임 뷰포트가 키를 받지 않는다(`UGameViewportClient::SetIgnoreInput`).
  게임 입력을 켠 채 열리는 패널이라, 숫자 칸이 처리하지 않은 WASD·E·스페이스가 뷰포트로 올라가 캐릭터가 움직였기 때문이다. 입력을 마치면(Enter·다른 곳 클릭) 바로 돌려준다.
- 조명 탭은 지금 사이트의 조명 프로필에서 페이즈 하나 — "자동"이면 조명 액터가 지금 고르는 페이즈(로비 / 판 / 정전). 판 값은 플레이어 설정
  "밝기"가 위에 얹힌 채 보인다(표에는 얹기 전 값이 들어간다).
- "레트로 켜기"는 이 머신의 플레이어 설정 값만 바꾸고 저장하지 않는다(설정 화면이 저장한다).
- 그리지 않은 프레임에 SlateIM 이 루트를 걷으므로 패널을 닫으면 저절로 사라진다. 루트 이름에 컨트롤러 이름을 붙여 한 프로세스 PIE 의 여러 클라가 겹치지 않는다.
- 문구는 문자열 표 `Debug.Screen.*`(ko).

## UI 애니메이션

- 화면 전환 0.3초 페이드, 패널 0.2초 슬라이드
- 중요 알림 번쩍임은 밤 만료 임박에만 제한적으로 — 구현은 위 HUD 표의 "밤 만료 경고"다
  (2026-09-08). HUD가 매 프레임 `GetNightRemaining()`을 보고, 문턱 아래인 동안에만 켜서
  불투명도를 흔든다. 꺼질 때 위상을 0으로 되돌리므로 항상 가장 밝은 지점에서 시작한다 —
  켜지자마자 어두운 구간이면 "떴다"는 사실 자체가 안 읽힌다
- **크기 튀기(번쩍임 아님, control-feel 결정 C18)**: 줍기·칸 전환 때 그 퀵슬롯이 1.0→1.15→1.0으로 0.15초,
  탈진 래치가 걸리는 틱에 스태미나 바가 1.0→1.12→1.0으로 0.2초 튄다. `UCL9HUDWidget::NativeTick`의 `TickPops`가
  사인 곡선으로 `SetRenderScale`만 옮긴다 — 색·불투명도는 건드리지 않고 WBP도 바꾸지 않는다. 배율·시간은 HUD
  프로퍼티(`QuickSlotPopScale/Time`, `StaminaPopScale/Time`). HUD가 뜨며 처음 채우는 소지품은 줍기가 아니라 튀지
  않는다(`bQuickSlotPopPrimed`); 이미 튀는 칸은 되감지 않는다(크기가 끊기지 않게)

구현(2026-09-06): `UCL9Widget`이 갖고 있어서 UI 표로 열리는 모든 화면이 함께 얻는다. 열릴 때
`FadeTime`(0.3s) 동안 밝아지고, `SlidePanelName`으로 지정한 안쪽 패널이 `SlideDistance`(24px)
아래에서 `SlideTime`(0.2s) 동안 감속하며 올라온다. 화면 전체를 움직이면 배경 덮개까지 따라
움직여 가장자리가 새기 때문에 패널만 움직인다. 값은 넷 다 WBP에서 조정한다(0이면 그 효과 없음).

**닫기는 상태와 그림을 분리한다**: `UIManager::CloseWidget`이 열린 목록·화면 이름에서 먼저 빼고
(그래서 `IsOpen`·`GetOpenScreen`은 즉시 닫힌 것으로 답한다), 위젯은 `PlayOutro()`로 화면에서만
어두워지다 스스로 부모에서 떨어진다. 닫힘 판정이 애니메이션을 기다리게 하면 M 여닫기 토글이
어긋나기 때문이다. 사라지는 동안에는 `HitTestInvisible`이라 클릭을 먹지 않는다.

### `ShowAnim`은 손으로 만든다 (2026-09-08)

스캔 라벨의 `ShowAnim`은 **에디터에서 사람이 만드는 것**이지 스크립트로 만들 수 없다. UE 5.8
소스에서 확인한 이유다.

- 컴파일러는 애니메이션의 **오브젝트 이름**으로 C++ 프로퍼티를 찾는다
  (`WidgetBlueprintCompiler.cpp` — `ParentClass->FindPropertyByName(Animation->GetFName())`).
  그래서 이름이 `ShowAnim`이면 `UCL9ScanLabelWidget::ShowAnim`에 저절로 붙는다.
- 그런데 트랙이 위젯을 붙잡으려면 possessable 바인딩이 있어야 하는데, `UWidgetAnimation`은
  `CreatePossessable`을 오버라이드하지 않는다 — 시퀀서 스크립팅의 `add_possessable`이 빈 GUID를
  돌려주고 아무것도 묶이지 않는다. 손으로 채워 넣는 길도 `FMovieScenePossessable`의
  `Guid`·`Name`이 private이라 막혀 있다.
- 바인딩 없는 애니메이션은 **수명만 정하고 아무것도 움직이지 않는다** — 지금의 C++ 페이드보다
  나쁘다. 그래서 만들 거면 UMG 디자이너에서 만들어야 한다.

만드는 순서: `WBP_ScanLabel`을 열고 애니메이션 패널의 [+ 애니메이션]으로 만든 뒤 이름을
정확히 `ShowAnim`으로 바꾼다 → 타임라인에서 라벨 루트를 트랙으로 추가하고 `RenderOpacity`(또는
`RenderTransform`의 스케일)에 키를 찍는다 → 저장. C++은 아무것도 고치지 않아도 되고, 있으면
그 길이가 라벨 수명이 되며 끝나는 순간 라벨이 스스로 숨는다(`OnAnimationFinished`).

## 글자 위계

1080p·배율 1.0 기준의 표다(전역 `ApplicationScale` 1.4가 그 위에 곱해진다). 2026-09-07에
전 화면을 이 표로 맞췄다 — 그전에는 일시정지를 뺀 모든 글자가 Bold 24 한 종류여서, 화면 안에서

| 20 Bold | 강조 값 (이더 · 아이템 이름 · 주문 카드 이름) |
| 20 Regular | 버튼 라벨 |
| 18 Regular | 보조 값 (머리 장비 · 아이템 값) |
| 16 Regular | 목록·힌트 (진행 중 주문 · 창구 재고 · 아이템 부가 정보 · 안내 문구 · 카드 상세) |
