# UI/UX 설계 (HUD 레이아웃)

> 화면에 무엇을 띄우고 무엇을 띄우지 않는가. 미니맵 표시는 전역 금지가 아니라
> **개체별 값(`bShowOnMinimap`)**으로 제어하고, 스태미나 바 없음은 rules.md의 흔들림 규칙에서 온다.

## HUD 방침

- **미니맵 표시는 개체별 값이다** — 몬스터·아이템의 `bShowOnMinimap`(기본 false)을 미니맵
  시스템이 읽는다. 전역 금지 원칙이 아니라 표에서 켜고 끈다
- **스태미나는 바 + 화면 흔들림 둘 다** (2026-09-05 번복 — decisions.md). 남은 양과 탈진
  래치 해제 시점이 흔들림만으로는 안 읽혀서다. 운반 흔들림은 여전히 바 없음
- 능력 바(회피/공격/아이템) 없음 — 그런 조작이 없다
- 라운드 목표금액·달성률 표시 없음 — 정산은 이틀 주기 기간 수입이다
- HP 표시는 **하트 초안** (2026-09-05): 좌상단에 ♥ × HP 개수 (10 초과 시 숫자) — 확정은
  플레이해보고. 바·퍼센트는 쓰지 않는 방향 (관리 자원화 방지 — 흔들림 규칙과 같은 결)

## 게임 중 HUD

```
┌─────────────────────────────────────────────────┐
│ [상단] N일차 · 밤 시계 (NightLength 잔여)        │
│                                                 │
│ [좌상단] HP · 스태미나 바 · 이더 (판 공유 자금)  │
│                                                 │
│              [게임 플레이 화면 (3D)]             │
│                                                 │
│ [좌하단] 진행 중 주문 (남은 재료 · 마감 일수)    │
│ [하단 중앙] 상호작용 프롬프트 · 던지기 차징      │
│ [우하단] 짐 슬롯 (손 · 품)                       │
└─────────────────────────────────────────────────┘
```

| 요소 | 내용 | 근거 |
|---|---|---|
| 밤 시계 | `NightLength` 잔여 — 만료가 실패라 보여야 한다 | rules.md |
| 스태미나 | 정규화 0~1 바. 탈진 래치 중에는 색이 바뀐다. CMC에 변경 이벤트가 없어 **폴링**한다 (차징 게이지와 함께 유일한 예외 — ui_system.md) | character.md |
| 이더 | `GameState.SharedMoney` (판 공유) — 좌상단 스태미나 바 아래 `MoneyText`에 "N 이더". `GetSharedMoney()`를 읽고 `OnMoneyChanged`로 갱신한다(지급·차감 양쪽에서 발동, 클라도 복제로 같은 값을 본다) | economy.md |
| 짐 슬롯 | 손에 든 것 + 품(Pocketable) + 머리(HeadItem — 헤드램프) | inventory.md |
| 주문 | 수락한 주문을 좌하단에 한 줄씩: 이름 · 재료×n · 마감 N일차까지 · **확정 보상 이더** (`GameState.AcceptedOrders`, `OnOrdersChanged`로 갱신). 보상은 카드의 범위가 아니라 수락할 때 굴려 확정된 `Reward`다 — 실제로 받을 액수를 보여준다(2026-09-06). 남은 재료 진행도는 아직 없다 | order.md |
| 상호작용 | 줍기·놓기·반납 프롬프트(하단 중앙 — 문구는 캐릭터 `GetFocusPrompt`가 조립, 비면 숨김), 던지기 차징 게이지(차징 중에만 표시) | raiding.md · input.md |
| 창구 재고 | 납품 창구를 바라보는 동안만, 프롬프트 위에 올려둔 것들을 보여준다: 같은 물건끼리 묶어 "익은 계란 ×2 · 340 이더" 한 줄씩 + 합계. 남이 올려도 바뀌므로 이벤트가 아니라 매 프레임 `ACL9Counter::GetStock()`을 읽는다(복제된다). 합계는 올릴 때 굴린 값의 합이고 실제 판매가는 목적지·일자 배율이 곱해진다 | order.md · economy.md |
| 조리 게이지 | 아이템 라벨 안의 가는 바 — 열을 받는 동안만 보인다(`ACL9Item::IsOnHeat`). `GetCookProgress()` 0~1로 채우고, 다음 전이가 "탄 것"이면(`IsNextBurnt`) 주황에서 붉은색으로 바뀐다 = 지금 집으라는 신호. 이게 없으면 이름이 바뀌기 전에는 얼마나 익었는지 알 수 없어 태우지 않을 방법이 없다(2026-09-06) | cooking.md |
| 아이템 라벨 | 아웃라인된 아이템 머리 위에 월드→2D 투영으로 붙는 라벨: 이름 · 개체별 실제 값(`ACL9Item::GetValue`, 호스트가 행 범위에서 굴려 복제) 이더 · 무게/품·손·수레/깨지기 쉬움 (2026-09-05 사용자 요청; 값을 범위가 아니라 개체 값으로 — 2026-09-06 사용자). 아이템(ACL9Item)만, 수레·항아리 같은 상호작용 액터는 프롬프트로 충분. 같은 액터의 행이 바뀌어도(요리) 다시 채운다 | item/common.md · economy.md |
| 스캔 | **우클릭**: 화면 중앙에서 원형 파동이 퍼지고(`ScanDuration` 0.8s) **그 순간 화면에 실제로 보이는**(그 프레임에 렌더됐고 뷰포트 안에 투영되며 시야 트레이스도 통과하는 — 화면 밖·가려진 것 제외, 2026-09-06 사용자) 반경 `ScanRadius`(15m) 안의 놓인 아이템에 이름·가격 라벨이 파동 도착 순서로 붙는다. **라벨은 켜져 있는 동안만 자기 애니메이션을 재생하고 끝나면 스스로 숨는다** — `WBP_ScanLabel`에 `ShowAnim` 위젯 애니메이션을 만들면 그 길이가 수명이고, 없으면 C++ 페이드(인 `FadeInTime` 0.12s · 유지 · 아웃 `FadeOutTime` 0.5s, 총 `ScanLabelDuration` 3s)가 대신한다 (2026-09-06 사용자). **스캔 한 번 = UI 표 Popup 행 `Scan`의 `WBP_Scan`(UCL9ScanWidget) 하나** — 라벨은 그 위젯의 LabelLayer에 개별로 붙고 개수 제한이 없으며, 파동과 라벨이 다 끝나면 위젯이 스스로 닫히면서 라벨도 함께 사라진다. 다시 우클릭하면 이전 것을 닫고 새로 연다. **보이는 종류는 WBP_Scan의 `ScanKinds`(ECL9ActorKind 목록)로 고른다** — 기본은 아이템만, 몬스터를 더하면 몬스터에도 이름 라벨(값 줄 없음)이 붙는다 (2026-09-06 사용자). 값은 WBP_Scan·WBP_ScanLabel 프로퍼티. 리썰 컴퍼니 스캔 참고 (2026-09-06 사용자 요청) | ui_system.md |

- 던지기 차징은 조작 피드백이라 게이지가 허용된다 — 스태미나 같은 "관리 자원"이 아니다.
- 미니맵은 초기 구현에서 생략. 넣을 때 무엇이 그려지는지는 개체별 `bShowOnMinimap` 값이 정한다.

## 화면 전환 — WBP_Main 하위

뷰포트에 붙는 위젯은 `WBP_Main` 하나이고, 전면 화면은 UIManager가 UI 표를 읽어 Screen
레이어에 배타적으로 연다 ([ui_system.md](ui_system.md) — 2026-09-05 구조 결정).

### 로비 (정차)

```
┌─────────────────────────────┐
│  N일차 · 누적 이더           │
│  플레이어 슬롯 0~3 (색 표시) │
│  캐릭터 선택                 │
│  주문서 선택 (N개 중 M개)    │
│  목적지 선택                 │
│  [밤 시작] (호스트)          │
└─────────────────────────────┘
```

구현(4c UI, 2026-09-06): 주문서 선택은 UI 표 `OrderSelect` 행(Screen)의 `WBP_OrderSelect`
(`UCL9OrderSelectWidget`)다. HUD가 `GameState.OnOrdersChanged`를 받아 `OfferedOrders`가 있으면 열고
비면 닫는다(열려 있어야 할 화면 = 상태의 함수). 카드는 제시 주문마다 런타임 생성(이름 · 재료×n ·
보상 a~b 이더 · 마감 d일), M개 고르면 [확정 (n/M)]이 켜지고 **호스트만** 누를 수 있다(클라는 "호스트가
주문을 확정합니다"). 확정은 `ACL9PlayerController::AcceptOrders(인덱스)`. 나머지(플레이어 슬롯 · 캐릭터 ·
목적지 · [밤 시작])는 미구현 — 밤 시작은 아직 `cl9.night`.

### 관전 (사망 시)

죽으면 `SpectateDelay` 뒤 동료 시점 관전으로 넘어간다. 부활 UI는 없다 — 회복 채널은
트럭 패드뿐이다.

구현(4a, 2026-09-05): UI 표 `Spectate` 행(Screen 레이어). 열고 닫는 주체는
`ACL9PlayerController`의 `bSpectating` OnRep이다 — 위젯이 스스로 열지 않는다. 위젯이 읽는
값: 관전 대상 = `PlayerController->GetViewTarget()`(동료 폰 → `GetPlayerState()`로 이름),
`IsSpectating()`. 대상 전환 버튼은 `SpectateNext()`를 부른다(IA_SpectateNext와 같은 함수).

화면 구성(`WBP_Spectate`, 부모 `UCL9SpectateWidget` — Source/CL9/UI): 상단 중앙의 작은 패널 하나.
「관전 중 · <동료 이름>」(뷰 타깃 폰의 PlayerState 이름 — 뷰 타깃 교체는 ClientSetViewTarget으로
와서 로컬 이벤트가 없으므로 0.25초 타이머로 다시 읽는다; 아직 자기 폰이면 「동료를 찾는 중…」) ·
안내 「다음 정차 때 트럭 패드에서 돌아옵니다」 · [다음 동료 (Tab)] 버튼. **화면을 어둡게 덮지 않는다** —
동료의 시점이 그대로 보여야 한다. 관전 중 M은 메뉴를 열고, 닫으면 관전 화면이 돌아온다.
카운트다운은 없다 — 화면은 딜레이가 끝난 뒤 열린다. 메뉴가 이 화면을 대체했다가 닫히면
관전 화면이 다시 열린다(PauseInput). 흐름 전체는 [character.md](character.md) 죽음 절.

### 새벽 결과 화면

`WBP_Dawn`(UCL9DawnWidget, UI 표 `Dawn` 행, Screen 레이어). 밤이 끝날 때마다 게임 쪽이 연다
(`ACL9GameMode::DawnUIRow`, 비우면 안 연다) — 정산 결과를 보여주는 자리다.

```
3일차 정산
이번 기간 1,240 / 목표 800 이더
통과 — 다음 기간이 시작된다
[계속]
```

미달이면 붉은 글씨로 "미달 — 판이 끝났다. 3일차까지 버텼다"가 뜨고 버튼이 [새 판으로]가 된다.
정산일이 아닌 새벽에는 견줄 목표가 없으므로 "N일차 새벽 · 이번 기간 X 이더"만 띄운다.

**숫자는 `OnSettled(Day, Earned, Target, bPassed)`가 실어다 주는 것을 쓴다.** 정산은 값을
정리하면서 기간 수입을 0으로 되돌리고 미달이면 1일차로 보내므로, 화면이 그 뒤에 GameState를
조회하면 보여줄 것이 남아 있지 않다. 그래서 신호는 **되돌리기 전에** 발동한다(2026-09-07).

클라이언트에서는 화면 열기(컨트롤러 RPC)와 정산(GameState 멀티캐스트)이 서로 다른 채널이라
도착 순서가 보장되지 않는다. 그래서 위젯은 붙는 순간 복제된 `GetLastSettlement()`를 한 번 읽고
(그날 것이면 그대로 표시), 그 뒤에 오는 신호로 갱신한다 — 순서와 무관하게 같은 숫자가 뜬다.

### 트럭 패널 (구매 화면)

`WBP_Shop`(UCL9ShopWidget, UI 표 `Shop` 행, Screen 레이어). 품목 기준·가격식은
[shop.md](shop.md)에 있고, 여기는 화면이 무엇을 보여주는지다.

```
트럭 패널
보유 1,240 이더
┌──────────────────────────┐
│ 프라이팬                  │
│ 200 이더 · 1/3 보유       │
└──────────────────────────┘
[닫기]
```

- 카드는 장비 표에서 런타임에 만든다 — `bPhysicalProp`인 행만(파는 것은 실물뿐이다).
  이름과 상세를 **다른 위젯 두 개**로 나눠 위계를 준다(글자 위계 절).
- 상세 줄은 `가격 · (상한이 있으면) N/M 보유 · (못 사면) 사유` 순으로 이어 붙인다.
  사유 문구는 화면이 만들지만 **판정은 만들지 않는다** — `ACL9GameState::CanBuy()` 하나를
  읽어서 버튼을 끄고 그 결과를 문구로 옮길 뿐이다. 화면이 규칙을 다시 구현하면 어긋나는
  순간 거짓말을 한다(창구 재고·주문 진행도와 같은 원칙).
- **클라이언트도 산다.** 그래서 판정이 GameMode가 아니라 복제되는 GameState에 있다
  (2026-09-07: 처음에 GameMode에 있어 클라 화면이 아무것도 못 읽던 것을 옮겼다).
  누가 사든 같은 지갑에서 나가므로 `OnMoneyChanged`가 오면 화면 전체를 다시 칠한다.
- 거절은 누른 사람에게만 온다(`OnBuyRejected`) — 안내 줄에 "프라이팬: 잔액 부족"처럼 뜬다.
- 화면을 여는 것은 트럭 패널 액터다. 상호작용한 사람에게 Client RPC로 연다 — 로비 주문
  화면과 달리 상태에서 파생시킬 것이 없어서, 누르면 곧바로 열린다.

### 메뉴

[계속] [설정] [로비로 나가기] [게임 종료].

**일시정지는 없다** (2026-09-06 사용자 확정). 온라인 협동 게임이라 한 사람이 세계를 멈출 수
없다 — 메뉴를 열어도 몬스터는 계속 쫓아오고 밤 시계도 계속 흐른다. 끊기는 것은 내 조작뿐이라
**메뉴를 여는 동안 캐릭터는 그 자리에 선 채 무방비다.** 이것이 밤중에 메뉴를 여는 값이다.

`WBP_Pause`(UI 표 `Pause` 행, Screen 레이어)는 화면을 검게 덮고 가운데에 패널을 띄운다.
에셋·입력 액션 이름의 `Pause`는 열고 닫는 키를 가리키는 옛 이름일 뿐 멈춤을 뜻하지 않는다.
[계속]은 `CloseSelf`, [게임 종료]는 Quit Game으로 배선돼 있다. [설정]과 [로비로 나가기]는
갈 곳이 아직 없어서(설정 화면 미구현 · 타이틀/세션 UI 미구현) 비활성이며, 왜 눌리지 않는지를
패널 맨 아래 안내 한 줄("설정과 로비 나가기는 준비 중입니다")이 설명한다. 두 화면이 생기면
비활성을 풀고 각각 설정 화면 열기·세션 종료로 잇는다.

## UI 애니메이션

- 화면 전환 0.3초 페이드, 패널 0.2초 슬라이드
- 중요 알림 번쩍임은 밤 만료 임박에만 제한적으로

구현(2026-09-06): `UCL9Widget`이 갖고 있어서 UI 표로 열리는 모든 화면이 함께 얻는다. 열릴 때
`FadeTime`(0.3s) 동안 밝아지고, `SlidePanelName`으로 지정한 안쪽 패널이 `SlideDistance`(24px)
아래에서 `SlideTime`(0.2s) 동안 감속하며 올라온다. 화면 전체를 움직이면 배경 덮개까지 따라
움직여 가장자리가 새기 때문에 패널만 움직인다. 값은 넷 다 WBP에서 조정한다(0이면 그 효과 없음).

**닫기는 상태와 그림을 분리한다**: `UIManager::CloseWidget`이 열린 목록·화면 이름에서 먼저 빼고
(그래서 `IsOpen`·`GetOpenScreen`은 즉시 닫힌 것으로 답한다), 위젯은 `PlayOutro()`로 화면에서만
어두워지다 스스로 부모에서 떨어진다. 닫힘 판정이 애니메이션을 기다리게 하면 M 여닫기 토글이
어긋나기 때문이다. 사라지는 동안에는 `HitTestInvisible`이라 클릭을 먹지 않는다.

## 글자 위계

1080p·배율 1.0 기준의 표다(전역 `ApplicationScale` 1.4가 그 위에 곱해진다). 2026-09-07에
전 화면을 이 표로 맞췄다 — 그전에는 일시정지를 뺀 모든 글자가 Bold 24 한 종류여서, 화면 안에서
무엇을 먼저 읽어야 할지 눈이 고르지 못했다.

| 크기·굵기 | 쓰는 곳 |
|---|---|
| 30 Bold | 전면 화면 제목 (메뉴, 주문 선택) |
| 24 Bold | 늘 보는 큰 값 (밤 시계 · HP · 상호작용 프롬프트 · 관전 대상) |
| 20 Bold | 강조 값 (이더 · 아이템 이름 · 주문 카드 이름) |
| 20 Regular | 버튼 라벨 |
| 18 Regular | 보조 값 (짐 슬롯 · 아이템 값) |
| 16 Regular | 목록·힌트 (진행 중 주문 · 창구 재고 · 아이템 부가 정보 · 안내 문구 · 카드 상세) |

주문 카드는 런타임에 C++이 만들므로 크기가 `UCL9OrderSelectWidget`의 `CardNameSize`(20) ·
`CardDetailSize`(16) 프로퍼티에 있다 — 카드는 이름과 상세를 **다른 위젯 두 개**로 나눠서
위계를 준다(한 덩어리 텍스트면 이름이 묻힌다).

## 접근성

- 글꼴 최소 16pt, 명확한 색 대비 — 위 표의 최솟값이 16이다
- 슬롯 색(`TintColor`)은 채도가 충분해야 한다 — 어둠 속 유일한 식별 수단
- 모든 오디오 신호에 텍스트 대안 (자막 옵션)
