# 참고 — 리썰 컴퍼니의 프런트엔드와 세션 흐름

> 설치본 Lethal Company 의 부팅 → 메인 메뉴 → 호스트·참가 → 로비(우주선) → 시작 → 죽음 → 전멸 → 해고 → 메인 메뉴 복귀까지의 흐름을 정리한 노트다.
> 조사 날짜 2026-10-05. 방법은 디컴파일 코드 읽기와 설치본 씬 데이터(UnityPy 직렬화 값·문자열 스캔) 읽기다. **플레이 실측이 아니다.**
> 코드·에셋은 이식하지 않는다. 디컴파일 소스는 옮겨 적지 않았고 구조와 수치만 적었다.

이미 [lethal-run.md](lethal-run.md)에 있는 내용(하루 루프, 쿼터, 페널티 공식, 접속 승인 순서, 위치 복제 등)은 다시 쓰지 않고, 거기에 없거나 어긋나는 부분만 채웠다. 다른 문서와 겹치는 부분은 한 줄로 가리키기만 한다.

## 표기 규칙과 출처

- 디컴파일 소스 파일은 `MenuManager.cs:720`처럼 파일명과 줄 번호로 적는다. `PlayerControllerB.cs`만 `GameNetcodeStuff/` 아래에 있다.
- `GAME`은 설치본 데이터 폴더 `C:\Program Files (x86)\Steam\steamapps\common\Lethal Company\Lethal Company_Data`이다.
- 출처는 세 종류로 구분해 적는다. "코드"는 디컴파일 소스에서 직접 읽은 것, "씬 데이터"는 `GAME`의 씬·에셋 파일에서 읽은 값(UnityPy와 문자열 스캔), "추정"은 근거가 간접적이라 단정하지 않는 것이다.
- 화면 문구는 거의 전부 한국어로 풀어 적었고, 버튼처럼 짧은 이름만 원문 그대로 적었다. 씬별 문자열 표(메인 메뉴·우주선 씬·시작 옵션 씬)는 조사하면서 뽑았지만 이 저장소에 두지 않았다.

## 0. 먼저 읽을 요지

1. **로비는 별도 씬이 아니라 우주선 그 자체다.** `SampleSceneRelay` 한 씬이 대기실, 하루 결산, 재정비, 해고 연출을 전부 맡고,
   달 씬은 그 위에 Additive로 얹혔다가 내려간다. 그래서 "게임 시작 전 로비"와 "하루가 끝난 뒤의 궤도 정박"은 같은 상태(`inShipPhase`)다.
2. **메인 메뉴로 돌아가는 길은 셋뿐이다.** 일시정지 메뉴의 나가기 확정, 호스트의 이탈(추방 포함), 연결 오류다.
   게임오버(해고)도 같은 씬에서 값만 초기화하고 같은 승무원이 그대로 이어서 한다.
3. **준비 확인(ready check)이 없다.** 첫 출발의 권한은 호스트의 레버 하나다. 서버가 확인하는 것은 "전원이 로딩을 마쳤는가"뿐이고,
   하나라도 로딩 중이면 레버가 제자리로 되돌아간다. 설치본 씬의 `singlePlayerEnabled`가 1이라 솔로 시작도 된다.
4. **가입 가능 구간은 "호스트가 월드 씬에 들어선 첫 프레임부터 첫 출발 확정 직전까지"다.** 첫 출발과 동시에 Steam 로비를
   떠나므로 그 뒤로는 새 참가도, 중도 이탈자의 재참가도 영구히 막힌다. 최대 인원은 코드에 리터럴 4로 박혀 있다.
5. **레버는 0.7초 길게 누르기(씬 값)다.** 첫 출발은 호스트만 할 수 있고, 첫 출발 이후의 착륙 레버는 살아 있는 누구나 당길 수 있다.
6. **개인 사망은 `YouDied` 4.25초 연출, 시체 카메라 1.5초, 가장 가까운 생존자 관전의 순서로 흐른다.**
   관전 중에는 관전 대상 주변의 산 사람 음성이 3D로 들리고, 죽은 사람끼리는 거리 없이 서로 들린다. 산 사람은 죽은 사람 목소리를 듣지 못한다.
7. **전멸 때 코드가 보내는 `allPlayersDead` HUD 트리거는 설치본의 어떤 AnimatorController에도 없는 파라미터다.**
   즉 별도의 "전멸" 화면은 나오지 않고, 우주선 이륙 연출 + 안내 방송 10초 + 효과음 + 결산 화면의 F 등급 덮개가 그 역할을 한다.
8. **일시정지가 없다.** Esc 메뉴는 오버레이일 뿐이고 게임은 계속 흐른다(`Time.timeScale`은 디버그 함수에서만 바뀐다).
9. **저장은 호스트만, 궤도에 있을 때만 한다.** 달 위에서 나가면 그날 진행분은 저장되지 않는다.
10. **호스트가 나가면 클라이언트는 전원 메인 메뉴로 쫓겨난다.** 호스트 이주는 없다.

`GAME\level0`부터 `level18`까지 19개 파일이 있는 것과 일치한다. 파일 번호와의 대응은 이 배치 순서에서 추정한 것이다.

## 2. 부팅에서 메인 메뉴까지

```
[InitSceneLaunchOptions] -> (Online / LAN 선택) -> [InitScene | InitSceneLANMode]
   -> (부트 화면) -> [ColdOpen1 | ColdOpen2 | 없음] -> [MainMenu]
```

### 2.1 시작 옵션 씬

- `IngamePlayerSettings`가 0.5초 뒤 설정을 읽고 패널을 켠다(`IngamePlayerSettings.cs:139-159`).
  이미 한 번 설정을 마친 사람(`playerHasFinishedSetup`)이면 앞의 안내 패널을 건너뛰고 곧장 마지막 패널("LAUNCH MODE")로 간다.
  즉 **설정을 마친 사람도 매 실행마다 Online/LAN을 한 번 눌러야 한다.**
- 패널 순서는 `LaunchSettingsPanels` 배열을 [ContinueButton]으로 넘기는 구조이고, 마지막 패널에서만 Continue 버튼이 사라진다(`PreInitSceneScript.cs:54-67`).
- 선택하면 효과음 → 설정 저장 → 0.2초 뒤 `InitScene`(온라인) 또는 `InitSceneLANMode`를 로드한다(`PreInitSceneScript.cs:75-101`).
  저장 중 오류가 나면 로드하지 않고 "파일 손상" 화면이 뜬다. 그 화면의 확정 버튼은 저장 파일 4개를 지우고 2초 뒤 게임을 종료한다(`PreInitSceneScript.cs:125-152`).
- 이 씬의 설정 항목은 밝기 슬라이더(감마), 마이크 켜기와 입력 장치, 음성 모드(음성 감지/푸시투토크)다.
  게임 안내 문구로 "인게임 음성 채팅을 전제로 설계됐으니 써 보라"는 권유가 들어 있다(씬 데이터).

### 2.2 부트 씬과 도입 시네마틱

- `InitializeGame.SendToNextScene()`의 경로(`InitializeGame.cs:73-112`):
  부트 효과음 재생 → 0.2초 → 건너뛰기 허용 → 부트 애니메이션 재생(`BootUpScreen` 클립 1.85초, 씬 데이터) →
  평상시에는 3초 + 0.2초 뒤 `MainMenu` 로드. 합계 **3.4초**다.
- 평상시에는 `OpenMenu` 입력으로 부트 화면을 건너뛰고 곧장 메인 메뉴로 간다(`InitializeGame.cs:63-71`).
  이 입력의 기본 바인딩은 시작 옵션 씬의 키 목록에 Esc와 Tab으로 적혀 있다. 다만 같은 목록에서 Tab은 유틸리티 슬롯 입력에도 배정돼 있어
  게임 중 실제 동작이 어느 쪽인지는 확인하지 못했다(12절).
- 도입 시네마틱 판정은 `Awake()`에서 한다(`InitializeGame.cs:40-61`).
  - `ColdOpen1`: 마지막으로 플레이한 버전이 50 미만이거나 실행 횟수(`TimesLoadedGame`)가 정확히 7일 때. 부트 화면 1.7초 뒤 로드.
  - `ColdOpen2`: 위가 아니고, (실행 횟수가 25 초과이거나 마지막 버전이 60 미만)이면서 `PlayedCinematic2`가 저장돼 있지 않을 때. 한 번만 재생되며 부트 화면은 오류판(`BootUpScreenError`, 3.717초 클립)이고 5.8초 뒤 로드.
  - 시네마틱 중에는 건너뛰기 입력이 코드에 없다(`canSkip`은 시네마틱이 아닐 때만 true).
  - 시네마틱이 끝나면 `EndColdOpenCutscene()`가 커서를 되살리고 `MainMenu`를 로드한다(`ColdOpenCinematicCutscene.cs:79-84`).

### 2.3 메인 메뉴 진입 직후의 상태

`MenuManager.Start()`가 하는 일을 순서대로 적으면 다음과 같다(`MenuManager.cs:254-376`).

1. 이전 세션이 연결 오류 메시지(`disconnectionReasonMessage`)를 남겼으면 그것을 팝업으로 띄운다. 없고 `disconnectReason`이 1이면 "호스트가 나갔다"는 팝업,
   2이면 "연결 시간이 초과됐다"는 팝업을 띄운다(2는 코드 어디서도 대입되지 않는다. 12절 참고).
2. LAN 모드면 LAN 경고 패널과 LAN 참가 버튼을, Steam 모드면 "Join a crew" 버튼을 보인다.
3. 기본 서버 이름을 정한다. LAN이면 "Unnamed", Steam에 로그인돼 있지 않으면 "Unnamed"와 함께 "Steam 서버에 연결할 수 없다, LAN만 하려면 시작 때 LAN을 고르라"는 안내 팝업,
   정상이면 `"{Steam 이름}'s Crew"`다. 이전에 저장한 공개 여부와 이름(`HostSettings_Public`, `HostSettings_Name`)이 있으면 그것을 쓴다.
4. 처음 메뉴에 들어온 세션이고 버전이 바뀌었거나 `AlwaysDisplayNews`(코드 기본 true)이면 "새 버전 안내" 패널을 띄우고 거기에 포커스를 둔다. 아니면 Host 버튼에 포커스를 둔다.
5. 세이브 슬롯 3개를 훑어 `FileGameVers`가 호환 하한보다 낮으면 해당 슬롯에 "호환되지 않음" 표시를 켜고 "손상될 수 있다"는 경고 팝업을 띄운다. 읽다가 예외가 나면 그 파일은 **즉시 삭제**한다.
6. 마지막 플레이 버전과 실행 횟수를 갱신하고, 메뉴 음악을 재생한다.
   처음 메뉴에 들어온 세션이면 열림 효과음 + 0.3초 + 0.1초 뒤 음악, 두 번째부터는 `skipOpening` 트리거로 열림 애니메이션을 건너뛴다(`MainMenuOpen` 클립 0.45초).

## 3. 메인 메뉴 UI 목록

아래는 `MenuManager`의 필드와 `GAME\level2`(MainMenu)의 문자열 표, 그리고 연결된 클릭 핸들러 이름에서 읽은 것이다.
버튼과 문구의 짝은 대부분 이름으로 확인했고, 짝이 불확실한 것은 "(추정)"으로 표시했다.

### 3.1 상태와 전환

```
MainButtons ──Host──▶ HostSettings ──Confirm──▶ [로딩 화면] ──▶ 월드 씬(호스트)
     │                    └─Go back─▶ MainButtons
     ├──Join a crew──▶ 서버 목록 ──행 클릭──▶ [로딩 화면] ──▶ 월드 씬(클라이언트)
     │                    └─Back─▶ MainButtons
     ├──Settings──▶ 설정 패널 ──Back / Confirm changes──▶ MainButtons
     ├──Credits──▶ 크레딧 패널 ──Back──▶ MainButtons
     └──Quit──▶ Application.Quit()  (확인 절차 없음, MenuManager.cs:860-863)
```

- 어느 패널에서든 실패하면 `MenuNotification` 팝업(문구 + 확인 버튼 하나)이 메뉴 위에 뜨고, 확인을 누르면 `MainButtons`로 돌아온다(`MenuManager.cs:670-683`).
- 로딩 화면이 켜지면 `MainButtons`와 서버 목록이 숨고 메뉴 음악 볼륨이 0.2로 줄며, 꺼지면 0.5로 돌아온다(`MenuManager.cs:608-668`).
- 패널마다 포커스를 둘 버튼을 코드가 지정한다(`EventSystem.SetSelectedGameObject`). 패드 조작을 전제로 한 구조다.
  포커스가 바뀔 때마다 선택 효과음, 눌렀을 때 확인 효과음, 취소 때 취소 효과음이 난다(`MenuManager.cs:171-210`).

### 3.2 메인 버튼 열(MainButtons)

| 요소 | 동작 |
|---|---|
| "> Host" | 호스트 설정 화면을 연다. 저장 슬롯 버튼의 색을 갱신하고 이전 공개 여부를 반영한다(`ClickHostButton`, `MenuManager.cs:760-775`). |
| "> Join a crew" | Steam 모드에서만 보인다. 서버 목록 패널을 연다. |
| "> Join LAN session" | LAN 모드에서만 보인다. 같은 패널에 IP 주소 입력란이 있고(씬 데이터), 접속은 `StartAClient()`가 맡는다(`MenuManager.cs:690-718`). 입력 값이 전송 계층에 들어가는 연결은 확인하지 못했다. |
| "> Settings" | 설정 패널(3.5). |
| "> Credits" | 크레딧 패널. 제작 협력자와 외부 음원 출처가 길게 적혀 있다. |
| "> Quit" | 즉시 종료. |
| 버전 표시 | `v{gameVersionNum}` 텍스트. 이 설치본은 80이다(안내 문구에서 확인). |
| LAN 표시 | LAN 모드일 때 "(Launched in LAN mode)" 문구가 켜진다. |

### 3.3 호스트 설정 화면

- **서버 이름 입력란.** 기본값은 2.3의 3번 항목과 같다. 비어 있으면 "이름을 입력하라"는 팁 문구를 띄우고 진행하지 않는다.
  40자를 넘으면 잘라 낸다(`ConfirmHostButton`, `MenuManager.cs:777-797`). 이름 필드에 글자가 들어오면 팁 문구가 지워진다.
- **공개 여부 토글(Public / Private 버튼).** 공개를 고르면 "서버 목록에 모두에게 보인다"는 설명이, 비공개를 고르면 "Steam 초대로만 들어올 수 있다"는 설명이 한 줄 나온다(`HostSetLobbyPublic`, `MenuManager.cs:815-836`).
  비공개 버튼의 화면 문구는 "Friends-only"일 가능성이 높다(추정: 그 문자열이 같은 씬에 있고, 코드의 비공개 분기가 `SetFriendsOnly()`를 부른다).
- **서버 태그 입력란("Enter a tag...").** 공개일 때만 켜지고, 비공개이거나 Steam을 끈 상태면 꺼진다(`MenuManager.cs:187-197`). 태그는 소문자로 저장되고 비워 두면 "none"이 된다.
- **세이브 슬롯.** "File 1/2/3"과 주간 챌린지 슬롯 "CHALLENGE"가 있다. 각 슬롯에는 저장돼 있으면 `$크레딧`과 `Days: n`이 보이고, 비어 있으면 아무것도 안 보인다(`SaveFileUISlot.cs:67-94`).
  선택한 슬롯은 눌린 상태로 강조된다(`SetButtonColor`, 애니메이터 `isPressed`). 호환되지 않는 슬롯에는 "File incompatible!" 경고가 켜진다.
  선택 값은 `GameNetworkManager.saveFileNum`/`currentSaveFileName`에 들어가고, 앱 종료 때 `SelectedFile` 키로 저장돼 다음 실행에서 복원된다(`GameNetworkManager.cs:285-303, 696-711`).
- **슬롯 삭제.** 슬롯마다 삭제 버튼이 있고, 누르면 "File N을 삭제하겠습니까?" 확인 패널이 뜬다(`DeleteFileButton.cs:12-15`). 확정하면 해당 세이브 파일만 지우고 삭제 효과음을 낸다.
- **챌린지 슬롯.** 이번 주 챌린지 이름은 주 번호(2023-12-11 기준)로 만든 가짜 이름이다(`GameNetworkManager.cs:157-272`). 이미 완료했으면 슬롯을 누를 때 호스트 설정 대신 순위표(Leaderboard)가 뜬다.
  순위표에는 "Sort: Friends / Similar rank / Top 20" 같은 필터, 새로고침, 내 점수 삭제, 다시 하기 버튼이 있다(`MenuManager.cs:417-585`).
- **확정과 뒤로.** "[ Confirm ]"이 `GameNetworkManager.StartHost()`를 부르고(`MenuManager.cs:777-797`), "Go back"은 설정 화면을 닫는 버튼으로 보인다(추정: 핸들러가 `DisableUIPanel`류로 연결돼 있다).
- **LAN 모드의 호스트 설정**은 "Host LAN Server:" 머리말 아래에 "Local-only"와 "Allow remote connections" 두 버튼이 있다. 각각 수신 주소를 `127.0.0.1` 또는 `0.0.0.0`으로 바꾼다(`MenuManager.cs:799-813`).

### 3.4 서버 목록(Join a crew)

- 머리말 "Servers", 새로고침 버튼, 거리 정렬 드롭다운(near / far / worldwide, 기본 worldwide = `sortByDistanceSetting` 2), 체크박스 두 개("With challenge moon"는 기본 켜짐, "With detected mods"는 기본 꺼짐), 태그 입력란이 있다(`SteamLobbyManager.cs:46-62`).
  모드 감지 체크박스를 켜면 "호스트가 변조된 버전을 쓰는 것 같으니 의도치 않은 동작을 겪을 수 있다"는 경고가 함께 켜진다.
- 목록을 요청하는 동안 "서버 목록 불러오는 중" 문구가, 결과가 0건이면 "참가할 수 있는 서버가 없다"는 문구가 빈 목록 자리에 뜬다(`SteamLobbyManager.cs:107, 152-155`).
  새로고침은 마지막 요청 후 0.5초가 지나야 다시 받는다(`SteamLobbyManager.cs:88-94`).
- **실제로 적용되는 필터는 여섯 가지뿐이다.** 거리 필터, 빈 칸 1개 이상, `vers`가 내 버전과 같을 것, (체크박스가 꺼져 있으면) `chal`이 "f"일 것, (체크박스가 꺼져 있으면) `dmods`가 "f"일 것,
  그리고 `tag`가 입력값(비어 있으면 "none")과 같을 것이다(`SteamLobbyManager.cs:133-148`).
  앞쪽 줄의 "최대 20개", `started=0`, `versNum` 필터는 `SteamMatchmaking.LobbyList`가 값 타입 `LobbyQuery`를 매번 새로 돌려주는 속성이라 버려지는 복사본에만 적용된다
  (Facepunch DLL을 디컴파일해 확인: `public static LobbyQuery LobbyList => default;`, `LobbyQuery`는 struct). 그래서 결과 개수 제한은 Steam 기본값이다(그 값은 확인하지 못했다).
- 방 목록의 한 줄은 이름(40자까지)과 `현재 인원 / 4`, 변조 여부 아이콘으로 구성된다. 이름에 부적절한 단어 26개가 들어 있으면 그 방은 목록에서 빼 버린다(`censorOffensiveLobbyNames` 기본 true, `SteamLobbyManager.cs:170-248`).
  챌린지 방은 다른 프리팹으로 그려진다. 줄 간격은 42픽셀이다.
- 줄을 누르면 `LobbySlot.JoinButton()`이 불려 4.2의 참가 절차가 시작된다.

### 3.5 설정 패널

메인 메뉴의 설정과 게임 중 Esc 메뉴의 설정은 같은 옵션 묶음을 쓰고, 둘 다 `IngamePlayerSettings`가 값을 관리한다.
옵션 목록은 `Settings` 클래스에 그대로 나열돼 있다(`IngamePlayerSettings.cs:12-83`).

- DISPLAY: 화면 모드(전체 화면, 창 전체 화면, 최대화 창, 창), 프레임 제한(제한 없음/144/120/60/30), 수직 동기화, 밝기(감마).
- GRAPHICS: 지형/풀 디테일, 간접광, 모션 블러, 픽셀 해상도.
- CONTROLS: 시선 감도, Y축 반전, 달리기 토글, "> Change keybinds"로 여는 키 재설정 패널. 재설정 가능한 동작은 이동 4방향, 달리기, 웅크리기, 상호작용, 스캔, 아이템 사용 1/2/3,
  버리기, 슬롯 좌/우 전환, 유틸리티 슬롯, 아이템 살펴보기, 가구 교체/회전/보관, 춤, 가리키기, 채팅 열기/보내기, 푸시투토크다(씬 데이터의 라벨).
- ACCESSIBILITY: 거미 공포증 모드, 고개 흔들림(Head Bobbing) 끄기, 화면 좌우 반전(코드상 4월 1일에만 켜지는 장난 기능이고, Esc 메뉴에서는 그날에만 이 옵션이 나타난다. `IngamePlayerSettings.cs:125-129`, `QuickMenuManager.cs:97-106`).
- 마이크: 음성 감지 또는 푸시투토크, 입력 장치 선택, 음량 미터.
- 확인 절차: 값을 바꾸면 "미확정 변경" 표시가 켜지고, 뒤로 가려 하면 "변경을 확정하겠습니까?" 패널이 뜬다. 버튼은 "> Confirm changes", "> Set to defaults", "> Reset all to default", "> Back"이다.
  메뉴를 닫을 때 확정 안 한 값은 버려진다(`QuickMenuManager.cs:342-353`의 `DiscardChangedSettings`).
- 모든 설정은 `LCGeneralSaveData` 파일의 키로 저장된다(`IngamePlayerSettings.cs:172-230`).

## 4. 호스트와 참가

### 4.1 호스트를 눌렀을 때

1. `ConfirmHostButton()`이 이름과 공개 여부를 `LCGeneralSaveData`에 저장하고, 비공개면 태그를 비운다. `HostSettings`(이름, 태그, 공개 여부)를 만든다(`MenuManager.cs:777-797`).
2. `GameNetworkManager.StartHost()`(비동기, `GameNetworkManager.cs:1206-1232`): 이미 로비가 있으면 떠나고, Steam이면 `CreateLobbyAsync(4)`로 **4칸 로비를 만들고 기다린다**.
   그다음 접속 승인 콜백을 달고 `MenuManager.StartHosting()`을 부른 뒤 `isHostingGame = true`, `connectedPlayers = 1`로 놓는다.
3. 로비가 만들어지면 `OnLobbyCreated`가 로비 데이터를 채운다(`GameNetworkManager.cs:610-659`):
   `name`(이름), `vers`(버전), `tag`(없으면 "none"), `dmods`(모드 사용 여부 t/f/u). 공개면 `SetPublic()`, 아니면 `SetPrivate()` + `SetFriendsOnly()`.
   **그리고 곧바로 `SetJoinable(false)`를 한다.** 아직 월드 씬이 없으니 들어올 수 없게 닫아 두는 것이다.
4. `MenuManager.StartHosting()`(`MenuManager.cs:720-752`): 로딩 화면 → `NetworkManager.StartHost()` → 클라이언트 동기화 모드를 `Single`로 지정 →
   "서버를 시작했다, 접속 중" 문구 → **1초 후 AudioListener 볼륨 0 → 0.1초 후 `SampleSceneRelay`를 `LoadScene`**. 호스트가 월드 씬에 들어가기까지 최소 1.1초에 씬 로드 시간이 더해진다.
5. 월드 씬에서 서버의 `StartOfRound.Update()` 첫 프레임에 `hasHostSpawned`가 켜지며 호스트의 `ClientPlayerList` 등록, 0번 플레이어 오브젝트 소유권 부여, 스폰 위치 텔레포트,
   **`SetLobbyJoinable(true)`**가 한꺼번에 일어난다(`StartOfRound.cs:2592-2601`). 챌린지 슬롯이면 로비 데이터 `chal`도 "t"로 갱신한다(`GameNetworkManager.cs:673-689`).
6. 서버의 `StartOfRound.Start()`는 이어서 저장 파일에서 시드, 행성, 쿼터, 마감, 누적 통계, 가구, 우주선 안 아이템을 복원한다(`StartOfRound.cs:872-907`, 자세한 필드는 lethal-run.md의 저장 절).
   첫날(`daysSpent == 0`)이면 우주선 스피커 소개 음성을 5.5초 뒤(메뉴가 열려 있으면 닫힐 때까지 기다린 뒤 0.2초) 재생한다.
   이 호출은 서버 전용 블록 안에 있어서 호스트의 화면에서 재생된다(`StartOfRound.cs:885-888, 1425-1428, 3679-3689`).

### 4.2 참가를 눌렀을 때

1. 방 줄을 누르면 `LobbySlot.JoinLobbyAfterVerifying()`이 서버 목록을 숨기고 로비 데이터를 새로 받는다(`lobby.Refresh()`).
   응답을 기다리는 동안 로딩 화면이 뜨고, **7초 안에 응답이 없으면 오류 팝업**이다(`LobbySlot.cs:51-101`, `GameNetworkManager.cs:551-557`).
   이미 받는 중이면 클릭을 무시한다(`waitingForLobbyDataRefresh`).
2. 응답을 받으면 `LobbyDataIsJoinable()`이 순서대로 거른다(`GameNetworkManager.cs:509-549`).
   (a) 로비의 `vers`가 내 버전과 다르면 거절, (b) 내가 차단한 사람이 호스트면 "오류"로 거절, (c) 로비 데이터 `joinable`이 "false"이면 "호스트가 아직 로딩 중이거나 이미 착륙" 문구로 거절,
   (d) 멤버 수가 4 이상이거나 1 미만이면 "가득 참"으로 거절. 통과하면 `JoinLobby()`로 간다.
3. `JoinLobby()`는 `lobby.Join()`이 성공하면 `StartClient(호스트 SteamID)`로, 실패하면 로비를 떠나고 "호스트가 아직 로딩하지 않았거나 이미 착륙했다"는 팝업을 띄운다(`GameNetworkManager.cs:1234-1266`).
4. `StartClient()`는 전송 계층의 대상 SteamID를 호스트로 지정하고, **접속 데이터에 `"버전,내 SteamID"` 문자열을 실어** `NetworkManager.StartClient()`를 부른다.
   시작이 되면 로딩 화면, 실패하면 로비를 떠나고 값을 되돌린다(`GameNetworkManager.cs:1285-1321`).
5. 서버의 `ConnectionApproval`이 6단계 검사를 한다. 순서와 거절 문장은 lethal-run.md 542~556행에 이미 정리돼 있다. 여기서 보태는 사실은 두 가지다.
   - 최대 인원은 `maxAllowedPlayers` 필드가 아니라 **리터럴 4**로 비교한다(`GameNetworkManager.cs:365`). 그 필드(`:39`)는 어디서도 쓰이지 않는다.
   - 승인이 거절되면 클라이언트는 `OnLocalClientConnectionDisapproved`로 가서 로딩 화면을 끄고 로비를 떠나며 네트워크를 닫고, 거절 사유가 팝업으로 뜬다(`GameNetworkManager.cs:442-458`).
6. 승인되면 NGO가 호스트의 씬 상태에 맞춰 `SampleSceneRelay`를 로드시킨다(동기화 모드 `Single`). 각 클라이언트는 `SceneManager_OnLoadComplete1`에서 `PlayerLoadedServerRpc`를 보내
   서버의 `fullyLoadedPlayers`에 등록된다(`StartOfRound.cs:771-788`). 월드 씬이 켜질 때 `NetworkManager` 싱글턴이 없으면 "로딩을 마치기 전에 연결이 끊어졌다"는 메시지를 남기고 바로 메뉴로 되돌아간다(`StartOfRound.cs:835-861`).
7. 서버의 `OnClientConnect()`는 **1~3번 중 비어 있는 가장 작은 번호**를 새 플레이어에게 배정하고, 그 플레이어 오브젝트의 소유권을 넘긴 뒤, 세계 상태를 한 RPC에 실어 보낸다(`StartOfRound.cs:1688-1743`, 필드 목록은 lethal-run.md 564-571행).
   받은 쪽은 자기 슬롯의 `isPlayerControlled`를 켜고 `GetPlayerSpawnPosition(번호)`의 우주선 안 위치로 텔레포트한다. 위치가 막혀 있으면 위로 0.5, 다른 번호의 자리, 우주선 안 무작위 위치의 순으로 대체한다(`StartOfRound.cs:1911-1954`).
   위치가 서버 값에서 6m 넘게 벗어나 있으면 최대 50회(2프레임씩) 다시 맞춘다(`StartOfRound.cs:2476-2488`).
8. 접속이 끝나면 새 플레이어의 클라이언트가 자기 Steam 이름과 ID를 서버로 보내고, 서버가 전원에게 이름 목록을 다시 뿌린다. 같은 이름이 있으면 번호를 덧붙인다.
   각 클라이언트는 채팅에 "[이름] joined the ship."을 남기고(`PlayerControllerB.cs:5024`), Esc 메뉴의 플레이어 목록 슬롯을 채우며(`QuickMenuManager.cs:440-454`), 12초 뒤 음성 효과를 갱신한다(`StartOfRound.cs:1435-1458`).
   Steam 이름은 문자만 남기고 구두점 등을 걸러 내며, 비면 "Nameless", 두 글자 이하면 "0"을 덧붙인다(`PlayerControllerB.cs:4925-4950`).

### 4.3 언제 들어올 수 있는가

| 구간 | 로비 상태 | 새로 들어오려 하면 |
|---|---|---|
| 호스트가 설정 화면에서 Confirm한 직후 ~ 월드 씬 로딩 중 | 만들어졌지만 `SetJoinable(false)` | 초대 수락처럼 로비를 직접 지정해 들어오면 로비 데이터 검사에서 "호스트가 아직 로딩 중" 문구로 거절된다. 검색 목록에 안 뜨는지는 Steam 쪽 동작이라 코드로 확인하지 못했다(추정). |
| 호스트가 월드 씬에서 첫 프레임을 돈 뒤 ~ 첫 출발 확정 | `joinable=true` | 들어올 수 있다. 달 경로를 고르는 이동 연출 중에도 같다. |
| 첫 출발(`StartOfRound.StartGame()` 서버 실행) 이후 | 서버가 `LeaveLobbyAtGameStart()`로 Steam 로비를 떠남, `gameHasStarted=true` | 로비가 사라져 목록에도 안 뜨고, 직접 연결해도 승인 단계에서 "이미 시작됨"으로 거절 |

- 서버가 로비를 떠나는 시점은 두 곳이다. `StartGame()` 안(`StartOfRound.cs:2781-2785`)과 `openingDoorsSequence()` 안(`StartOfRound.cs:2838-2842`)이고, 둘 다 `gameHasStarted`가 이미 true면 건너뛴다.
- `ManuallyEjectPlayersServerRpc`(터미널의 `ejectPlayers` 이벤트로 호스트가 판을 리셋하는 경로, 7.2)는 `gameHasStarted = true`만 세우고 Steam 로비는 떠나지 않는다.
  이때는 Steam 목록에 방이 남을 수 있지만 승인 단계에서 거절된다(코드 사실, 실제 UI에 노출되는지는 확인하지 않았다).
- 첫 출발 이후에는 모든 클라이언트의 Esc 메뉴에서 초대 버튼이 흐려지고 눌러도 동작하지 않는다(`StartOfRound.cs:2843`, `QuickMenuManager.cs:363-374`).
- Steam 친구가 보낸 초대를 수락했을 때 `MenuManager`가 없는 씬이면(즉 게임 중이면) 아무 반응 없이 무시한다. 메뉴에 있고 이미 다른 로비에 들어 있으면 "이미 로비에 있다"는 팝업을 띄우고 로비를 떠난다(`GameNetworkManager.cs:486-507`).
- Steam 풍부한 상태(rich presence)는 착륙 시 "Landed", 궤도 복귀와 도착 시 "Orbiting"으로 바뀌고, 로비 이름과 인원수를 그룹 정보로 올린다. 친구 목록에서 바로 참가하게 해 주는 장치다(`StartOfRound.cs:2844-2848, 3197-3201, 4510-4514`).

### 4.4 늦게 들어온 사람은 어떻게 되는가

늦은 참가는 첫 출발 전에만 가능하므로 늦게 온 사람이 보는 세계는 항상 "궤도에 정박한 우주선"이다.

- 호스트가 이미 뭔가 사 놓았거나 가구를 옮겼으면 그 상태를 두 개의 동기화 RPC로 받는다(lethal-run.md 573-578행).
- 서버의 `fullyLoadedPlayers`가 새로 온 사람을 아직 못 세었으면 호스트가 레버를 당겨도 출발하지 않고 레버가 되돌아간다(5.2).
- 첫 출발 이후에 연결이 끊긴 사람은 돌아올 수 없다. 서버는 그 슬롯을 `disconnectedMidGame`으로 표시하고, 들고 있던 것을 떨어뜨리고, 자리를 `notSpawnedPosition`으로 치운다(`StartOfRound.cs:1612-1686`).
  결산 화면에서는 그 사람도 "활동한 플레이어"로 이름이 남는다(`StartOfRound.cs:3134`, `HUDManager.cs:2505`).

## 5. 로비 단계(우주선 안에서 시작 전)

### 5.1 시작 전에 할 수 있는 것

월드 씬에 들어온 플레이어는 곧바로 1인칭으로 우주선 안에 서 있다. 게임이 시작되기 전에도 다음이 전부 가능하다.
아래 항목은 씬 데이터의 상호작용 문구와 코드로 확인한 것이다.

- 걷고 뛰고 웅크리고, 근접 음성 대화를 한다. 음성은 Dissonance로 3D 공간화되고, 채팅은 텍스트로도 된다(채팅 열기 키는 바인딩 목록에 있다).
  이름표는 머리 위에 뜨고, 이모트(춤, 가리키기. 시작 옵션 씬의 키 목록에는 숫자 키 1과 2로 적혀 있다)도 쓸 수 있다.
- 터미널에 접근해 행성 경로를 고르고, 도구와 가구를 사고, 도감과 저장 창고를 본다("Access terminal"). 경로를 바꾸면 이동 연출(5.4)이 돈다.
- 조명 스위치("Switch lights"), 보안 카메라 전환("Switch camera"), 확성기 끄기("Disable speaker"), 문 조작("Door controls", 문은 최대 20초만 닫아 둘 수 있다),
  아이템 충전기, 가구 보관("Store item")과 배치 모드를 쓸 수 있다.
- 슈트(옷)를 갈아입는다(`UnlockableSuit`).
- 처음 접속한 계정이면 4초 뒤(메뉴가 열려 있으면 닫힐 때까지 기다린 뒤) "스캔은 우클릭"이라는 안내 팁이 한 번 뜬다. 이 팁은 계정에 저장돼 다시 안 나온다(`PlayerControllerB.cs:955-961`).
- 새 세이브(첫날)라면 호스트의 화면에서 5.5초 뒤 우주선 스피커가 소개 음성을 튼다. "Disable speaker" 상호작용으로 서버를 거쳐 전원에게서 끌 수 있다(`StartOfRound.cs:3691-3745`).

### 5.2 게임을 시작하는 방법: 레버

- **레버는 우주선 안의 물체**이고 `InteractTrigger`로 구현돼 있다. 씬 데이터의 값은 `holdInteraction = 1`, `timeToHold = 0.7초`, `interactCooldown = 켜짐`, `cooldownTime = 2.0초`다
  (레버의 `triggerScript` path_id 6906). 즉 **0.7초 동안 상호작용을 길게 누르는 방식**이다.
  `openingDoorsSequence()`가 착륙할 때마다 `timeToHold`를 0.7로 다시 쓰는 코드가 있어 값이 일치한다(`StartOfRound.cs:2834`).
  마감 일수가 0일 때 레버를 잡고 있으면 4초로 늘리고 "마감 0일, 회사로 가서 팔아라"는 경고 팁을 띄운다(`StartMatchLever.cs:296-307`).
- **누가 당길 수 있는가.** 클라이언트의 레버는 `Start()`에서 `interactable = false`, 문구 "호스트여야 한다"로 잠긴다(`StartMatchLever.cs:309-316`).
  `Update()`는 2초마다 문구를 고르며, 아직 첫 출발 전이고 클라이언트이면 문구를 건드리지 않는다(`StartMatchLever.cs:318-354`).
  그래서 **첫 출발은 호스트만** 할 수 있다. 첫 출발 이후에는 궤도 복귀 때마다 `SetShipReadyToLand()`가 모든 클라이언트의 레버를 다시 켜므로
  살아 있는 누구나 착륙 레버를 당길 수 있고, 클라이언트가 당기면 `StartGameServerRpc`로 서버가 대신 시작한다(`StartMatchLever.cs:240-247`).
  죽은 사람은 레버 애니메이션 단계에서 막힌다(`StartMatchLever.cs:29-32`).
- **준비 확인은 없다.** 서버가 보는 조건은 다음 다섯 가지뿐이다(`StartMatchLever.cs:210-257`, `StartOfRound.cs:2745-2770`).
  이동 연출 중이 아님, `inShipPhase`임, 이미 로딩 시작이 아님, 씬이 하나뿐이고 던전을 만드는 중이 아님, 그리고 `fullyLoadedPlayers`가 접속 인원 이상일 것.
  최소 인원 조건은 코드에 있지만 **설치본 씬의 `singlePlayerEnabled` 값이 1이라 혼자서도 시작된다**(레버 컴포넌트의 직렬화 값에서 읽음).
  그래서 "최소 2명" 안내 문구는 이 설치본에서는 나오지 않는다.
- 한 가지라도 어긋나면 레버가 제자리로 돌아가고(`CancelStartGame`), 전원에게도 알린다(`CancelStartGameClientRpc`).
  로딩이 덜 끝난 사람이 있을 때는 레버 문구가 4초간 "플레이어들이 로딩 중"으로 바뀐다(`StartMatchLever.cs:249-256`).
- 레버 문구 요약: 첫 출발 전 호스트에게는 "시작", 첫 출발 후에는 "착륙", 당겨 놓은 동안에는 "출발", 착륙 중에는 "우주선이 내릴 때까지 기다려라",
  경로가 자정이면 "이 달에는 너무 늦었다"(`StartOfRound.cs:896, 3861`).

### 5.3 레버를 당긴 직후

레버를 당기면 모든 클라이언트에서 같은 일이 일어난다.

1. 당긴 사람은 로컬로 먼저 애니메이션을 돌리고(낙관적 적용) 서버에 알려 모두에게 같은 애니메이션을 재생하게 한다(`StartMatchLever.cs:52-64, 76-128`).
2. 모든 클라이언트에서 우주선 시동음이 시작되고 보안 카메라 두 대가 꺼진다. **2초 뒤** 착륙 소리가 나고(스크랩이 6개 넘게 있으면 달그락 소리 추가) 화면이 계속 흔들린다(`StartMatchLever.cs:130-173`).
3. 서버는 `StartGame()`에서 `beganLoadingNewLevel`을 켜고(첫 출발이면 Steam 로비를 떠남), `fullyLoadedPlayers`를 비우고, 모든 클라이언트에 로딩 값을 초기화하라고 알리고
   레버를 "우주선이 내릴 때까지 기다려라"로 잠근다. 시드를 정하고 달 씬을 Additive로 로드한다(`StartOfRound.cs:2772-2812`).
4. 전원이 달 씬을 올리면 서버가 0.5초 더 기다렸다가 던전 생성을 시작하고(`StartOfRound.cs:2820-2826`), 로딩 화면에는 시드가 적힌다(`RoundManager.cs:1179-1180`).
   각 클라이언트의 로딩 문구는 씬이 올라가는 동안 "월드 로딩 중", 다 올라간 뒤 다른 사람을 기다리는 동안 "승무원 대기 중"이다(`StartOfRound.cs:778-781, 831-832`).
5. 생성이 끝나면 모든 클라이언트가 `openingDoorsSequence()`를 시작하고, 거기서 로비 단계가 끝나 하루가 흐르기 시작한다(`StartOfRound.cs:2828-2925`). 이후 구간은 lethal-run.md의 "착륙과 이륙" 절이 다룬다.

### 5.4 로비에서의 경로 선택(터미널)

- 터미널에서 달을 고르면 서버가 `ChangeLevelServerRpc`로 크레딧과 상태를 확인하고(이동 중이 아니고 `inShipPhase`이고 로딩 시작 전이고 던전 생성 중이 아니고 챌린지가 아닐 것), 맞으면 전원에게 `ChangeLevelClientRpc`를 보낸다.
  틀리면 크레딧을 되돌린다(`StartOfRound.cs:4366-4453`).
- 이동 연출은 모든 클라이언트에서 레버를 잠그고, 이륙 효과음, 행성 날아감 애니메이션, 긴 화면 흔들림을 재생한 뒤 2초 + 그 달의 `timeToArrive`초 뒤에 도착한다
  (`StartOfRound.cs:4466-4494`). 달별 `timeToArrive`는 41 Experimentation과 220 Assurance의 1.0초부터 20 Adamance, 68 Artifice, 44 Liquidation의 4.0초까지이고 이름 없는 테스트용 프리셋은 5.0초다(씬 데이터 `SelectableLevel`).
  도착하면 레버를 다시 켜는데, **호스트이거나 이미 게임이 시작된 뒤인 사람에게만** 켠다(`StartOfRound.cs:4481-4484`).

### 5.5 저장 슬롯과 로비의 관계

- 로비가 만들어지는 시점에 이미 슬롯이 정해져 있다(호스트 설정 화면에서 고른 값). 월드 씬이 뜬 직후 서버가 그 슬롯의 값을 읽어 들인다.
- 우주선이 궤도에 도착할 때마다(`SetShipReadyToLand`) 자동 저장이 돌고 "Autosaving..." 아이콘이 깜박인다(`StartOfRound.cs:3380-3384, 3868`). 저장은 호스트만 쓴다.

## 6. 죽음에서 관전까지

lethal-run.md의 "죽음과 시체", "관전", "전멸" 절이 코드 흐름을 다뤘다. 여기서는 **화면과 소리, 입력**을 채운다.

### 6.1 개인 사망 직후

`PlayerControllerB.KillPlayer()`가 소유 클라이언트에서 실행된다(`PlayerControllerB.cs:6754-6839`).

- 즉시 일어나는 것: HUD 숨김(`HideHUD(true)`), 커서 아이콘과 힌트 숨김, 오디오 리스너를 관전 카메라로 이동, 메인 카메라를 관전 카메라로 전환, 근접 피사계 심도 켜기.
- 사망 연출 애니메이터에 `gameOver` 트리거를 보낸다. 이 애니메이터는 설치본의 `DeathScreens` 컨트롤러이고, `gameOver`로 `YouDied` 상태(클립 길이 **4.25초**)로 들어간다. `revive` 트리거는 0.233초짜리 `Revive` 상태로 되돌린다
  (AnimatorController 직접 읽음). 화면에 어떤 문구와 그림이 나오는지는 클립과 스프라이트 데이터에 있어 코드로는 알 수 없다(12절).
- **`isInGameOverAnimation = 1.5`초 동안은 자기 시체를 비춘다.** 시체가 있으면 1.5초 카운트다운이 돌고, 시체가 없으면(`Abandoned`로 죽은 경우 등) 이 구간 없이 곧바로 관전으로 넘어간다
  (`PlayerControllerB.cs:6095-6103, 7727-7738`).
- 들고 있던 아이템은 떨어뜨린다(시체가 없으면 서버가 슬롯의 아이템을 디스폰한다, lethal-run.md 346쪽).
- 서버는 `livingPlayers`를 줄이고 시체 오브젝트를 만들고 다른 클라이언트들에게 사망을 알린다. 다른 클라이언트는 사망자의 음성 피치를 되돌리고 음성 효과를 갱신하며, 자기가 이미 죽어 있으면 관전 상자 목록(6.3)에 그 사람을 올린다(`PlayerControllerB.cs:6842-6989`).

### 6.2 관전 중 카메라

- 관전 대상은 먼저 **죽은 자리에서 가장 가까운 살아 있는 플레이어**로 고르고, 그다음부터는 번호 순으로 돈다(`PlayerControllerB.cs:7964-8027`).
- **입력:** 마우스 이동으로 대상 주위를 돌고(좌우는 피벗 회전, 상하는 ±80도 제한), **아이템 사용 입력(`ActivateItem`)이나 상호작용 입력(`Interact`)으로 다음 생존자로 넘긴다**.
  단 관전 대상이 이미 죽었으면 그 입력은 무시되고 자동 전환을 기다린다(`PlayerControllerB.cs:1797-1816, 2317-2325, 3537-3543`).
- 카메라 위치는 대상의 하복부에서 0.7m 위를 피벗으로 삼아 뒤쪽 1.3m에 둔다. 벽이 막으면 그 지점에서 0.25m 앞으로 당긴다(레이캐스트 1.4m). 시야각은 66도로 고정한다(`PlayerControllerB.cs:7739-7802`).
- 관전 대상이 죽으면 1.5초간 그 시체를 비춘 뒤 다음으로 넘어간다. 전원이 죽은 상태에서는 타이머가 3배 빨라 0.5초다(`PlayerControllerB.cs:7742-7766`).
- 관전 중에도 Esc 메뉴를 열 수 있다. 죽은 사람은 Esc 메뉴 조건을 통과한다(`PlayerControllerB.cs:3368-3371`).

### 6.3 관전 중 화면 구성

- **죽은 사람들의 상자 목록**이 쌓인다(자기 자신 포함). 코드를 읽어 보면 상자는 죽은 사람마다 하나씩 만들어지고, 각 상자에는 Steam 프로필 사진, 이름,
  **지금 말하고 있는지를 나타내는 표시**가 있다(0.35초마다 갱신). 상자 간격은 70픽셀이다. 살아 있는데 연결이 끊긴 사람의 상자는 치워지고 아래 상자들이 70픽셀씩 올라온다
  (`HUDManager.cs:1307-1363, 1395-1446`). 죽은 사람끼리만 서로 들린다는 음성 규칙(6.4)에 맞춘 "지금 누가 말하는가" 표시판이다.
  이 목록은 죽은 직후 한 번(`hasLoadedSpectateUI`)과, 이미 죽은 상태에서 다른 사람이 죽을 때마다 갱신된다.
- "(Spectating: 이름)" 줄이 뜨며, 이름은 그때그때의 관전 대상이다(`HUDManager.cs:1448-1458`). 화면 어디에 놓이는지는 확인하지 못했다.
- **조기 이륙 투표 UI.** 달 위에 있고(`planetHasTime`), 배가 아직 떠나는 중이 아니면 "자동조종 우주선에 일찍 떠나라고 알려라: 우클릭 길게(3초)" 문구와 게이지, `(표 수 / 죽은 사람 수 Votes)`가 나온다.
  이미 투표했으면 "투표했다"로, 배가 1시간 뒤 떠날 예정이면 "1시간 뒤 이륙"으로 바뀐다(`HUDManager.cs:1614-1669`). 규칙 자체는 lethal-run.md 121-124행에 있다.
- 살아 있는 사람 중 아무도 10초 넘게 안 움직이는 상태가 12초 이어지면 같은 조작을 알려 주는 한 번짜리 팁이 7초간 뜬다(`HUDManager.cs:3231-3282`).
- 죽은 사람 클라이언트에는 HUD 대부분이 숨어 있다. 스캔(우클릭)은 죽은 사람에게 막혀 있다(`HUDManager.cs:1298-1305`).

### 6.4 관전 중 음성

`StartOfRound.UpdatePlayerVoiceEffects()`가 2초마다 정리한다(`StartOfRound.cs:4127-4218`).

- **죽은 사람의 목소리는 죽은 사람끼리만 들린다.** 죽은 사람이 듣는 죽은 사람 음성은 거리 감쇠 없는 2D에 음량 1.0이다. 산 사람이 듣는 죽은 사람 음성은 음량이 0이다.
- **산 사람의 목소리는 죽은 사람에게 3D로 들린다.** 오디오 리스너가 관전 카메라에 있으므로 관전 대상 주위의 소리가 들리고, 음량은 산 사람이 들을 때(1.0)보다 약간 작은 0.8이다.
- 죽은 사람의 음성 소스는 저역/고역 필터가 꺼지고 좌우 팬이 0으로 맞춰진다. 무전기는, 말하는 사람이 무전기로 말하고 **관전 대상이 무전기를 들고 있을 때** 2D로 들린다.
- 죽는 순간 오디오 리스너가 관전 카메라로 옮겨지고 믹서 스냅샷 호출이 한 번 일어난다(`PlayerControllerB.cs:6815-6816`). 그 스냅샷이 어떤 소리를 바꾸는지는 믹서 에셋이라 확인하지 못했다.

### 6.5 죽음의 페널티(화면에 보이는 형태)

개인 사망의 크레딧 감소와 경험치 변화 공식은 lethal-run.md 209-213행과 221-223행에 있다. 화면에 어떻게 나오는지만 적는다.

- 결산 화면의 플레이어 줄에서 살아 있으면 "생존" 아이콘, 죽었으면 "사망" 아이콘, **우주선에 못 타서 `Abandoned`로 죽었으면 "실종" 아이콘**이 나온다(`HUDManager.cs:2517-2531`).
  플레이어마다 최대 3줄의 비꼬는 메모("가장 게으른 직원", "가장 편집증적인 직원", "가장 많이 다친 직원", "가장 수익성 높은 직원")가 붙는다(`StartOfRound.cs:3130-3193`).
- 사망자가 하나라도 있으면(챌린지 제외) 결산 화면이 끝난 뒤 **벌금 화면**(`FinesUI` 클립 4.267초)이 뜨고, "사망자 N명: -X%"와 "(회수한 시신 M구)", "청구액: $Y"가 표시된다(`HUDManager.cs:2978-2995`).
- 별도의 개인 "게임 오버" 확인 화면이나 재도전 버튼은 없다. 죽은 사람은 하루가 끝날 때까지 관전하다가 결산 중에 자동으로 부활한다(6.6).

### 6.6 부활

- 부활은 하루 결산 중에 `ReviveDeadPlayers()`가 모든 클라이언트에서 한꺼번에 돌린다. 체력 100으로 되돌리고 우주선 안 자기 번호의 스폰 위치로 텔레포트한다(`StartOfRound.cs:3924-4077`).
  소유자의 `gameOver` 애니메이터는 `revive` 트리거로 0.233초에 되돌리고, 관전 UI를 치우고, 관전 카메라를 자기 피벗 아래로 되돌리며, 시체 오브젝트와 랙돌을 전부 파괴한다.
- 이 부활은 결산 시작 후 약 10초 시점에 일어난다(9절의 시간표). 따라서 부활한 사람은 결산 화면이 아직 도는 동안 이미 우주선 안에 서 있다.

## 7. 전멸, 해고, 그리고 로비 상태와 메인 메뉴의 구분

### 7.1 전멸(모두 죽음)

lethal-run.md 232-240행이 규칙을 다뤘다. 여기서는 **화면에 나오는 순서와 시간**을 채운다.

마지막 생존자가 죽으면 서버가 `allPlayersDead`를 켜고 `ShipLeaveAutomatically()`를 부른다. 이때부터의 시계는 다음과 같다
(`StartOfRound.cs:2710-2742`, 이륙 애니메이션 길이와 이벤트 시각은 씬 데이터).

| 경과 시간 | 일어나는 일 |
|---|---|
| 0초 | 우주선이 아직 착륙 중이면 착륙을 기다린다. 이륙 레버를 원위치시키고 `ShipLeave()` 실행(이륙 애니메이션 14.983초 시작). |
| 1.5초 | 모든 클라이언트에서 관전 카메라가 씬에 박혀 있는 **고정된 게임 오버 카메라 위치**(`gameOverCameraHandle`)로 옮겨진다. 죽은 사람(관전 카메라를 보고 있는 사람)에게는 오디오 환경도 "전멸용" 설정으로 바뀐다(날씨 효과를 끄고 태양을 켜고 잔향 프리셋 3번을 쓴다). 그 위치가 우주선 밖인지는 확인하지 못했다. |
| 2.5초 | 우주선 안내 방송이 나온다. 두 줄이고 각각 5초씩이라 10초 동안 이어진다(씬 데이터의 `waitTime` 5.0, 5.0). 내용은 "승무원이 돌아오지 않아 비상 코드를 발동했고, 자동조종이 가장 가까운 안전한 우주항으로 날아가며, 물건은 모두 잃었다"는 안내다. |
| 12.0초 | 전멸 효과음이 울린다. 이때 `gameOverAnimator`에 `allPlayersDead` 트리거도 보내지만 **그 이름의 파라미터를 가진 컨트롤러가 설치본에 없어 아무 연출도 일어나지 않는다**(GAME 전체 데이터에서 문자열 자체가 한 번도 안 나옴, 12절). |
| 12.9초 | 이륙 애니메이션의 `ElevatorFullyRunning` 이벤트. 아직 우주선 밖에 남아 있는 사람이 있으면 죽인다(전멸이면 해당 없음). 서버가 2초 뒤 달 씬을 내린다(`ShipHasLeft`). |
| 약 15초+씬 내리는 시간 | 서버가 결산 값을 계산해 `EndOfGameClientRpc`를 보낸다. 모든 클라이언트가 **하루 결산 화면**(`EndgameStats` 클립 11.65초)을 띄운다. 등급 F와 "전멸" 덮개가 켜지고 플레이어 줄에는 사망(또는 실종) 아이콘이 뜬다(`HUDManager.cs:2517-2549`). |

- 결산 직후의 흐름(10초 시점의 전원 부활, 3초 뒤 벌금 화면, 하루 넘기기)은 9절과 lethal-run.md의 하루 결산 절에 있다. 전멸은 쿼터와 마감을 그대로 둔 채 하루만 소모한다.
  **크레딧은 사망 페널티만큼 줄어든다.** `EndOfGame()`이 부활 직전에 `playersDead = 접속자 수 - 생존자 수`를 구하는데 전멸이면 그 값이 접속자 전원이라서,
  챌린지가 아닌 한 벌금 화면이 뜨고 `ApplyPenalty`가 그 인원만큼 곱해 적용된다(`StartOfRound.cs:3277-3286`, `HUDManager.cs:2978-2995`). 4명이 전멸하고 시신을 하나도 못 회수하면 기준 크레딧의 80%가 빠진다(하한은 `min(현재 크레딧, 60)`).
- **메인 메뉴로는 가지 않는다.** 결산이 끝나면 같은 우주선 로비 상태로 돌아가고, 같은 승무원이 이어서 한다.

### 7.2 해고(진짜 게임오버)

마감일에 쿼터를 못 채우면 서버가 결산이 끝난 뒤 `FirePlayersAfterDeadlineClientRpc`를 보낸다(`StartOfRound.cs:3296-3312`). 수치(경보, 흡입, 화면)의 개요는 lethal-run.md 196-207행에 있다. 전체 시계는 다음과 같다
(`StartOfRound.cs:3421-3541`).

| 경과 시간 | 일어나는 일 |
|---|---|
| 0초 | 터미널과 상호작용 중이면 강제로 빠져나오게 한다. 결산 통계(근무 일수, 모은 스크랩 가치, 사망 횟수, 걸음 수)를 문구로 만들고 로컬 통계를 0으로 돌린다. |
| 5초 | 경보 애니메이션(`ShipAlarm` 6.1초)이 돌고 우주선 조명이 꺼지며, "해고" 방송과 경보음이 나온다. |
| 14.37초 | 우주선 문이 궤도에서 열리고 기압 소리가 난다. 별 구체가 켜진다. |
| 14.62초 | 문 쪽으로 플레이어와 가구가 **진공에 빨려 나가기** 시작한다. 모든 플레이어의 들고 있던 것이 떨어진다. |
| 20.62초 | **해고 화면**이 켜진다(`GameOverScreen` 컨트롤러의 `GameOverAppear` 3.0초). 믹서 스냅샷 3번으로 2초에 걸쳐 전환되고(내용은 믹서 에셋이라 확인하지 못했다) 터미널의 구매 물건이 비워진다(`ClearBoughtItems`). 화면에는 "마감까지 쿼터를 못 채웠다", "당신은 해고됐다", 통계 네 줄, "직급은 유지되지만 우주선과 크레딧은 초기화된다"는 안내가 적혀 있다(씬 데이터). |
| 22.62초 | 별 구체가 꺼지고 호스트가 저장 값을 초기화하며(`ResetSavedGameValues`) 모든 클라이언트가 `ResetShip()`을 실행한다. |
| 28.62초 | 경보와 흡입이 멈추고 문이 닫힌다. 모든 플레이어가 자기 스폰 위치로 돌아와 조명이 다시 켜진다. |
| 30.62초 | 클라이언트가 서버에 준비 완료를 알리고, 서버는 전원이 모일 때까지 기다린 뒤 `EndPlayersFiredSequenceClientRpc`를 보낸다. |
| 그 직후 | 전원 부활, 해고 화면이 사라진다(`GameOverDisappear` 8.317초 애니메이션), `SetShipReadyToLand()`로 로비 상태 복귀와 자동 저장, 새 세이브처럼 우주선 소개 음성이 5.5초 뒤 다시 나온다. |

- 결산의 마지막에 이 분기로 들어오므로, 해고되는 날에도 통상의 결산 화면과 벌금 화면이 먼저 다 돈다(약 14.7~18.7초). 그 뒤 위의 30.62초 연출이 이어진다.
- **세이브는 지워지지만 같은 세션이 유지된다.** 크레딧, 쿼터, 마감, 가구, 곰팡이가 초기값이 되고 시드가 1 늘어난다(`StartOfRound.cs:3543-3566`, `GameNetworkManager.cs:849-894`). 직급과 경험치는 계정 전역 값이라 그대로다.
  접속자는 그대로이고 새 참가자도 받지 않는다(`gameHasStarted`는 true로 유지).
- 챌린지 슬롯에서는 이 해고 경로로 들어가지 않는다(`ManuallyEjectPlayersServerRpc`가 `!isChallengeFile`를 요구하고 결산 분기도 챌린지를 따로 처리한다, `StartOfRound.cs:3297-3312, 3411`).
- **자발적 리셋 경로가 하나 더 있다.** 터미널의 `ejectPlayers` 이벤트 노드가 호스트의 클라이언트에서 실행되면(호스트만, 챌린지가 아니고, 궤도에 있고, 해고 연출이 돌고 있지 않을 때)
  `ManuallyEjectPlayersServerRpc`가 같은 해고 연출을 시작한다. 서버는 전원 로딩 완료도 확인한다(`Terminal.cs:526-529`, `StartOfRound.cs:3387-3418`).
  이 노드를 부르는 명령어 문구는 확인하지 못했다(12절). 즉 Lethal에는 "실패하지 않아도 호스트가 판을 스스로 엎는" 경로가 있다.

### 7.3 "로비 상태로 복귀"와 "메인 메뉴로 복귀"의 구분

| 사건 | 도착 상태 | 근거 |
|---|---|---|
| 하루가 끝남(정상, 일부 사망, 전멸 모두) | 같은 월드 씬, `inShipPhase=true`(로비 상태). 자동 저장. | `StartOfRound.cs:3195-3318, 3848-3871` |

## 8. 일시정지, 나가기, 끊김

### 8.1 Esc 메뉴(QuickMenu)

- **`OpenMenu` 입력(기본 바인딩 목록에 Esc와 Tab이 함께 적혀 있다)**으로 연다. 이미 열려 있으면 닫고, 설정에 미확정 변경이 있으면 닫기 전에 확정 패널을 띄운다(`PlayerControllerB.cs:3355-3393`).
  터미널을 쓰는 중이거나 채팅 입력 중이면 이 입력은 그쪽 닫기로 소비된다.
- **게임은 멈추지 않는다.** 열리면 커서가 풀리고 이동, 시선, 상호작용, 점프 입력이 막히지만(`PlayerControllerB.cs:1837, 2029, 2053, 3397, 3507, 3651, 5361`) 시간과 AI와 다른 사람은 계속 움직인다.
  메뉴가 열려 있는 동안 우주선 스피커 소개나 팁 같은 일부 연출은 메뉴가 닫힐 때까지 기다리게 만들어 놓았다(`StartOfRound.cs:3682-3687`, `PlayerControllerB.cs:958-959`).
- 버튼: "> Resume", "> Settings"(3.5와 같은 설정 패널), "> Invite friends", "> Quit". "> Quit"를 누르면 확인 패널("게임을 떠나시겠습니까?")이 뜨고 "> Confirm"/"> Cancel"이 있다.
  **호스트가 달 위에서 이 확인 패널을 열면 "파일이 저장되지 않는다, 우주선이 궤도에 있어야 한다"는 보충 문구가 켜진다**(`QuickMenuManager.cs:376-382`, 문구 매핑은 추정: 조건과 씬 문자열이 일치).
- **"> Invite friends"**는 Steam 오버레이의 초대 창을 연다(`SteamFriends.OpenGameInviteOverlay`). 첫 출발 이후에는 버튼이 흐려지고 동작하지 않는다(`QuickMenuManager.cs:363-374`).
- **플레이어 목록**은 접속자가 한 명이라도 있을 때 메뉴 옆에 뜬다. 슬롯마다 이름, 음량 슬라이더(자기 자신 제외), 이름을 눌러 Steam 프로필 열기, **호스트에게만 보이는 추방 버튼**이 있다(`QuickMenuManager.cs:440-489`).
  음량 슬라이더는 해당 플레이어의 음성 볼륨을 로컬에서만 조절한다(`QuickMenuManager.cs:409-426`).
- **추방**은 호스트만 한다. 확인 패널 후 `StartOfRound.KickPlayer()`가 그 Steam ID를 이번 세션의 추방 목록에 넣고 연결을 끊고 채팅에 안내를 남긴다.
  1~3번만 추방할 수 있어 호스트 자신(0번)은 추방 대상이 아니다(`QuickMenuManager.cs:468-475`).
  확인 패널의 이름 표시는 이름의 앞 최대 6글자(이름 길이 - 1 미만)까지만 보여 준다(`QuickMenuManager.cs:458`).
- 편집기에서만 열리는 디버그 메뉴(적 스폰, 아이템 스폰, 부활, 무적, 테스트 방)가 같은 메뉴에 붙어 있다. 설치본에서는 `Application.isEditor`가 꺼져 있어 안 보인다(`QuickMenuManager.cs:319-326`).

### 8.2 나가기를 확정했을 때

`GameNetworkManager.Disconnect()`(`GameNetworkManager.cs:713-744`)가 한 번만 돈다(`isDisconnecting`).

1. 호스트이면 `disallowConnection = true`로 새 접속 승인을 막는다.
2. Steam 로비를 떠나고 풍부한 상태를 지운다. 모든 `NetworkObject`의 `DontDestroyWithOwner`를 끈다.
3. 저장한다(`SaveGame`): 이 컴퓨터의 플레이어 경험치와 직급을 `LCGeneralSaveData`에 쓰고, **호스트이면** 아래 규칙으로 슬롯 파일에 쓴다(`GameNetworkManager.cs:826-1056`).
   - 궤도에 있으면(`inShipPhase`): 쿼터, 크레딧, 마감, 행성, 가구, 곰팡이, 시드, 통계, 우주선 안 아이템을 전부 저장한다. 단 로딩 중이거나 던전 생성 중이면 건너뛴다.
   - 달 위에 있으면: 그날의 진행분은 저장하지 않는다. 대신 "그 달에서 저장 후 나간 횟수"(`Level{ID}TimesSavescumming`)를 올리고, 그 값이 5 이상이면서 곰팡이가 번질 수 있는 달이면 곰팡이를 퍼뜨린다.
   - 챌린지 슬롯은 점수만 기록한다.
4. `NetworkManager.Shutdown()` → 종료될 때까지 기다림 → 내부 값 전부 초기화 → `MainMenu` 로드. `MenuManager.Awake()`가 `isDisconnecting`과 `isHostingGame`을 되돌린다.
   `StartOfRound`가 없을 때(`Disconnect`가 `StartOfRound.Instance`를 요구한다)는 아무 일도 하지 않는다.
5. 앱 종료 시에도 같은 `Disconnect()`가 불리고 선택된 슬롯 번호가 저장된다(`GameNetworkManager.cs:696-711`).

### 8.3 다른 사람이 끊겼을 때

- **클라이언트가 호스트의 끊김을 알아챈 경우**: 연결 콜백에서 "끊긴 것이 호스트(0번)이거나 나 자신"이면 `disconnectReason = 1`로 놓고 `Disconnect()`로 메인 메뉴에 간다.
  메뉴에서는 "호스트가 나갔다" 팝업이 뜬다(`GameNetworkManager.cs:429-434`, `MenuManager.cs:265-282`). 호스트 이주는 없다.
- **서버가 클라이언트의 끊김을 알아챈 경우**(`StartOfRound.OnClientDisconnect`/`OnPlayerDC`, `StartOfRound.cs:1504-1686`):
  채팅에 "[이름] disconnected."를 남기고, 산 사람이었다면 `livingPlayers`를 줄이고, 슬롯의 플레이어 상태를 되돌린다. 달 위(`!inShipPhase`)였으면 `disconnectedMidGame`을 표시하고 마지막 생존자였으면 전멸 처리로 이어진다.
  들고 있던 아이템은 그 자리에 떨어지고, 플레이어 오브젝트는 `notSpawnedPosition`으로 치워지고 슈트가 기본으로 돌아가며, Esc 메뉴의 플레이어 목록 슬롯이 사라진다. 서버만 소유권을 회수한다.
  나머지 클라이언트에게는 `OnClientDisconnectClientRpc`로 같은 정리를 시킨다.
  결과적으로 **남은 사람은 아무 팝업 없이 계속 한다.** 나간 사람의 자리는 첫 출발 전이라면 다음 참가자가 재사용한다(1~3 중 가장 작은 빈 번호).
- 연결 끊김의 사유를 시간으로 판정하는 코드는 이 소스에 없다. `MenuManager`가 "연결 시간 초과"(`disconnectReason == 2`) 문구를 갖고 있지만 **어디서도 2를 대입하지 않는다**(`grep` 확인, 12절).

## 10. 좋은 로비 감각을 만드는 디테일

이 장은 사실만 적는다. CL9에 무엇을 옮길지는 판단하지 않는다.

1. **로비가 곧 게임 공간이다.** 별도의 대기실 UI 없이 같은 씬에서 1인칭으로 걸어 다닌다. 플레이어 오브젝트 4개가 씬에 미리 박혀 있고 접속하면 번호 순으로 자리가 배정되니,
   들어오는 즉시 몸이 있고 다른 사람이 보인다.
2. **시작 신호가 몸짓이다.** 레버를 0.7초 눌러 당기는 동안 전원의 화면에서 같은 레버가 움직이고, 시동음과 2초 뒤 착륙 진동이 전원에게 같이 들어간다.
   당기는 사람의 클라이언트는 로컬에서 먼저 반응하고(낙관적 적용) 서버가 확인한다. 시작이 거절되면 레버가 되돌아간다. 거절을 팝업이 아니라 몸짓으로 알린다.
3. **준비 확인 대신 서버가 보는 "전원 로딩 완료"만 있다.** 사람들이 서로 "준비됐어?"를 말로 묻게 되고(근접 음성), 로딩이 덜 끝난 사람이 있을 때만 레버 문구가 4초간 알려 준다.
4. **시작 권한의 비대칭.** 첫 출발만 호스트 전용이라 장난으로 시작할 수 없고, 이후 착륙은 누구나 한다. 이 구분이 레버 문구 하나("호스트여야 한다")로 표현된다.
5. **기다리는 동안 할 일이 우주선에 박혀 있다.** 터미널(경로, 구매), 조명 스위치, 보안 카메라, 슈트 갈아입기, 가구 배치, 확성기, 이모트와 채팅, 음성 대화가 전부 상호작용 물체로 존재한다.
   누가 자기 일을 하든 대기가 끊기지 않는다.
6. **신규 접속은 합류 안내 한 줄로 끝난다.** 채팅에 "[이름] joined the ship." 한 줄, Esc 목록에 이름 추가, 음성 추적 시작이 전부다. 별도의 환영 화면이 없다.
7. **로딩을 숨기지 않고 말한다.** 로딩 화면에 "월드 로딩 중", "승무원 대기 중", 시드가 적히고, 터미널과 레버 문구가 상태를 알려 준다.
8. **일시정지가 없다.** Esc는 설정, 초대, 나가기와 플레이어 목록(음량, 프로필, 추방)을 한 창에 모은 오버레이이고 게임은 흘러간다.
   초대 버튼과 목록이 같은 창에 있어 "로비를 관리하는 곳"이 메뉴이기도 하다.
9. **Steam 통합이 로비의 일부다.** 풍부한 상태에 로비 이름과 인원, 상태(Landed/Orbiting)를 올려 친구 목록에서 바로 합류하게 하고, 초대 수락은 메뉴 씬에서만 받는다.
10. **실패를 같은 공간에서 소화한다.** 전멸이나 해고가 메뉴로 튕기지 않고 우주선 안의 연출(방송, 경보, 진공 흡입, 해고 문구)로 끝난 뒤 다시 로비로 돌아온다.
11. **메뉴가 세계관 안의 기계다.** 부트 화면은 가짜 BIOS 문구이고 설정 밝기 조정 문구도 그 말투를 따른다. 첫 실행에만 시네마틱을 보여 준다.

## 11. lethal-run.md와 다르거나 새로 확인된 것

[lethal-run.md](lethal-run.md)를 읽고 대조한 결과다. 고칠 만한 부분과 더할 만한 부분을 나눠 적는다. 아래 줄 번호는 2026-10-05 정정을 달기 전 문서의 번호다.

### 고칠 만한 것

1. **49행의 "접속 인원 2명 이상(`singlePlayerEnabled`이면 1명도 허용)"**: 설치본 씬 값이 `singlePlayerEnabled = 1`이라 실제 빌드에서는 혼자서도 시작된다.
   "최소 2명" 문구는 이 빌드에서는 도달하지 않는 분기다.
2. **546행의 `maxAllowedPlayers = 4`**: 그 필드는 어디서도 쓰이지 않는다. 승인 검사(365행)와 로비 생성(1221행)이 4를 리터럴로 쓴다.
3. **236행의 "전멸은 크레딧·쿼터·마감을 그대로 남기고 하루만 소모"**: 쿼터와 마감은 맞지만 크레딧은 사망 페널티를 받는다. 전멸이면 사망자 수가 접속자 전원이라
   벌금이 인원 수만큼 곱해진다(7.1). 716행의 "전멸했지만 계속 진행된다"는 요약도 같은 점을 덧붙일 만하다.

### 더할 만한 것(문서에 없던 것)

- 전멸 연출 코드가 `gameOverAnimator`에 보내는 `allPlayersDead` 트리거는 설치본의 어떤 애니메이터에도 없는 파라미터라서 화면에는 아무 일도 일으키지 않는다(7.1).
- 레버가 0.7초 길게 누르기이며 첫 출발은 호스트 전용이라는 점(5.2).
- 로비가 월드 씬과 같다는 점, 가입 가능 구간의 정확한 경계, 로비 생성 직후 `joinable=false`였다가 호스트가 월드 씬에 선 뒤에야 열린다는 점(4.1, 4.3).
- 메인 메뉴의 화면 전체 목록과 상태 전이, 서버 목록의 실제 필터(6개)와 무시되는 필터(3.4).
- 부트와 도입 시네마틱의 조건과 시간, 시작 옵션 씬이 매 실행마다 Online/LAN을 묻는다는 점(2).
- 죽음의 화면 구성(죽은 사람들의 상자 목록, 투표 UI, 음성 규칙)과 `DeathScreens` 4.25초 연출(6).
- 해고의 정확한 시계(30.62초)와 결산의 정확한 시계(14.7/18.7초)(7.2, 9.5).
- 터미널에 호스트가 판을 스스로 리셋하는 `ejectPlayers` 경로가 있다는 점(7.2).
- 설치본의 `SelectableLevel` 달별 이동 시간(1.0~4.0초)과 우주선 이륙 애니메이션 14.983초 / 이벤트 12.9초(5.4, 7.1).
- Esc 메뉴의 구성, 저장 규칙(달 위에서 나가면 저장 안 함), 호스트 이탈 처리(8).

## 12. 확인 못 한 것

- **개인 사망 화면의 문구와 그림.** `DeathScreens` 컨트롤러가 `YouDied` 클립(4.25초)을 재생한다는 것만 확인했다. 그 안의 글자와 스프라이트는 클립 데이터에 있어 읽지 않았다.
- **전멸 때 `gameOverAnimator`에 보내는 `allPlayersDead` 트리거.** 설치본 전체 데이터에서 이 문자열이 한 번도 나오지 않는 것을 확인했다(`globalgamemanagers`, `resources.assets`, `sharedassets*.assets`, `level*` 전체 바이트 검색, 같은 방법으로 `gameOver`, `revive`는 찾아짐).
  그래서 "이 트리거는 아무것도 하지 않는다"고 적었지만, 에셋 번들 등 다른 위치에 컨트롤러가 있을 가능성까지 배제하지는 못했다. `StreamingAssets`에는 설정 JSON 하나뿐이다.
- **`Level12Liquidation` 씬.** `SelectableLevel` 에셋에는 있지만 빌드 설정 씬 목록과 `StreamingAssets`에 없다. 이 설치본에서 로드할 수 없는 달이거나 다른 방식으로 포함돼 있을 수 있다.
- **`MenuManager.disconnectReason == 2`("연결 시간 초과" 팝업)**를 대입하는 코드를 소스 전체에서 찾지 못했다. 같은 이유로 `StartConnectionTimeOutTimer`(10.5초)도 호출 지점이 코드에도 MainMenu 씬 문자열 표에도 없다. 죽은 코드로 보이지만 씬의 UnityEvent 연결은 문자열 표로 전부 확인한 것은 아니다.
- **Steam 로비 `joinable` 키의 출처.** `LobbyDataIsJoinable`이 `lobby.GetData("joinable")`를 읽는데, 이 키를 설정하는 코드는 `SetJoinable()`뿐이고 그 구현은 Steam API 호출 하나다.
  `GetData("joinable")`가 Steam의 예약 키인지는 Steam 쪽을 확인하지 못했다. 거절 문구의 존재로 동작은 짐작되지만 이 경로는 추정이다.
- **`Facepunch`의 `LobbyQuery` 결과 개수 기본값.** `WithMaxResults`가 호출되지 않으므로 Steam 기본값이 적용되나 그 값은 이 조사에서 보지 못했다.
- **메인 메뉴 텍스트와 개체의 정확한 짝.** UnityPy로 컴포넌트를 연결하지는 않고 문자열 표와 핸들러 이름으로 대응시켰다. 특히 "Friends-only" 문구가 비공개 버튼의 것이라는 점은 추정이다.
- **새 버전 안내 패널(News)의 표시 조건.** 코드는 `AlwaysDisplayNews`(기본값 true)와 버전 비교를 쓰지만 씬에 직렬화된 실제 값은 읽지 않았다.
- **`HUDManager`의 `gameOverAnimator`가 `DeathScreens`에 물려 있다는 점**은 파라미터 이름(`gameOver`, `revive`)이 그 컨트롤러에만 있다는 사실에서 추론했다. 오브젝트 참조를 직접 따라가지는 않았다.
- **Esc 메뉴를 여는 키.** 시작 옵션 씬의 키 설정 목록에 `OpenMenu`가 Esc와 Tab으로 적혀 있지만, 같은 목록에서 Tab이 유틸리티 슬롯 입력에도 배정돼 있다.
  또 같은 목록의 스캔 키(F)가 화면 문구의 "스캔: 우클릭"과 어긋나서 이 목록이 게임 중 실제 기본값 전체를 대표하는지 확신할 수 없다. 키 이름은 UnityPy로 입력 자산을 직접 읽어 확인해야 한다.
- **터미널의 `ejectPlayers` 이벤트를 부르는 명령어 문구.** 터미널 노드 에셋을 읽지 않았다.
- **사운드와 소리 크기, 화면 연출의 세부.** 효과음 클립 이름과 볼륨 값은 정리하지 않았다.
- **`Terminal` 명령 목록.** 로비에서 할 수 있는 일로 "경로 지정, 구매, 도감"까지만 언급했고 명령 체계는 이 조사 범위 밖이라 읽지 않았다.

## 13. CL9 설계에 참고할 관찰(결정은 하지 않음)

- CL9의 흐름 "시작 레벨 → Lethal식 메인 메뉴 → 로비 → 게임 → 사망 → 게임 오버 → 메뉴 복귀"를 Lethal과 견주면 가장 크게 다른 지점은 **게임 오버의 도착지**다.
  Lethal은 게임 오버도 로비로 돌아오고 메뉴 복귀는 사용자의 선택과 연결 오류뿐이다.
- "로비 = 허브 공간 = 결산·재정비 공간"이라는 구조 덕에 Lethal은 **전환 화면이 따로 없고**, 씬 로드가 필요한 구간(첫 출발, 하루 결산 때 달 씬 내리기)에만 로딩 화면이 있다.
- 가입 가능 구간을 "첫 출발 전"으로 못 박은 것이 접속 동기화 코드를 얼마나 줄였는지는 lethal-run.md 756-760행이 정리했다. 이 문서의 4.3은 그 경계를 코드로 확인해 준다.
- 관전 구현은 "카메라를 동료에게 붙이고 음성 규칙만 바꾼다"로 끝나며(6.2~6.4) 별도 관전 전용 씬이나 오브젝트가 없다.

## 14. 재현 방법

값은 설치본에서 UnityPy로 읽은 씬·에셋 데이터와 디컴파일 코드에서 얻었다. 덤프·문자열 표·스크립트는 이 저장소에 두지 않았다. 재현하려면 [README.md](../README.md)의 "어떻게 조사했나" 순서를 따른다.

- 쓴 도구는 `UnityPy`와 `TypeTreeGeneratorAPI`다. 캐시된 패키지만 쓰려면 `uv run --offline --no-project --with unitypy --with typetreegeneratorapi python <스크립트>` 꼴로 돌린다.
- 씬 파일의 인쇄 가능한 문자열을 뽑는 것(시작 옵션·부트·메인 메뉴·우주선 씬), 씬 파일의 MonoBehaviour 값을 필드 이름으로 골라 덤프하는 것(`singlePlayerEnabled`, `timeToHold` 확인), 애니메이션 클립 길이·이벤트 시각·애니메이터 컨트롤러 상태와 전이를 읽는 것, `SelectableLevel` 에셋의 씬 이름과 이동 시간을 읽는 것을 각각 직접 짠 스크립트로 했다.
- Facepunch의 `LobbyQuery`, `SteamMatchmaking.LobbyList`, `Lobby.SetJoinable`은 `ilspycmd`로 `GAME\Managed\Facepunch.Steamworks.Win64.dll`에서 해당 타입만 디컴파일해 확인했다.

## 15. CL9 에 옮긴 것

이 노트를 근거로 한 CL9 의 결정은 [../../goal/start-lobby.md](../../goal/start-lobby.md)가 정본이다(2026-10-05, 결정 L1~L12). **구현 중이다 — 결과는 그 문서 상단 Status 에 적힌다.** 요지만 적는다.

- **따른 것 — 로비는 게임 공간이다.** 대기실을 따로 만들지 않고 스테이지 레벨의 Lobby 단계(트럭 마당)를 대기실로 쓴다. 메뉴 레벨 하나와 하드 트래블(OpenLevel) 한 번만 있고 로비 레벨·ServerTravel 은 두지 않는다(L1). 10절 1)과 같은 방향이다.
- **따른 것 — 출발 레버.** 트럭 패드 옆에 런타임으로 세우는 출발 레버가 `StartNight` 를 부른다. 리썰의 0.7초 길게 누르기는 옮기지 않았고, 한 번 누르면 5초 동안 무장되고 다시 누르면 출발하는 두 번 누르기다. 호스트만 출발하며, 주문 제안이 남아 있으면 누를 때 주문 화면이 먼저 열린다(L6). 5.2절의 "시작 권한의 비대칭"에 해당한다.
- **시작 레벨과 메뉴.** `Lvl_Start`(빈 레벨, 네이티브 메뉴 게임 모드, 폰 없음)에 타이틀 화면을 띄운다. [방 만들기] → 스테이지 목록 → 호스트, [설정], [종료]. 화면은 C++ 위젯이 스스로 짜고 WBP 는 빈 껍데기다(L2·L5·L10). 하드 트래블 뒤에 UI 관리자가 죽어 있는 문제를 함께 고친다(L3).
- **게임 오버.** 전멸하면 관전 지연 뒤에 밤을 정리하고 단계를 Dawn 에 붙잡아 둔 채 게임 오버 화면을 띄운다. 호스트는 [시작 화면으로], 클라이언트는 [나가기]로 시작 레벨에 돌아간다(L7·L8). 리썰은 해고조차 같은 우주선 로비로 돌아오지만(7.2절) CL9 는 시작 레벨로 보낸다. 전멸해도 하루를 넘겨 계속하던 기존 규칙을 사용자 지시로 뒤집은 것이며, `bWipeEndsRun` 플래그(헤더 기본값 false)로 켜고 끈다.
- **전송.** 호스트는 `OpenLevel`(비 Shipping 빌드에서만 listen), 나가기는 설정의 시작 레벨 줄을 연다(L4). Steam 은 이번 범위 밖이다. 개발용 주소 접속 API 는 두되 타이틀의 참가 UI 는 스트레치다.
- **이번에 자른 것.** 접속 승인(PreLogin)·최대 인원 4·슬롯/명단·알림·실패 처리(L9). 리썰의 4칸 로비·가입 구간·호스트 이탈 처리·친구 목록 합류(4~5절)는 옮기지 않았고, 지금 동작(최대 16명·밤 중 합류·호스트 이탈 때 엔진 기본 동작)을 그대로 둔다.
- **스트레치.** 주문 전에도 로비를 걸어 다닐 수 있도록 OrderSelect 가 제안마다 한 번만 자동으로 열리게 하는 것(L11), 타이틀의 참가 구간.
- **기본 시작 맵.** `GameDefaultMap` 은 전체 순환 게이트가 통과한 뒤 마지막 단계에서만 `Lvl_Start` 로 바꾼다(L12).
