# 스테이지 연결과 출시 준비 — 2026-10-17

요청: 스테이지를 자연스럽게 연결하고 관련 파일을 정리한다. 빠른 출시를 우선한다.
연결의 의미와 출시 단계는 사용자 확인 대기이며, 우선 회사와 목적지 사이의 전환을 다룬다.

## 이번 변경

- `CL9GameMode.cpp`의 `TravelForRun`을 같은 모듈의 `GameMode/CL9StageTravel.cpp`로 분리했다.
- 저장 성공 → 화면·오디오 페이드 아웃 → 서버 레벨 이동 순서로 연결했다.
- 새 플레이어 컨트롤러의 로컬 화면은 페이드 인한다. 기존 트럭 도착 카메라는 유지한다.
- `CL9Rules.StageTravelFadeTime`은 기본 0.75초, 0이면 지연 없이 다음 틱에 이동한다. 유한한 비음수 값인지 검사한다.
- `ServerTravel`의 즉시 거절은 이어가기 표시·출발 중 표시·카메라 페이드를 해제한다. 비동기 접속 실패 복구 전체를 구현한 것은 아니다.
- 스테이지 도구의 진입점은 `Tools/Unreal/stages/README.md`에 모았다. 진행 중인 모델 원본·실험 스크립트·UE 에셋은 일괄 이동하지 않았다.

## 확인한 출시 장애물

현재 코드 기준이며 오래된 출시 명세의 진행 상태를 그대로 사용하지 않는다.

1. `CL9GameInstance.cpp`의 Shipping 경로에는 개발용 listen·주소 참가가 비활성화되어 있다. 출시용 온라인 세션 연결을 완성하고 패키지에서 확인해야 한다.
2. `CL9.uproject`에는 Redpoint 플러그인이 없다. `BP_HostLobby` 등 C++ 브리지는 있지만 플러그인과 BP 구현·실제 음성 검증은 별도 작업이다.
3. 같은 PC의 PIE 이력만으로 실제 다른 PC의 접속·음성·레벨 이동을 출시 검증 완료로 볼 수 없다.

사용자에게 요청한 정보: 목표 출시 단계, Steamworks/AppID 준비 여부, EOS/Redpoint 준비 여부, 다른 PC·테스터 확보 여부. 비밀 키는 채팅으로 요청하지 않는다.

## 검증

게임 타깃 컴파일 요청 #1 성공(46초). 새 `CL9StageTravel.cpp` 컴파일 및 CL9.exe 링크 완료. 로그: `.claude/runs/build-broker/logs/compile-20261017-025259.log`. 변경 파일의 `git diff --check` 통과.

에디터 반영·왕복 PIE·화면 확인은 아직 완료하지 않았다. 기존 PIE 실행 중이며 `cl9_lock.py acquire editor`가 훅 비활성을 이유로 거절했다. 기존 플레이를 중단하거나 잠금 가드를 우회하지 않았다. 잠금을 정상 획득할 수 있는 세션에서 에디터 빌드와 왕복 검증을 이어가야 한다.
확인할 흐름: 목적지 정산일 → 회사 → 목적지, 두 플레이어 동반 이동, 일차·돈·장비 유지, 연속 레버 입력, 페이드 시간 0, 이동 거절 시 재시도.

같은 장소에서 다음 판을 생성하는 시점과 실내·실외 공간 연결은 이번 변경에 포함되지 않는다.
