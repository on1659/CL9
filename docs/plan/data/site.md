# 목적지 — `UCL9SiteDef`

원정을 가는 곳. 양계장 · (나중에) 벌집 · 그 밖.

"스테이지"는 난이도 단계가 아니라 **어디로 가는가**다.
주문서가 필요한 재료를 정하고, 재료가 목적지를 정한다.

## 맵 생성

| 컬럼 | 타입 | 뜻 | 양계장 |
|---|---|---|---|
| `Generator` | enum `ECL9Generator` | **어떤 생성기를 쓰나** | `Henhouse` |
| `Theme` | `FName` | **어느 조각 묶음으로 짓나** (asset-swap.md) | `henhouse` |
| `AisleCount` | int | 통로 수 (1F) | 10 |
| `ColCount` | int | 열 수 (1F) | 16 |
| `AisleCountB1` / `ColCountB1` | int | 지하 격자 | 8 / 12 |
| `AisleWidth` | float | 통로 폭 (cm) | 250 |
| `ColWidth` | float | 열 폭 (cm) | 500 |
| `RowDepth` | float | 케이지 열 깊이 (cm) | 120 |
| `OpenWidth` | float | 케이지 열 관통 개구 (cm) | 200 |
| `PlugWidth` | float | 통로 마개 폭 (cm) | 180 |
| `TargetOpen1F` | int | **1층 개구부 목표 수** | 175 |
| `TargetOpenB1` | int | 지하 개구부 목표 수 | 105 |
| `JarCount1F` / `JarCountB1` | int | 항아리 수 | 7 / 6 |

**개구부 수가 난이도 손잡이다** — 줄이면 막다른 길이 늘고 도망칠 곳이 준다.

**2026-09-07 격자 확대** (사용자 결정 "맵이 작아서 금방 다 돈다"): 1층 8×6 = 48칸 → **10×8 = 80칸**
(1.67배), 지하 6×4 = 24칸 → 8×6 = 48칸. 개구부 수는 개방률(1층 61% · 지하 66%)을 유지하도록
간선 총수에 맞춰 올렸고(1층 82→142칸, 지하 38→82칸), 항아리는 칸 수에 비례해 늘렸다.
동시에 **통로 폭 255→250 · 열 폭 900→1000**으로 바꿔 조각 모듈(500cm)의 배수에 맞췄다 —
치수와 테마는 한 벌로 움직인다([../../systems/asset-swap.md](../../systems/asset-swap.md)).

축사 내부가 5400×2880 → **8000×3580cm**가 됐다. 달리기(654cm/s)로 장축 직선 주파가 8.3초에서
12.2초가 되므로 245초 밤이 빡빡해질 수 있다 — **밤 길이는 아직 안 건드렸다.** 실제로 뛰어 본 뒤
따로 판단한다(두 변수를 동시에 흔들지 않는다).

**벽 두께는 컬럼이 아니다.** `barn` 종류가 쓰는 조각의 실측 두께를 `ACL9SiteMap`이 읽어
`FCL9SiteFrame::Wall`에 넣는다 — 팩이 바뀌면 통로 폭이 그대로 따라 맞는다.

**2026-09-07 미로 밀도 (사용자: "내부가 미로가 아니라 그냥 단일 하나다")**: 위 확대 직후 걸어 보니
미로가 아니라 뻥 뚫린 복도로 읽혔다. 원인은 **칸 비율**이었다 — 칸이 1000 × 250(4:1)이라 정상적인
미로가 "줄무늬"로 그려졌고, 80m 복도에 막는 벽이 평균 2.7개뿐이었다.

> **생성기는 멀쩡했다.** `CarveFloor`의 Kruskal은 셀을 `Aisle*Cols + Col`로 인덱싱해 가로 간선
> `(a,c)-(a,c+1)`과 세로 간선 `(r,c)-(r+1,c)`를 잇는 **표준 2차원 격자 그래프**이고, 기하도 위상과
> 일치한다(닫힌 가로 간선 → 통로를 막는 플러그, 열린 세로 간선 → 케이지 열의 구멍). 위상을 고칠
> 일이 아니라 표 수치만 고칠 일이었다.

그래서 **축사 크기는 8000 × 3580cm 그대로 두고 칸만 절반으로 쪼갰다**: `ColWidth` 1000 → 500(조각
한 장, 통로 피치 370에 가까워 칸이 거의 정사각) · `ColCount` 8 → 16 · `ColCountB1` 6 → 12 ·
`OpenWidth` 360 → 200(칸의 40% — 구멍이 아니라 문처럼 읽힌다). 개구부 목표는 신장 트리(1층 159 ·
지하 95)에 고리를 조금 얹어 175 / 105로 잡았다 — **고리를 0으로 두면 완전 미로가 되지만 추격당할 때
도주로가 사라진다.**

결과: 1층 칸 80 → **160**, 직선 시야 평균 22m → **11m**, 통로당 막는 벽 2.7 → **6.1개**.
축사 물리 크기가 그대로라 **항아리 커버리지(1500u)는 영향을 받지 않는다** — 거리는 안 바뀌었다.

참고 분석: [../reference-lethal-company.md](../reference-lethal-company.md)

**격자 치수는 시드와 무관하게 고정이다.** 시드가 바꾸는 건 미로 내부(케이지·마개·주방·둥지·
개구멍)뿐이고 마당·트럭·계단·축사 외곽은 손으로 짓는다 — 아티스트가 만질 수 있는 영역과
해시에 물린 영역의 경계선이다.

## ★ 목적지마다 생성기가 다르다

맵 생성기는 목적지마다 다르다 — 양계장은 통로와 케이지 열이 격자로 늘어선 구조에 맞춰진
생성기가 필요하고, 벌집은 격자 구조가 달라 **별개의 생성기가 필요하다.**
`Generator` 컬럼이 어떤 생성기를 쓸지 가리킨다 — **목적지 하나 추가 = 맵 생성기 하나.**

레이아웃을 복제하지 않고 시드만 보내는 구조는 생성기가 바뀌어도 그대로다.

## 서식 동물

| 컬럼 | 타입 | 뜻 |
|---|---|---|
| `MonsterSpawns` | `TArray<FCL9SpawnEntry>` | `{ Alias, MinCount, MaxCount }` (schema.md 정본 필드명) |

양계장 기본값 (**미정 — 아래 참조**):

| 몬스터 | 최소 | 최대 |
|---|---|---|
| `chicken` | 8 | 12 |
| `goose` | 0 | 1 |
| `raccoon` | 0 | 0 |

**이 값은 기준값이고, 일자 곡선이 배율을 곱한다.** 3일차 곡선이 0.8이면 실제로는 6~10마리가
나온다. 상세는 [progression.md](progression.md).

거위를 되살릴 때는 요충지 술어를 통과해야 한다 — 거위가 좁은 길목에 서면 그 길이 막힌다.
