# 파동 (소음 반경 시각화) — 기획

> 플레이어나 몬스터가 소리를 내면 **그 자리에서 바닥에 원형 링이 퍼져 나간다.** 링이 멈추는
> 곳이 곧 그 소리가 닿는 곳이다 — 몬스터가 듣는 반경을 눈으로 보여 주는 채널이고, 숫자로만
> 있던 `CL9Rules`의 소리 반경을 화면에 꺼내 놓는 것이 이 시스템의 전부다.
> UE에서 어떻게 짓는지는 [../systems/wave.md](../systems/wave.md), 값은
> [data/wave.md](data/wave.md)(표)와 [data/rules.md](data/rules.md)(판정 반경).

**상태: 구현됨 (2026-09-16).** C++ `Source/CL9/FX/CL9WaveRenderer.*`·`Source/CL9/Data/CL9WaveTable.*`,
표 에셋 `Content/Data/WaveTable`, 나이아가라 `Content/Effects/NS_CL9_Wave` — 구현 상태와 실제 모양은
[../systems/wave.md](../systems/wave.md). 전신 프로젝트 CCL8(웹, three.js)에 있던 연출이고,
사용자가 "우리 게임에 꼭 구현해야 한다"고 정해 CL9로 옮겨 왔다. 값은 전부 초안이라 PIE 관찰 뒤
확정한다 ([data/wave.md](data/wave.md) PIE 관찰).

---

## 왜 만드나

**소음 반경은 지금 숫자로만 존재한다.** 달리면 390cm, 뛰다가 주우면 390cm, 밀치면 255cm —
[data/rules.md](data/rules.md)의 소리 표에 적혀 있고 몬스터가 그대로 판정한다
([../systems/monster.md](../systems/monster.md) 감각 파이프라인). 그런데 플레이어에게는 그 반경이
한 번도 보이지 않는다. "여기서 달려도 되나"를 배울 방법이 경험칙밖에 없고, 그래서 들킨 뒤에도
왜 들켰는지 모른다.

파동은 그 반경을 **행동한 순간 그 자리에** 그린다. 세 가지가 한꺼번에 해결된다.

1. **내 소리의 크기를 안다.** 걸으면 아무것도 안 뜨고(어그로 0), 달리면 큰 링이 뜬다 —
   "걷기는 안전하다"는 이 게임의 기본 안전 수단이 설명 없이 전달된다.
2. **동료의 위치와 행동을 읽는다.** 어둠 속에서 저쪽 통로에 피어오르는 링이 누가 뭘 하고
   있는지 알려 준다. 링의 색이 그 사람의 슬롯 색이라 누구인지도 같이 온다.
3. **벽의 모양이 잠깐 드러난다.** 링이 벽에 닿은 자리에 세로 자국이 남아, 손전등이 닿지 않는
   곳의 윤곽이 한 번 스친다.

세 번째는 이득이지만 공짜가 아니다 — **링을 보려면 소리를 내야 하고, 소리를 내면 몬스터가
듣는다.** 정보와 위험이 같은 행동에서 나오는 것이 이 시스템이 게임에 기여하는 방식이다.

---

## 규칙

### 1. 링의 반경은 그 행동의 소음 판정 반경이다

거짓말을 하지 않는다. 링이 멈춘 곳까지가 몬스터가 듣는 곳이고, 그 밖은 안 들린다.
표에는 **반경 배율(`RadiusScale`, 기본 1.0)** 만 두고, 반경 자체는 `CL9Rules`의 소리 컬럼을
그대로 읽는다. 배율을 1.0에서 옮기는 순간 링은 거짓말이 되므로 그때는 로드 검사가 경고를
남긴다 ([../systems/wave.md](../systems/wave.md) 로드 검사).

| 행동 | 링 반경의 출처 |
|---|---|
| 달리기 (발걸음마다) | `RunNoiseRadius` |
| 걸으면서 줍기 | `PickupQuietRadius` |
| 뛰다가 줍기 | `PickupLoudRadius` |
| 밀치기 | `PushNoiseRadius` |
| 미끼 (탄 요리·거위 잠듦) | `DecoyRadius` |
| 몬스터 울음 | **그 개체의 `PackAlarmRadius`** (무리 경보 반경 — 몬스터 표) |
| 그 밖 (수레·착지·던져 깨짐·몬스터 근접 소나) | 판정 반경이 없다 — 표의 `FallbackRadius` |

몬스터의 울음 파동은 **무리 경보의 시각 표현이다** (2026-09-16 사용자). 링이 닿은 동료는 실제로
깨어나므로 여기서도 "링 = 들리는 범위"가 그대로 성립하고, 종마다 경보 반경이 다르면 링 크기도
저절로 달라진다.

판정 반경이 없는 행동만 파동 표가 반경을 직접 갖는다. **이 경우에도 "링 = 들리는 범위"가
깨지지 않게, 그 행동의 청각 판정이 생기면 그때 `CL9Rules`로 옮긴다** (미결 1).

**예외 — 착지 핑 (2026-10-16 사용자).** 착지 파동은 재사용 대기(2초)가 지났으면 벽을 만날 때까지(상한 12m) 퍼지고, 사람·몬스터·아이템을
통과하며 그 위를 타고 넘는다. 착지는 판정 반경이 없는 행동이라 링이 들리는 범위를 속이지 않는다 — 대신 "뛰어서 주변을 비춰 본다"는 의도된
정보 도구다(몬스터 실루엣이 드러나는 것까지 의도). 몬스터 파동과 다른 플레이어 파동은 이 규칙 그대로다. 값과 근거는
[data/wave.md](data/wave.md) 3-1, 명세 [../goal/wave-landing-ping.md](../goal/wave-landing-ping.md).

### 2. 걷기는 링이 없다

걷기의 어그로는 0이다 ([data/rules.md](data/rules.md) 소리). 링이 곧 판정 반경이므로
걷기는 그릴 것이 없다. 표에는 `walk` 행이 있지만 **기본이 꺼짐**이다 — 나중에 "아주 작은
링이라도 있는 편이 읽힌다"고 판단되면 행만 켜면 된다(그 순간 링은 판정 없는 장식이 되므로,
켤 때 거위의 `WakeRadius`처럼 근거가 필요하다).

### 3. 표시 시점은 표가 정하고, 기본은 "항상"이다

| 값 | 언제 보이나 |
|---|---|
| `Always` | 언제나 — **기본** |
| `NightOnly` | 밤 페이즈에만 |
| `BlackoutOnly` | 정전 중에만 (CCL8이 하던 방식) |

CCL8은 파동을 정전 전용으로 묶어 두었다. 밝은 구간의 밸런스를 한 글자도 안 건드리겠다는
제약 때문이었고, 그래서 파동은 "정전 스테이지의 장치"였다. CL9은 반대로 **파동을 게임의
상시 채널로 쓴다** — 소음 반경을 배우는 일이 밤 내내 일어나야 하기 때문이다. 그래도 행마다
시점을 고를 수 있으니, 예컨대 몬스터 근접 소나만 정전 중에 켜는 식의 조합이 표에서 가능하다.

### 4. 소음원은 전부 구현하고, 행마다 켜고 끈다

"구현해 두고 표로 제어"가 원칙이다. 소음원 열두 가지 (1차 열한 가지 + 2026-09-20 `monster_pounce`):

| 행 | 무엇이 낸다 | 기본 | 비고 |
|---|---|---|---|
| `run` | 달리는 발걸음마다 | 켜짐 | 연속 상태라 **거리 간격**으로 이벤트가 된다(아래 5) |
| `pickup_quiet` | 걸으면서 주울 때 | 켜짐 | |
| `pickup_loud` | 최근에 달렸으면(`RecentRunTime`) 주울 때 | 켜짐 | |
| `push` | 몬스터를 밀칠 때 | 켜짐 | |
| `decoy` | 미끼가 놓일 때 (탄 요리 등) | 켜짐 | |
| `throw_break` | 던진 것이 깨질 때 | 켜짐 | |
| `cart` | 수레를 끄는 동안 | 켜짐 | `run`처럼 거리 간격 |
| `land` | 점프 착지 | 켜짐 | |
| `walk` | 걷는 발걸음 | **꺼짐** | 어그로 0이라 그릴 반경이 없다 |
| `monster_prox` | 몬스터가 가까이 왔을 때 몬스터 자리에서 | 켜짐 | 아래 6 |
| `monster_call` | 몬스터 울음 (기상 예고·경보) | 켜짐 | 반경 = 그 개체의 `PackAlarmRadius` — 무리 경보의 시각 표현이다 |
| `monster_pounce` | 몬스터가 잡기 예고(`Pounce`)에 들어가는 순간 몬스터 자리에서 | 켜짐 | 반경 306 = `Speed` 510 × `PounceWindup` 0.6 — **링이 다 퍼지는 순간이 덮치는 순간**이라 아래 7의 예외로 피해자에게 닿는다. `PounceWindup`을 바꾸면 이 행도 같이 (2026-09-20, [data/wave.md](data/wave.md)) |

행을 늘리는 것은 표가 아니라 코드다 — 소음원이 하나 늘면 그 사건을 내는 코드에 호출이 한 줄
필요하기 때문이다. 대신 **그 행의 값은 전부 표에 있다** ([../systems/wave.md](../systems/wave.md)
"어디서 무엇을 고치나").

### 5. 달리기는 발걸음마다 난다

달리기는 순간 사건이 아니라 상태다. 매 틱 링을 뿜으면 화면이 하얘지므로, **이동한 누적
거리가 `StepDistance`(표 열, cm)를 넘을 때마다 한 번**씩 낸다 — 발을 디딜 때마다 링이 하나씩
피어 걸음의 리듬이 그대로 보인다. CCL8이 쓰던 방식 그대로다(걷기 42u·달리기 52u마다).
수레도 같은 방식이고, 원샷 소음원은 이 값을 0으로 둔다.

### 6. 벽 차폐 · 벽 자국 · 고유색 — 셋 다 넣는다

- **벽 차폐**: 링은 벽을 통과하지 않는다. 소리가 지형을 속이면 안 된다는 규칙은
  [data/segkind.md](data/segkind.md)의 `bBlocksSight` 한 컬럼이 이미 담당하고 있고, 파동도 그
  목록을 쓴다 — 물통·상자처럼 일부러 시야를 안 가리게 해둔 낮은 물건은 파동도 안 가린다.
- **벽 자국**: 링이 벽에 닿은 자리에 세로 점 기둥이 한 번 찍힌다. 손전등이 닿지 않는 곳의
  윤곽이 잠깐 드러나는 것이 CCL8에서 가장 강한 그림이었다. 행별로 끌 수 있다.
- **고유색**: 다른 플레이어가 낸 링은 그 사람의 슬롯 색(`TintColor`)으로 뜬다 — 어둠 속에서
  누가 누군지 아는 유일한 단서가 슬롯 색이라는 기존 설계
  ([data/character.md](data/character.md) `TintColor`와 슬롯)를 그대로 쓴다.
  **자기가 낸 링은 더 밝다** — 내 소리와 남의 소리를 한눈에 가른다.

### 7. 몬스터의 링은 공포 발신기이지 레이더가 아니다

몬스터가 가까이 오면 그 몬스터 자리에서 링이 핀다. 이건 "근처에 뭔가 있다"만 말하는 장치이고,
**링은 절대 플레이어에게 닿지 않는다** — 발동 거리(`TriggerRadius`)보다 링 반경이 작아야 하고,
어긋나면 로드 검사가 잡는다. 닿는 순간 그것은 "내가 위험하다"를 알리는 레이더가 되어,
눈·발각 게이지·`WakeTelegraph` 같은 기존 읽기 채널을 전부 무의미하게 만든다
([../systems/warning.md](../systems/warning.md) — 위협은 월드에서 읽는다).

벽 차폐가 링을 깎으므로 벽 너머의 몬스터는 링도 잘려서 온다. 이것도 정직함의 일부다.

**예외는 잡기 예고 링(`monster_pounce`) 하나다** (2026-09-20). 그 링은 "근처에 뭔가 있다"가 아니라
**덮침이 닿는 거리와 시각**을 보여 주는 것이 목적이라 피해자에게 닿는다 — 링이 멎는 순간이 덮치는
순간이다. 레이더가 아니라 예고 자체의 그림이다 ([data/monster/common.md](data/monster/common.md) 잡기 예고).

## 파동이 아닌 것

| 헷갈리는 것 | 무엇이 다른가 |
|---|---|
| **스캔 파동** (우클릭) | 화면 중앙에서 퍼지는 **UMG 화면 효과**다. 아이템 이름·가격 라벨을 붙이는 UI이고 월드에 링이 없다 ([../systems/ui.md](../systems/ui.md) 스캔) |
| **미니맵** | 미니맵에 무엇을 그리나는 전역 계약이 아니라 **종별 값** `bShowOnMinimap`이 정한다 ([data/monster/common.md](data/monster/common.md) 표시) — 파동은 그와 무관한 월드 연출이지 지도 표시가 아니다 |
| **몬스터 청각 판정** | 파동은 눈에만 보인다. 몬스터가 무엇을 듣는지는 여전히 `CL9Rules`와 몬스터 감각이 정한다 ([../systems/monster.md](../systems/monster.md)) |

## CCL8과의 차이

| | CCL8 (원안) | CL9 |
|---|---|---|
| 표시 시점 | 정전 중에만 (밝은 구간 밸런스 동결이 제약이었다) | **표의 열, 기본 항상** |
| 반경 | 시각용 상수를 판정 상수와 따로 뒀다 (`VIS_RUN` 130 ↔ 어그로 310) | **판정 반경 그대로** + 배율 하나 |
| 값이 사는 곳 | 코드 상수 (`WAVE_SPEED` 170 · `WAVE_RAYS` 540 · `STEP_RAYS` 180) | **표의 열** — 리소스·속도·두께·색·파워·광선 수까지 전부 |
| 걷기 | 연한 청색 링이 떴다 | **꺼짐** (어그로 0이라 그릴 반경이 없다) |
| 몬스터 소나 | `PROX_R` 260 안에서 심박처럼 빨라지는 케이던스 | 같은 개념, 간격·반경은 표 |
| 그림 | 광선 540개(발소리 180)를 미리 쏴 벽 뒤를 막고, 벽에 닿은 자리에 점 기둥 | 같은 구조를 Niagara로 (광선 수는 표 열) |

CCL8의 수치는 **원안**일 뿐이다. CCL8은 1u = 3cm이므로 속도 170u/s는 510cm/s에 해당하고,
실제 값은 balance가 [data/wave.md](data/wave.md)에서 정한다.

## 옵션으로 열 것인가 — 열지 않는다

[settings.md](settings.md) 체크리스트를 돌린 결과다.

1. **이 값이 달라도 판이 공평한가 → 아니다.** 파동을 끄고 켜는 것은 곧 "몬스터가 듣는 범위를
   보느냐"이고, 넷이 서로 다른 값을 가지면 유불리가 그대로 갈린다. 체크리스트가 "몬스터 감지
   표시"를 이름으로 지목해 막고 있는 바로 그 종류다.
2. 나머지 항목은 볼 필요가 없다 — 하나라도 "아니오"면 옵션이 아니다.

따라서 **표시 여부·색·밝기는 전부 데이터 표의 값**이고, 플레이어 설정 화면에 뜨지 않는다.
개발 중에 잠깐 끄는 것은 치트 쪽 몫이다(`cl9.fxoff` 계열 — [../systems/cheats.md](../systems/cheats.md)).

접근성(빛 번쩍임에 민감한 사람) 관점의 재검토는 접근성 섹션이 생기는 시점으로 미룬다 (미결 4).

## 미결

1. **소음 이벤트와 몬스터 청각을 합칠 것인가.** 지금 몬스터는 매 틱 "거리 ≤ `RunNoiseRadius`
   이고 달리는 중"을 스스로 본다(폴링). 파동은 "소음이 난 순간"이 필요해서 이벤트를 새로
   만든다. 둘을 하나로 합치면(몬스터가 이벤트를 듣는 구조) 줍기·밀치기·미끼의 반경이 비로소
   청각에 물리지만, **그건 몬스터 감각을 바꾸는 별건이다** — 이번 실행에서는 청각 판정을
   건드리지 않는다.
2. **판정 반경이 없는 소음원**(수레·착지·던져 깨짐·몬스터 근접 소나)의 반경은 지금 파동 표에만
   있다. 그 행동들의 청각이 생기면 `CL9Rules`로 옮기고 표는 배율만 남긴다.
