# 개발 계획 — 한 스텝씩 쌓기

Status: **진행 중** · CCL8 `docs/plan`에서 이식 (2026-08-30) · 진행 현황 갱신 2026-09-21
(①②③ 완료 · ④는 4g 목적지 선택·세션 UI만 남음 · ⑤는 5a~5d 완료, 5e는 처형 클립 Run 2만 남음 ·
세션(접속·재접속·Steam)은 아직 없음 · ④~⑤ 이후 더해진 시스템은 아래 "④~⑤ 이후 더해진 시스템" 절)

**이 문서가 현재 작업 순서의 정본이다.** UE 아키텍처의 정본은
[../conventions.md](../conventions.md)(§ 2~5 · § 10)다 — 2026-08-31 결정으로 확정했다
([../decisions.md](../decisions.md)).

## 왜 이 계획인가

직전 프로젝트(CCL8)는 세션·생성기·판정 코어부터 쌓다가, 코드가 5천 줄 넘게 쌓인 뒤에도
걸어다닐 캐릭터 하나 없어서 맞게 짓고 있는지 눈으로 확인할 방법이 없는 상태에 이르렀다.
전부 화면 뒤에 있는 것들이라, 만들어도 맞는지 확인할 길이 없었다.

CL9은 그 순서를 뒤집는다. **눈에 보이는 것부터 하나씩 쌓고, 매번 직접 해보면서 간다.**

---

## 네 가지 원칙

### 원칙 1 — 모든 스텝은 실행해서 직접 해볼 수 있어야 한다

"컴파일 성공"으로 끝나는 스텝은 만들지 않는다. 아래 표의 "직접 해보는 것" 칸에 채울 게 없으면
그건 스텝이 아니라 다른 스텝의 일부다.

### 원칙 2 — 캐릭터·에셋은 나중에 사서 갈아끼운다

```
ACL9Character (C++)           BP_CL9Character (블루프린트 자식)
  캡슐 39 / 90                   메시 · 머티리얼 · AnimBP
  이동 · 네트워크 · 카메라 · 입력    ↑ 여기만 갈아끼운다
  ↑ 에셋 참조 0줄
```

- C++ 클래스에 메시·애니메이션 경로를 **한 줄도 안 쓴다.**
- `DefaultPawnClass`는 C++ 클래스가 아니라 **BP를 가리킨다.**
- **살 때 주의:** 캡슐 크기가 기준이고 메시가 거기 맞춘다. 캡슐을 키우면 통로 폭이 깨진다.

### 원칙 3 — 수치는 전부 에셋에서 읽는다

숫자 하나 바꾸려고 빌드를 다시 하는 건 말이 안 된다. **전부 에디터에서 바꾸고 바로 확인한다.**

대신 로드할 때 **관계 검사**를 돌린다. 숫자들끼리 지켜야 하는 부등식이 있어서다:

```
A1  지친 빈손 속도 > 잡는(Catch) 몬스터의 추격 속도   ← 깨지면 짐 다 버려도 못 도망침
A2  질주 예금     > 시야 반경                        ← 깨지면 시야를 못 끊음
A4  잡는 몬스터의 추격 < 운반 질주                    ← 깨지면 잡힘이 확정
```

경보꾼 거위(`CatchRadius` 0)는 A1·A4 대상이 아니다. 2026-09-20에 잡기 예고 A5(예고를 보고 걸어서
물러나면 피한다)와 처형 A6(앵커 ≥ 몸 반경 + 캡슐)·A7(후퇴 반경 ⇒ 후퇴 속도)이 더해졌다 — 정본 목록과
식은 [economy.md](economy.md), 에디터 없는 쌍둥이 검사는 `py -3 Tools/Balance/check_inequalities.py`.

검사에 걸리면 로그에 어느 줄이 깨졌는지 찍는다. 표에서 숫자 하나 잘못 고쳤을 때 조용히
밸런스가 망가지는 걸 막는 용도다.

멀티에서 호스트와 클라의 숫자가 같은지 접속할 때 대조하는 `CL9TuningHash`는 **설계만 있고 아직
미구현**이다 (2026-09-21 확인 — 소스에 없다).

**구조:** 정적 표는 각 머신이 로컬 레지스트리로 읽고 로드 검사를 돌린다 — GameState는
런타임 진행 상태만 나른다 ([../conventions.md](../conventions.md) § 5). 호스트·클라 값의
일치 검증(`CL9TuningHash`)은 위와 같이 미구현이다.

### 원칙 4 — 테이블에 행 추가하면 찍혀 나온다

아이템도 몬스터도 **틀을 먼저 만들고, 그다음엔 표에 데이터만 넣는다.** 계란 하나 만들려고
C++을 고치는 구조로 가지 않는다.

**유니티의 "아이템 전용 컴포넌트"는 언리얼에서도 된다.** `Instanced` 프로퍼티를 쓰면 표의 각
행에 기믹 목록을 두고, 에디터에서 `+`로 종류 고르고 각각 설정값을 넣을 수 있다. 스폰할 때
액터가 그 목록을 읽어서 붙인다. UX가 유니티 컴포넌트 추가와 거의 같다.

```cpp
UPROPERTY(EditAnywhere, Instanced)
TArray<TObjectPtr<UCL9Gimmick>> Gimmicks;   // 에디터에서 + 로 추가
```

**단, 판정에 영향을 주는 기믹은 값으로 표현한다.** 호스트가 판정하는 구조라 기믹이 액터에서
직접 상태를 바꾸면 클라와 갈라진다. 연출 기믹은 컴포넌트로, 판정 기믹은 표의 값으로 두고
호스트 판정 코드가 읽는다.

## ① 캐릭터

| 스텝 | 만드는 것 | 직접 해보는 것 |
|---|---|---|
| 1a | 평지 맵 + `ACL9Character`(캡슐) + 이동·시점 입력 + 폰 연결 | **걸어다니고 둘러본다** |
| 1b | 규칙 에셋 + 관계 검사 (이동 수치부터) | **에디터에서 속도 바꾸면 바로 반영된다** |
| 1c | `BP_CL9Character` + 임시 메시 | **몸이 보인다** |
| 1d | 달리기 — 커스텀 CMC + `FSavedMove` | **달려본다** (렉 없이) |
| 1e | 스태미나 (수치는 에셋에서) | **달리면 지치고, 지치면 못 달린다** |
| 1f | 2인 리슨 접속 | **둘이 만나서 부딪힌다** |

**1d가 제일 어렵다.** 속도를 바꾸는 순간 클라와 서버가 다르게 계산해서 캐릭터가 끌려다닌다.
`FSavedMove`에 달리기 상태를 실어야 하고 여기만 며칠 걸릴 수 있다.

**1e가 여기 있는 이유:** "하드락 없음" 보증이 스태미나 사이클에서 나온다. 스태미나가
없으면 무한 질주라 ②③ 내내 잘못된 감각으로 테스트하게 된다. 특히 ③ 닭 추격이 딴 게임이 된다.

몸 수치(속도·캡슐·스태미나)는 [data/character.md](data/character.md), 전역 규칙(소리·죽음·밤)은
[data/rules.md](data/rules.md)에 있다.

## ② 아이템

지금은 계란뿐이지만 **틀을 먼저 만든다.** 나중엔 표에 행만 추가하면 새 아이템이 나온다.

컬럼 정의는 [data/item/common.md](data/item/common.md)에 있다.

### 스텝

| 스텝 | 만드는 것 | 직접 해보는 것 |
|---|---|---|
| 2a | 아이템 테이블 + 스폰 틀 + 계란 1행 | **표에 행 추가하면 새 아이템이 바닥에 뜬다** |
| 2b | 줍기 | **주우면 상대 화면에서도 사라진다** |
| 2c | 놓기 | **놓으면 상대도 본다** |
| 2d | 던지기 + 깨짐 (`BreakSpeed` 읽어서) | **던져서 깬다 / 표에서 문턱 바꾸면 달라진다** |
| 2e | 기믹 층 — 아이템별 특수 동작 붙이기 | **표에서 기믹 추가하면 그 아이템만 달라진다** |
| 2f | 퀵슬롯(4칸, 2026-09-13 — 옛 "품 교체" 폐기) · 수레 · 항아리 · 반납 | **둘이 같이 나르고 반납한다** |

**주의:** 손에 뭘 들었는지 같은 "지금 상태"는 `ACL9PlayerState`가 가진다. 표는 "아이템이
뭔지"를 정하고, PlayerState는 "지금 누가 뭘 들고 있는지"를 가진다. 둘을 섞으면 안 된다.

## ③ 몬스터

닭 하나가 아니다. 아이템과 같은 구조로 간다.

컬럼 정의는 [data/monster/common.md](data/monster/common.md)에 있다.

### 스텝

| 스텝 | 만드는 것 | 직접 해보는 것 |
|---|---|---|
| 3a | 벽을 회색 상자로 세운다 (아래) | **보이지 않던 지형이 보인다** |
| 3b | 몬스터 테이블 + 스폰 틀 + 닭 1행 | **표에 행 추가하면 새 몬스터가 나온다** |
| 3c | 이동 · 순찰 | **닭이 돌아다니는 걸 본다** |
| 3d | 상태 기계 — 조사 · 추격 · 복귀 | **다가가면 쫓아온다 / 벽 뒤로 숨으면 놓친다** |
| 3e | 발각 게이지 + 잡힘 | **잡혀서 넘어진다** |
| 3f | 무리 경보 | **한 마리 깨우면 옆줄이 반응한다** |
| 3g | 기믹 층 + 거위 · 너구리 추가 | **표에 두 행 추가하니 새 몬스터가 산다** |

**3a를 왜 여기 넣었나 — 원칙 1과 "맵은 ⑤"가 충돌해서다.**
몬스터는 벽으로 시야가 막히고 벽을 피해 길을 찾는다. 벽이 안 보이면 **없는 걸 피해 다니는**
것처럼 보여서 맞는지 틀린지 판단이 안 된다. 좌표는 맵 생성 단계에서 나오므로, 회색 상자로
세우기만 한다. ⑤에서 진짜 벽으로 갈아끼운다.

## ④ 시스템

**루프 전체를 만든다.** *정차 → 주문서 → 목적지 선택 → 원정 → 귀환 → 요리 → 납품 →
구매* 여덟 칸 중 **목적지 선택(4g)만 남았다** (2026-09-07). 루프 설명은 [loop.md](loop.md).

| 스텝 | 만드는 것 | 직접 해보는 것 | 상태 |
|---|---|---|---|
| 4a | 죽음 · 관전 · 트럭 패드 회복 | **죽고 관전하고 살아난다 / 에셋에서 관전 대기 시간 바꾸면 반영된다** | 완료 |
| 4b | 일자 진행 곡선 | **일차가 오르면 몬스터가 늘어난다 / 곡선을 끌면 바로 달라진다** | 완료 |
| 4c | 주문서 — N개 중 M개 선택 | **주문을 골라서 받는다** | 완료 |
| 4d | 요리 — 열 상태변화 하나 | **조리대에 올리면 익고 더 두면 탄다** | 완료 (열원은 조리대 — 아래 번복) |
| 4e | 납품 — 주문 마감 판정 | **주문대로 내면 돈이 된다 / 표에서 가격 바꾸면 달라진다** | 완료 |
| 4f | 구매 — 장비(실물) | **이더를 내고 프라이팬을 산다** (물물교환 없음) | 완료 |
| 4g | 목적지 선택 (모듈 세트 교체 구조 — 아래) | **다른 목적지를 고를 수 있다** | **남음** |
| 4h | HUD · UI | **화면에 상태가 뜬다** | 완료 (설정 화면·키 리바인딩 2026-09-12 완료 — [settings.md](settings.md); 세션 UI는 남음) |
| 4i | 먹기 — 요리 타입 아이템의 스탯 효과 | **먹으면 잠깐 달라진다 / 표에서 효과 바꾸면 반영된다** | 완료 |

**정산도 들어갔다** (2026-09-07, ⑥에서 당겨 옴): 정산일에 기간 수입이 목표에 못 미치면 판이
끝나고 1일차로 다시 시작한다 ([../systems/balance.md](../systems/balance.md) 정산).

**4g가 제일 크다.** 맵은 목적지마다 다르다 — 2026-09-08 맵 재작성 이후 그 차이는 생성기 코드가
아니라 **그 스테이지의 모듈 세트**에서 나온다. 사이트 행의 `Theme`가 조각 표와 모듈 표를 한
이름으로 가리키고, **조각 표와 달리 모듈 표에는 공용 행 폴백이 없다** — 그래서 목적지를 하나
늘리려면 그 스테이지의 모듈이 통째로 한 벌 있어야 한다. **새 목적지 하나가 사실상 모듈 세트
하나다.** 그래서 4g는 "목적지를 고를 수 있는 구조"까지가 범위이고, 두 번째 목적지 자체는 별도다.

크기는 4g에서 새로 만들 것이 없다 — 사이트 행의 `BaseModuleCount`에 진행 표의 `SiteSizeCurve`가
곱해지는 구조가 이미 있다 ([data/site.md](data/site.md) · [data/progression.md](data/progression.md)).

**4d 요리는 미니게임이 아니다.** 하는 일은 원정과 같다 — 놓고, 기다리고, 집는다.
새로 생기는 시스템은 열 상태변화(날것 → 익음 → 탄 것) 하나뿐이다. 뒤집기나 불 조절을 넣지 않는다.
**열원은 프라이팬이 아니라 부엌(조리대)다** (2026-09-06 번복 — decisions.md · systems/cooking.md).
조리대 하나가 한 번에 하나를 익힌다. 프라이팬은 그냥 아이템이 됐다.

**4e 정산은 표를 읽는다.** 최종 가격 = `[ValueMin, ValueMax]` 굴림 × 목적지 배율 × 일자 배율.
가격을 바꾸려면 C++이 아니라 표를 고친다.

**4f 구매.** 파는 물건은 실물(`bPhysicalProp` = true) 장비다 — 표는
[data/equipment.md](data/equipment.md)에 있다.

**4h UI 구조 — 메인 위젯 하나만 뷰포트에 붙인다:**

```
WBP_Main            ← 뷰포트에 붙는 유일한 위젯
  ├ HUD 레이어 (짐 슬롯 등 — 항상 표시)
  ├ Layer_Screen    ← 전면 화면 (정산·로비·관전…) — UIManager가 UI 표를 읽어 배타로 연다
  └ Layer_Popup
새 UI는 WBP 제작 + UI 표에 행 추가다 (systems/ui_system.md — 2026-09-05 결정).
```

위젯마다 뷰포트에 직접 넣으면 z 순서·정리·전환이 전부 손으로 관리하는 일이 된다.

**HUD 방침:** 미니맵 표시는 개체별 값(`bShowOnMinimap` — systems/ui.md)으로 제어한다.
스태미나는 화면 흔들림과 HUD 바를 함께 쓴다 (2026-09-05 번복 — [data/rules.md](data/rules.md)).

**밤 수명주기(로비→밤→새벽)는 들어왔다** — ①~③ 사이에 지었고 PIE로 검증했다.
**세션(접속·재접속·Steam)은 아직 없다** — 남은 기술 기반은 이쪽이다.

## ⑤ 맵과 에셋 교체

| 스텝 | 만드는 것 | 직접 해보는 것 | 상태 |

### 5a 맵 배치 툴

에디터 창을 하나 만든다. **시드를 넣고 버튼을 누르면 그 시드의 맵이 레벨에 깔린다.**

```
[ 시드: 873 ]  [ 배치 ]  [ 지우기 ]
```

맵 생성기는 ②~④ 사이 어딘가에서 새로 짠다 — 시드에서 벽·상자·둥지·계단 좌표가 나오게
만든다. 툴은 그 좌표를 읽어서 액터를 놓는 일만 한다. 어떤 메시를 놓을지는 종류별 표에서 읽는다.

이러면 밤마다 새 맵이 나오는 게임 규칙과, 에디터에서 특정 맵을 열어보는 작업이 같은 코드를 쓴다.

**2026-09-06: 4c 다음에 당겨 구현했다** (systems/map.md 구현 상태, decisions.md). 창은 아직 없고 에디터 콘솔
`cl9.seed N`이 그 자리다.

**애니메이션(5e)이 뒤에 있는 이유는 스켈레톤이다.** 임시 메시로 만들면 산 캐릭터의 뼈대가
달라서 다시 만들게 된다. 단 UE5 마네킹 스켈레톤을 쓰는 에셋을 살 거면 앞당겨도 된다.

## ⑥ 마무리 정리

⑤까지 끝난 뒤: 유닛 테스트 · 2인 스모크 · 소스 스캔.

**스냅샷 테스트는 만들지 않는다.** 기준 CSV를 만들고 갱신 스크립트를 계속 맞춰주는 비용이,
빨간 채로 방치되어 진짜 실패를 가리는 위험보다 크다고 판단했다 — CCL8에서 실제로 그렇게
됐던 경험을 따른다. 개발자가 직접 실행해 보고 판단한다.

**단, 복제 등록 검사는 필요하다** — 스냅샷(값 대조)이 아니라 *"Replicated 필드를 더하고
`GetLifetimeReplicatedProps` 등록을 안 하면 조용히 동기화가 깨진다"*를 잡는 구조 검증이다.
성격이 달라서 예외로 둔다. ②에서 PlayerState 상태를 처음 지을 때 같이 만든다.

## 매 스텝 지켜야 하는 것

- **플레이어 판정 상태는 `ACL9PlayerState`에만, 공유 게임 상태는 `ACL9GameState`에만.**
  Character에 HP·짐 같은 판정 상태 필드를 두지 않는다 — 예외는 이동 예측에 들어가는 상태
  (달리기·스태미나·무게 감속)로, `FSavedMove`에 실어 CMC 경로에 둔다 (PlayerState는 표시
  미러 — conventions § 4 예외 · systems/character.md). 몬스터·아이템은 자기 상태를
  Replicated로 갖는다 (호스트에서만 수정 — [../conventions.md](../conventions.md) § 4).
- **`TakeDamage` · `UDamageType` 금지.** 데미지 파이프라인이 없는 게임이다.
  GAS는 금지가 아니라 현재 미사용 — 필요해지면 도입을 검토한다.
- 복제되는 액터는 `SetNetUpdateFrequency(20)`을 부른다 ([../conventions.md](../conventions.md) § 6).
- **C++에 에셋 경로를 안 쓴다.** 메시·머티리얼·애님은 BP나 표가 가진다.
- **정적 표는 각 머신의 로컬 레지스트리로, 런타임 상태는 GameState로.** 표를 통째로
  복제하지 않는다 — 접속 시 일치 검증(`CL9TuningHash`)은 설계만 있고 아직 미구현이다.
- **①~④는 평지에서** (③의 회색 상자 제외).

