# CL9 몬스터·배경 아트 제작 계획

작성·수정: 2026-10-11
상태: **몬스터 선정 철회 / 과거 제안 보존**.
사용자가 이전 몬스터 시안을 폐기하고 실제 컨셉아트에 근거해 글부터 다시 정하도록 요청했다.
아래 종 선정·제작 순서·8절 세션 시작문을 현재 제작 지시로 사용하지 않는다.
배경 제안도 이 몬스터 목록에 맞춰 자동 착수하지 않는다. 기존 게임 데이터·파일 삭제를 뜻하지 않는다.
후속 대화의 새 몬스터 아이디어는 아직 채택된 제작 기준이 아니다.

## 1. 방향과 선정 결과

**작고 둥근 도둑 요리사들이 기괴한 주인의 일터에서 재료를 훔쳐 돌아오는 B급 협동 공포 게임.**

기존 닭·거위·돼지·너구리는 현행 콘텐츠이자 행동 구현의 사례다. 새 디자인이 따라야 할 종 목록이 아니다.
몬스터는 실제 동물, 사물형 생물, 정체를 알 수 없는 크리처 모두 가능하다.
이번 시안은 **식재료와 작업 도구가 어긋나게 살아 있는 일터**를 선택한다.
플레이어의 동글한 외형과 몬스터의 과장된 부위를 대비시키고, 요리·운반과 자연스럽게 연결한다.

| 대상 | 선정 | 플레이 경험 |
|---|---|---|
| 첫 대표 몬스터 | **포대꾼** — 밀가루 포대 같은 둥근 생물 | 들키면 짧은 다리로 쫓아와 몸으로 덮침 |
| 경보 몬스터 | **종지기** — 큰 식당 호출벨이 머리인 경비 생물 | 때리기보다 깨우지 않고 지나가야 하는 위협 |
| 무거운 몬스터 | **냉장고지기** — 낡은 냉장고 같은 몸의 거대한 생물 | 느리지만 좁은 곳에서 만나면 돌아가야 함 |
| 뒤쪽 위협 | **빈앞치마** — 몸이 비어 있는 긴 앞치마와 조리용 장갑 | 재료를 보다가도 뒤를 돌아보게 만듦 |
| 첫 배경 | **폐점 후 달걀 선별장** | 익숙한 재료가 낯설게 느껴지는 짧은 실내 탐색 |
| 두 번째 배경 | **냉장 가공창고** | 큰 물건을 들고 묵직한 위협을 피하는 압박 |
| 세 번째 배경 | **심야 식재료 시장** | 진열대·점포·운반 통로를 오가며 재료를 모으는 탐색 |
| 공통 거점 | **낡고 따뜻한 푸드트럭** | 돌아가고 싶은 곳, 요리와 동료 사고가 생기는 곳 |
| 공통 외부 | **외딴 식재료 단지의 진입로** | 건물 외곽, 흙길·전신주·나무 띠·작업동 원경 |

양계장·돼지농장·대농장은 현행 검증 공간과 재사용 파츠의 출처로 남긴다.
새 배경은 기존 사이트 이름을 몰래 바꾸는 방식으로 적용하지 않는다.
새 Alias/Theme와 적용할 레벨은 후보 검수 뒤 별도 데이터 연결 작업으로 만든다.
현재 진행 중인 플레이어 후보 제작은 이어가며, 이 문서 작성만으로 그 세션의 범위를 바꾸지 않는다.

## 2. 행동과 외형을 분리해서 설계한다

확인 근거:
- [몬스터 공통 정의](../plan/data/monster/common.md): 감각·추격·경보·스토킹·처형 설정.
- [몬스터 시스템](../systems/monster.md): 공통 AI와 특수 기믹의 경계.
- `Source/CL9/Monsters/CL9Monster.cpp`: 데이터의 SkeletalMesh·AnimBP를 로드하고, ExecuteRadius로 사냥 상태를 선택함.
- `Source/CL9/Data/CL9MonsterDef.h`: IsExecutioner는 ExecuteRadius와 bExecuteOnCatch로 판정함.

**같은 행동 계열을 사용해도 외형·리그·동작·소리는 새롭게 만들 수 있다.**
반대로 메시 하나를 바꿨다고 새 능력이나 게임 연결이 자동으로 생기지는 않는다.

| 신규 후보 ID — 아직 런타임 행 아님 | 기존 경로를 이용할 기본 행동 | 추가하지 않을 능력 / 별도 개발이 필요한 확장 |
|---|---|---|
| sack_keeper | 순찰·조사·추격·예고·Catch | 포대 속으로 숨기, 밀가루 시야 차단, 분열은 별도 기믹 |
| bell_watcher | 경보·기상/수면 설정, CatchRadius=0 계열 | 실제 장비 전원을 끄거나 맵 전체를 봉쇄하는 기능은 별도 기믹 |
| cold_locker | 느린 추격·예고·bExecuteOnCatch 계열 | 재료를 냉각/보관, 플레이어를 내부 공간으로 이동, 냉기 지대는 별도 기믹 |
| hollow_apron | ExecuteRadius>0 계열의 스토킹·응시 반응·뒤쪽 처형 | 순간이동·투명화·벽 통과·동료 목소리 흉내는 별도 기믹 |

기존 종의 설정은 행동 시험의 출발점으로만 사용한다. 몸 크기와 애니메이션이 달라지므로 수치를 통째로 복사해서 완료 처리하지 않는다.
특히 감지 거리·몸 반경·예고·이동·공격 범위의 관계 검사와 실제 회피 가능성을 확인한다.
종별 제작 스크립트, AnimBP 분기, 사운드, 소켓, 처형의 플레이어 짝 동작도 새 후보에 맞춰 연결해야 한다.
기존 5종만 받는 제작 도구가 있다면 도구의 입력/내보내기 경로를 확장한다. 이것과 공통 AI의 재작성은 구분한다.

## 3. 공통 아트 규칙

- **형태:** 삼각면 저폴리와 큰 덩어리. 포대꾼은 둥근 주머니, 종지기는 돔과 긴 막대,
  냉장고지기는 낮고 넓은 사각, 빈앞치마는 긴 삼각형과 비어 있는 공간으로 구분한다.
- **색:** 재료와 캐릭터에는 눈에 띄는 큰 색 구역, 배경에는 넓은 중간 명도 면.
  Base Color를 검게 칠해 밤을 만들지 않는다.
- **공포:** 정지해 있던 것이 움직이거나, 코너에 몸 일부만 걸리고, 가까워지며 큰 실루엣이 드러나는 데서 만든다.
- **B급:** 도구가 제 역할을 지나치게 열심히 하는 듯한 진지함과 불편한 몸짓.
  붙인 눈 두 개나 웃긴 이름만으로 완성하지 않는다.
- **읽히는 위험:** 예고 자세와 공격 방향은 분명하다. 투명한 몸·발광 눈·과한 안개로 숨기지 않는다.
- **1인칭:** 손·소품·앞의 길이 동시에 읽혀야 한다. 멀리 보이는 실루엣과 가까이 보이는 표면을 둘 다 확인한다.
- **빛:** 손전등은 손과 렌즈 위치, 헤드램프는 시점 가까운 광원으로 읽힌다.
  화면 위에서 아래로 쏟아지는 별도 스포트라이트로 헤드램프를 설명하지 않는다.
- **스케일:** 기존 종의 신장은 새 후보의 정답이 아니다. 먼저 캡슐·문·천장 가이드와 함께 크기를 정하고 카드에 기록한다.
  후보 외형을 맞추기 위해 게임의 캡슐·문·카메라를 자동으로 변경하지 않는다.

## 4. 몬스터별 제작 카드

### M01. 포대꾼 — sack_keeper

**핵심 인상:** 묵직한 밀가루 포대가 자신이 창고 직원이라고 믿는 것 같다.

- 실루엣: 위를 묶은 큰 주머니, 아래쪽으로 처진 배, 짧은 두 다리, 팔 대신 굵은 천 묶음 두 개.
- 얼굴: 포대에 인쇄된 두 눈이 접힘 때문에 한쪽만 눌린 형태. 실제 눈동자와 인쇄선의 경계를 모호하게 한다.
- 색·표면: 밀가루색 천, 파란 인쇄 띠, 갈색 봉합선. 섬유 한 올 대신 넓은 접힘 3~5개로 표현한다.
- 움직임: 발이 먼저 출발하고 무거운 배가 뒤따른다. 예고 때 포대 입구가 조여지고 배를 뒤로 뺐다가 덮친다.
- 공격 표현: 팔 휘두르기보다 몸통과 천 묶음으로 밀어붙이는 Catch. 몸이 터지거나 플레이어를 삼키는 기능은 넣지 않는다.
- 코미디: 밀렸을 때 묶인 꼭지가 한 박자 늦게 흔들린다. 길을 돌아설 때 한 번 몸 전체를 옮겨야 한다.
- 만드는 순서: 정지 실루엣 → 걷기 → 예고/덮침 → 피격/밀침/사망.
- 필수 리그 기능: 몸통 눌림, 꼭지 흔들림, 좌우 다리와 천 팔 독립 제어. 본 수는 변형 시험 뒤 확정.
- 대표 화면: 진짜 포대 세 개 옆에서 혼자 발이 보이는 포대꾼, 앞에는 계란을 든 플레이어 손.
- 오인 방지: 첫 샘플부터 발·파란 띠·꼭지로 일반 포대와 구분할 수 있게 한다.
  완전한 위장 후 근접 즉사 같은 새 규칙은 넣지 않는다.

**첫 완성 대상.** 캐릭터와 크기·색이 맞고 어둠에서 읽히면 이 스타일을 나머지 종에 적용한다.

### M02. 종지기 — bell_watcher

**핵심 인상:** 손님을 부르는 식당 벨이 너무 큰 몸을 얻어 경비 일을 한다.

- 실루엣: 큰 돔형 금속 벨, 길고 가는 목대, 작은 둥근 몸통과 넓적한 두 발.
- 얼굴: 벨 아래쪽의 검은 가로 틈. 눈은 작은 부속 표현으로만 쓰고 벨 모양을 우선한다.
- 색·표면: 낡은 황동 머리, 탁한 적갈색 몸, 어두운 고무발. 반사로 주변 전체가 번쩍이지 않게 거칠기를 조절한다.
- 움직임: 평소 머리가 내려가 있고, 깨거나 경보를 준비할 때 목대가 세워지며 벨 안쪽 추가 드러난다.
- 경보 표현: 벨이 좌우로 크게 흔들린다. 소리와 표현 타이밍은 실제 경보 소비 경로에 연결한다.
- 코미디: 다리는 분주하지만 머리는 무거워 늦게 따라온다. 벨의 위엄과 작은 몸통이 어긋난다.
- 만드는 순서: 접힌/선 자세 → 이동 → 깨기 → 울기 → 피격/밀침/사망.
- 필수 리그 기능: 목대 기울기, 벨과 추의 독립 제어, 두 발. 추가 실제 물리 시뮬레이션은 필수가 아니다.
- 대표 화면: 좁은 출입문 옆에서 머리가 천천히 올라가고, 플레이어가 재료를 들고 돌아서는 장면.

기본 역할은 **경보**다. 벨이 손전등을 무력화하거나 문을 잠그는 기능으로 해석하지 않는다.

### M03. 냉장고지기 — cold_locker

**핵심 인상:** 오래된 냉장고 같은 생물이 내용물을 누구에게도 내주지 않는다.

- 실루엣: 넓고 두꺼운 사각 몸통, 낮은 두 발, 비대칭 문짝, 손잡이가 달린 한쪽 굵은 팔.
  평범한 냉장고에 팔다리를 얇게 붙이기보다 몸과 문이 한 덩어리로 보이게 한다.
- 얼굴: 냉장고 자석 같은 두 표식과 문틈. 문틈의 어둠이 큰 입을 연상시킨다.
- 색·표면: 바랜 민트 도장, 누런 손잡이, 갈색 고무 패킹, 적은 면적의 녹. 상시 파란 발광은 없다.
- 움직임: 발을 내디딜 때 몸이 조금 기울고, 회전은 느리게 무게를 옮긴다. 예고 때 문짝이 벌어지고 몸이 낮아진다.
- 주 공격: 문짝과 몸으로 정면에서 눌러 넘어뜨리는 짧은 처형 연출.
  피해자는 기존 앵커 공간에 남고, “냉장고 안으로 넣어 다른 공간에 가둠”은 구현하지 않는다.
- 코미디: 격한 움직임 뒤 장식 자석 하나가 늦게 흔들리는 정도. 웃음보다 막힌 길의 압박을 우선한다.
- 만드는 순서: 닫힌/예고 자세 → 걷기·회전 → 플레이어 짝 주 공격 → 피격/밀침/사망.
- 필수 리그 기능: 몸통 기울기, 문짝 힌지, 팔, 발. 문이 닿는 프레임과 피해자 접촉 위치를 같이 검수한다.
- 대표 화면: 냉장창고 복도 끝에서 문이 조금 열린 채 다가오며, 운반 상자를 든 손이 화면 아래를 가리는 장면.

움직이는 문짝의 시각 범위와 실제 몸/공격 판정 차이를 검수한다. 문을 통해 벽 너머 플레이어를 잡는 것처럼 보이면 실패다.

### M04. 빈앞치마 — hollow_apron

**핵심 인상:** 퇴근하지 않은 주방장의 앞치마만 혼자 돌아다닌다.

- 실루엣: 길쭉한 삼각 앞치마, 안쪽이 비어 있는 어깨와 허리, 큰 조리용 장갑, 가느다란 두 발.
  머리는 찌그러진 작은 체/소쿠리 형태다.
- 얼굴: 앞쪽에 얼굴이 있어야 할 자리는 비어 있다. 머리 방향은 손잡이·테두리의 비대칭으로 구분한다.
- 색·표면: 바랜 남색 앞치마, 크림색 장갑, 짙은 금속 테두리. 피 얼룩 대신 오래된 기름 자국과 큰 봉합면.
- 플레이어와 구분: 작은 플레이어는 속이 찬 둥근 덩어리, 이 괴물은 키가 길고 속이 빈 형태.
  같은 요리사 복장으로 동료와 혼동되게 만들지 않는다.
- 움직임: 앞으로 숙여 따라오고, 들키면 한 손을 든 어색한 자세로 멈춘다. 가까이 들키면 물러난다.
- 주 공격: 등 뒤에서 장갑 두 개가 어깨로 들어오는 처형. 오래 응시한 뒤 격분 추격은 기존 행동 계열을 이용한다.
- 만드는 순서: 정지 실루엣 → 낮은 이동 → 시선에 걸린 정지/후퇴 → 뒤쪽 주 공격 → 격분·피격/사망.
- 필수 리그 기능: 어깨·장갑·팔꿈치·발·앞치마 큰 변형. 천 시뮬레이션 없이 스킨 애니메이션으로 시작한다.
- 대표 화면: 재료 선반을 보다가 뒤돌면 점포 사이 모서리에 빈 앞치마가 멈춰 있고 한 장갑만 올라가 있다.

보이지 않는 벽 통과나 투명화를 능력으로 추가하지 않는다.
기존 스토킹의 시선·거리·시간 조건과 외형 연출을 맞춘다.

## 5. 배경과 몬스터를 묶는다

다음 ID는 제작용 후보 ID이며 현재 MapTable/Theme에 존재한다고 가정하지 않는다.

### E01. 폐점 후 달걀 선별장 — sorting_works

- **주인:** 포대꾼. 종지기가 일부 작업 구역의 경보 역할을 맡는다.
- **대표 이미지:** 넓은 노란 분류대, 계란 트레이, 목재 팔레트와 늘어선 포대, 한쪽만 켜진 작업등.
- **색:** 바랜 노랑·청회색 철제 프레임·크림색 재료·탁한 파란 표식.
- **공간:** 입구 검사실, 포장 작업실, 포대 창고, 선별대 옆 통로, 출고 대기 구역.
- **랜드마크:** 과하게 큰 달걀 등급판, 파란 문, 노란 선별 호퍼.
- **필수 소품:** 계란 트레이, 포대, 팔레트, 분류대, 호퍼, 운반 상자, 방 용도 그림판.
- **대표 컷:** 계란을 든 손 + 진짜 포대 사이 포대꾼 + 돌아갈 파란 문.
- **재사용:** 기존 양계장 벽·문·기둥·상자·포대·계란 에셋을 비교하고 맞는 부분을 활용한다.
- **새 기능 경계:** 컨베이어는 처음에는 정적인 소품이다. 물건 자동 운반이나 분류 미니게임을 만들지 않는다.

**처음 만들 검수 공간:** 문과 코너가 있는 짧은 통로 + 포장 작업대 + 포대꾼 한 마리.
전체 레벨을 만드는 대신 이 한 구역에서 플레이어·몬스터·재료가 함께 읽히는지 본다.

### E02. 냉장 가공창고 — cold_store

- **주인:** 냉장고지기. 깊은 선반 구역에는 빈앞치마가 등장하는 구성을 목표로 한다.
- **대표 이미지:** 흰 단열 벽, 두꺼운 창고 문, 차갑게 보이는 철제 선반, 드문 따뜻한 점검등.
- **색:** 회민트·탁한 흰색·짙은 고무색·안전 표식 주황. 전체 화면을 파란색으로 덮지 않는다.
- **공간:** 입고 검사대, 냉장 통로, 고기 보관 선반, 설비실, 반출 대기 구역.
- **랜드마크:** 큰 원형 온도계, 주황 번호 문, 굵은 배관과 작은 결로 창.
- **필수 소품:** 단열 벽 표면, 두꺼운 문 외형, 보관 선반, 운반 상자, 냉각기 외형, 배관, 온도계.
- **대표 컷:** 큰 짐을 든 손, 복도 끝 넓은 냉장고지기, 몸을 돌려 빠질 수 있는 옆 통로.
- **재사용:** 기존 지붕·바닥·구조·운반물 규격을 공유하며 돈사 대신 새로운 소재 묶음을 만든다.
- **새 기능 경계:** 저체온·미끄러짐·냉기 데미지·자동문 압사는 넣지 않는다. 차가움은 조명·재질·연출로 먼저 표현한다.

### E03. 심야 식재료 시장 — night_market

- **주인:** 종지기와 빈앞치마. 포대꾼은 창고 구역, 냉장고지기는 냉장 점포 쪽에 배치하는 구성을 목표로 한다.
- **대표 이미지:** 닫힌 셔터와 처진 천막, 낮은 진열대, 큰 점포 번호, 뒤쪽으로 이어지는 운반 통로.
- **색:** 바랜 빨강·청록·겨자색 점포 면을 구역별로 쓰고, 공용 구조는 짙은 중성색으로 통일한다.
- **공간:** 식재료 매대, 닫힌 점포, 공동 보관실, 하역장, 점포 뒤 연결 통로.
- **랜드마크:** 달걀 그림 간판, 큰 매달린 저울, 색이 다른 천막, 멀리 보이는 출고 표식.
- **필수 소품:** 매대, 셔터, 천막, 가격판, 큰 저울, 운반 상자, 후면 적재 선반.
- **대표 컷:** 재료를 집고 돌아보면 점포 사이에 빈앞치마가 멈춰 있고, 반대편에서 종지기가 머리를 세우는 장면.
- **재사용:** 선별장의 상자·팔레트, 냉장창고의 선반·문을 재사용하고 점포 외피로 장소를 바꾼다.
- **새 기능 경계:** 상인 NPC·흥정·새 상점 시스템은 없다. 시장은 원정 장소이고 구매·납품은 기존 게임 흐름을 따른다.

### E00. 푸드트럭과 단지 외부 — 공통

- 푸드트럭은 크림색+청록색 외장, 따뜻한 작업등, 손때 묻은 조리 공간으로 잡는다.
- 기존 food_truck_b의 출입구·실내 공간·계단을 기준으로 한다. 조리대·납품 창구의 현행 설치 여부를 먼저 확인한다.
- 단지 바깥은 흙길, 낮은 구릉과 나무 띠, 전신주, 창고 실루엣으로 구성한다.
- 보행 경계와 큰 스테이지 범위는 현행 기획을 유지하고, 원경은 실제 최대 플레이 바운드 밖에 정한다.
- 공유 원경 + 사이트별 시드 기반 근경을 사용한다. 입구·트럭 경로·내비게이션을 장식으로 막지 않는다.
- 자체 제작/보유 에셋 재사용을 기본으로 한다. Lvl_Flat은 검수용 상태를 유지하고 배경 비교 공간을 별도로 둔다.

## 7. 기술 계약과 납품

### 모델

- 신규 몬스터는 기존 동물 리그를 억지로 늘리지 않고 형태에 맞는 리그를 만든다.
  기존 애니메이션을 그대로 쓸 수 있다고 가정하지 않는다.
- 바닥 중심 root, 축·단위·실제 cm 크기, 소켓·재질·UV·변형을 제작 카드에 기록한다.
- 상태별 AnimBP와 클립 연결은 별도 작업이다. 첫 이동/공격 하나를 먼저 검수한 뒤 전체 클립으로 확대한다.
- 원본 .blend, 재실행 가능한 제작 스크립트, 중립광 정면/측면/3/4, 어두운 조명, 동작 미리보기를 납품한다.
- 생산 단계에 실제 FBX·텍스처·manifest를 추가한다. 존재하지 않는 출력 파일을 완료 목록에 적지 않는다.

신규 원본 후보 경로:
`ArtSource/monster/<sack_keeper|bell_watcher|cold_locker|hollow_apron>/candidates/01/`
이 경로와 ID는 목표이며 아직 만들어졌다는 뜻이 아니다.
기존 파일이 있으면 조사 후 이어 쓸지 결정하고, 다른 세션의 후보를 덮어쓰지 않는다.

### 배경

- 기존 500cm 셀과 실제 문·층고, Tile/Stretch 계약을 따른다. 테마의 분위기 때문에 통로 폭을 임의 변경하지 않는다.
- 각 파츠로 납품하고 Blender 조립 씬은 검수에 쓴다. 방 전체 FBX 하나를 생성기에 넣지 않는다.
- 새 Theme는 조각 표만 바꿔 끝내지 않고 모듈 표도 함께 준비한다.
- 벽·문·코너·계단 접점, 수레/큰 운반물/몬스터 통과, 시야·충돌·시드 일치를 게임에서 확인한다.
- 새 사이트 행/레벨은 기존 것을 보존한 상태에서 시험한다. 기존 stage JSON과 setup_stage 흐름을 확인한다.

신규 배경 후보는 `ArtSource/map/<sorting_works|cold_store|night_market>/` 아래 파츠별로 나눈다.
실제 UE 목적 경로는 프로젝트 명명 규격에 맞춰 임포트 작업에서 기록한다.

### 완료 단계

**제작됨 → Blender 검수됨 → UE 임포트 검수됨 → 게임 연결 검수됨**을 나누어 기록한다.
객체 수와 정점 수 검사는 외형 검수를 대신하지 않는다. 실제 렌더를 직접 보고 수정한다.
보지 못한 화면·실행하지 않은 AI·실패한 도구 연결은 그대로 미실행으로 기록한다.

다른 세션에 이 지시를 자동으로 보내거나 새 세션을 만드는 것은 이 문서 작성의 범위가 아니다.

## 9. 기존 문서와의 관계

이번 아트 후보는 기존 “특정 동물 농장” 표현에서 범위를 넓힌 **재료를 지키는 기괴한 주인의 일터**다.
기존 [게임 개요](../plan/overview.md)의 동물 설정과 기존 사이트 행은 현재 구현의 기록으로 남아 있다.
후보를 실제 본편 콘텐츠로 채택할 때 개요·개별 몬스터·사이트 명세·카탈로그를 함께 갱신한다.
이 문서 작성만으로 기존 동물을 삭제하거나 게임 세계관·데이터가 이미 교체됐다고 보고하지 않는다.

[기존 아트 방향](design-concept.md)의 소재를 바꿔도 유지하는 형태·색·빛 원칙은 이어간다.
이전 버전의 “닭→거위→돼지→너구리 필수 재디자인”과
“양계장→돼지농장→대농장으로 새 아트 한정”은 이번 선정으로 대체한다.
