## 현재 구현에 맞출 것 — 2026-09-10 소스 확인, 2026-09-21 갱신

- `CL9Item::LoadData`가 `Def->Radius / Mesh->GetBounds().SphereRadius`로 메시 전체를 균등 배율 조정한다.
  **Blender에서 30cm로 만들었다고 게임에서도 30cm인 것은 아니다.** 원본 cm, 바운드 반경,
  적용 배율, 액터에서 보이는 최종 치수를 카드에 적는다. 임시 보정 코드지만 지금은 적용되고 있다.
- 피벗은 기본적으로 **물체 중심**, 메시 바운드 중심도 원점에 맞춘다. 손잡이가 길면 바운드와
  자동 배율이 달라진다. 작업용 가이드·보이지 않는 큰 메시를 내보내기에 포함하지 않는다.
- 충돌: 보통 아이템은 액터 `SphereComponent`(행 `Radius`)가 몸체고 메시 충돌은 꺼진다 — UCX 를 만들어도 쓰이지 않는다.
  예외는 행 `bMeshIsBody`(2026-09-13, 지금은 수레만): 임포트한 UCX 심플 콜리전이 곧 물리 몸체고 `Radius` 자동 배율도 없다
  (`Source/CL9/Data/CL9ItemDef.h` `bMeshIsBody`, [cart.md](cart.md) UCX 표). 납작한 요리·긴 손전등은 게임에서 떠 보임/회전을 검수한다.
- 부착: 든 아이템은 소지자 **전신 메시의 `HandGrip_R` 소켓**(없으면 `hand_r` 뼈)에 붙고, 행 `GripOffset`(cm)·`GripRotation` 이
  손잡이를 손바닥에 맞춘다(2026-09-12, `CL9ItemDef.h` Carry 절·`Source/CL9/Items/CL9Item.cpp`). 소유자 화면에서는 메시 컴포넌트만
  1인칭 팔로 옮겨 그린다. 값은 손으로 맞추지 않고 `Tools/Blender/measure_item_grip.py` 로 1인칭 자세에서 역산한다(028·031 증거).
  Blender 의 `Grip` 마커는 제작 참고일 뿐 코드가 읽는 것은 행 값이다.
- 머리 장비는 현재 카메라에 붙는다. 시야 가림과 타인 화면의 위치를 별도로 확인한다.

## 상태와 재질

| 대상 | 제작 대상 | 엔진 연결 주의 |
|---|---|---|
| 계란 | 날것 / 익음 / 탐 | `egg`, `egg+cooked`, `egg+burnt` 행. 익은 모습은 카드에서 결정 |
| 균열 | 금이 읽히는 표현 | 기획상 상태는 있으나 새 텍스처/메시 전환 소비처 확인 필요 |
| 파손 | 선택적 조각·효과 | 파편 메시 생성만으로 파손 연출이 연결되지는 않음 |
| 고기 | 날것 / 익음 / 탐 | 실제 요리 체인과 일치시킴 |
| 손전등·헤드램프 | 본체 / 렌즈 / 발광 영역 | 실제 광원과 토글은 엔진 담당 |
| 수레 | 바구니·손잡이·바퀴 형상 | 물리 몸체(`bMeshIsBody`, UCX 9)·앞에서 밀기(2026-09-13). 바퀴 회전 표현은 연결 필요 |

계란의 기획 `Radius=21cm`(정본 `docs/plan/data/item/egg.md`, 2026-09-21 확인)는 현실 계란 크기가 아닌 게임 판정 기준이다.
상태 변형은 같은 원점·방향을 쓰고, 바운드가 달라지면 자동 배율 변화까지 검수한다.
태운 상태는 색만 미세하게 바꾸지 말고 손전등 아래에서 즉시 구분되게 만든다.

## 검수

바닥에서 줍기 → 퀵슬롯 전환(휠·1~4) → 놓기(G)·던지기(달리기+G) → 수레 적재 → 조리대 → 납품을 적용 가능한 항목에 대해 확인한다.
1인칭에서 손과 메시가 과하게 겹치지 않고 화면을 가리지 않아야 한다. 반납 항아리·조리대처럼
고정 상호작용 액터인 소품은 제작 카드에 소비 클래스를 명시하고 아이템 자동 배율 규칙을 그대로 적용하지 않는다.
