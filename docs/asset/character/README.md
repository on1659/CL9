# 플레이어 캐릭터 제작 규격

기획: [캐릭터](../../plan/data/character.md), 기술: [애니메이션](../../systems/animation.md).
1인칭 게임이므로 **동료에게 보이는 풀바디**와 **자기 화면의 팔**을 별도로 제작·검수한다.

## 몸 크기와 리그

- 현재 기준 캡슐 반경 **39cm**, 반높이 **90cm**(전체 180cm), 눈높이 **156cm**.
  캡슐은 시각 모델의 키를 강제로 180cm로 정한다는 뜻은 아니다. 외형을 캡슐과 시점에 맞춰 검수한다.
  외형 때문에 판정 캡슐·눈높이를 변경하지 않는다.
- 풀바디 원점은 바닥 중앙. 현재 `CL9Character`는 메시 Z를 `-CapsuleHalfHeight`, 회전을
  Yaw **-90도**로 둔다. **몬스터용 +X 정면/보정 0 규칙을 그대로 적용하지 않는다.**
- 기존 UE5 Manny/Quinn 계열을 재사용하는 방향이 기본이다. 원본 Skeleton의 뼈 이름·부모·
  레스트 포즈·스케일을 유지한다. 이름만 같다고 호환이라고 하지 않는다.
- 기존 리그를 가져오기 어렵다면 독립 리그 제작/리타깃 비용과 연결 필요를 카드에 명시한다.
  임의로 다시 만든 “비슷한 마네킹”을 호환 모델로 납품하지 않는다.
- 슬롯 색이 구분되는 옷 영역/마스크를 준비한다. `TintColor`를 받아 변경할 머티리얼 연결은
  실제 소비 경로를 확인한다. 색 차이를 보이게 하려고 캐릭터 전체를 발광시키지 않는다.

## 1인칭 팔

팔 전용 메시와 AnimBP는 `ArmsMesh`/`ArmsAnimBP`, 풀바디는 `SkeletalMesh`/`Skeleton`/`AnimBP`에
연결한다. 현재 캐릭터 데이터/코드에 팔 필드가 있으므로 과거 애니메이션 문서의 “추가 필요”와 구분한다.
자기 팔/타인 몸의 가시성은 엔진이 담당한다. 팔은 기본 FPP 리그와 카메라를 먼저 기준으로 삼는다.

손등·손가락·손목은 가까이 보인다. 계란·손전등·큰 운반물에서 그립이 무너지지 않게 만든다.
팔 절단면이 카메라에 보이지 않아야 한다. 단일 Blender 렌더 대신 실제 UE 카메라/FOV에서 확인한다.
손 소켓은 제작 참고일 수 있지만 현재 아이템은 캡슐에 붙는다. 손 부착 전환 구현을 가정하지 않는다.

## 동작 목록 — 해당 게임 상태가 소비하는 것부터

| 구분 | 클립/포즈 | 규칙 |
|---|---|---|
| 풀바디 | Idle, Walk, Run, Jump/Fall/Land | 기존 로코모션 재사용 우선, in-place |
| 풀바디 | CarryPose | 손/품·짐 종류를 읽는 연결 여부 확인 |
| 풀바디 | HitReact, Knockdown/GetUp, Death | 실제 비틀/넘어짐 시간과 상태 전이에 맞춤 |
| 팔 | Idle, HoldEgg, HoldFlashlight, CarryLarge | 1인칭 화면 가림·그립 검수 |
| 팔 | Pickup, Throw, Swap, Use/Eat | 필요한 동작부터. 없던 게임 조작을 추가하지 않음 |

모든 행이 이미 AnimBP에 연결됐다는 뜻은 아니다. 제작 카드에 필요한 클립과 소비 상태를 매핑한다.
품 교체·경직 시간은 현재 데이터 기준으로 맞추고, 클립의 Notify로 재고·HP·아이템 상태를 바꾸지 않는다.

## 검수

1인칭 팔과 동료 화면을 모두 확인한다. 위/아래 보기, 달리기, 점프, 큰 짐 운반, 던지기,
넘어짐에서 손목 뒤집힘·의복 관통·카메라 노출·바닥 관통을 확인한다. 슬롯 색은 같은 외형 4종으로 비교한다.
기존 애니메이션 한 개의 호환 검수가 끝나기 전에는 전체 동작을 새 리그로 제작하지 않는다.

## 첫 왕복에서 확인한 내보내기 — 024

farmer_a의 실제 Manny Simple은89뼈다. Blender FBX import는 root를 armature 오브젝트로 분리해
88개 bone과 root 오브젝트로 표현했다. 이 구조를 유지한 채 FBX root 이름을 `root`로 내보낸다.
원본은 Metric1m/오브젝트 배율1, 내보내기 전용 복사본만 기하·뼈 좌표100배/Unit Scale0.01로 변환한다.
FBX `-Y/+Z`, `FBX_SCALE_ALL`, leaf bones 없음, deform-only=false,
UE `force_front_x_axis=false`/배율1/기존 Skeleton ref pose 갱신=false.
일반 m FBX는 UE root scale100이 되어 실패했다. cm 복사본은 모든89뼈의 위치/회전/배율/부모와
기존 Walk를 검수했다. 애니메이션을 가진 원본에 일괄 배율 적용하지 않는다.

색의 경우 `has_vertex_colors=true`만으로 렌더 통과라고 하지 않는다. 실제 pawn에서 하얀 장화/장갑을
확인했고, farmer_a는18색256×8 PNG 팔레트와 UV1 샘플로 해결했다. UV0는 별도 unwrap으로 유지한다.
다른 VertexColor 에셋이 같은 문제인지 실제 화면에서 확인하기 전까지 정상/동일 원인으로 단정하지 않는다.
