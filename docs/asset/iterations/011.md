# 011 — 양계장 운반 수레

Blender MCP로 철제 프레임/판재 바닥/열린 난간/앞 손잡이/고무 바퀴4개의 수레를 제작했다.
153.40×115.20×105.40cm, 5,532 tris/2,968 vertices, UV0/2재질.
원본 `ArtSource/item/cart_a/cart_a.blend`, FBX/재질 값/manifest와 최종 중립·야간·손전등 렌더 저장.
처음 잘린 미리보기는 카메라 초점/프레이밍을 조정하여 전체가 보이게 수정 후 직접 확인했다.
적재 바닥/손잡이/바퀴 중심을 REF Empty와 manifest에 보존했고 FBX에서는 제외했다.

## 검수 증거

- [UE 임포트](../evidence/011-cart-imports.json): UE5.8.1 `/Game/CL9Art/Items/CartA`,
  치수 오차 <0.000017cm, 두 재질 슬롯/LOD3 생성. Native MCP 에셋 이미지 확인.
  현재 Radius60 자동 배율0.59485012, 표시91.25×68.53×62.70cm.
- 실제 cart 행에 임시 연결, Native Unreal MCP로 Lvl_Flat PIE 시작/종료.
  정밀 샘플과 실제 Server_PickPlace RPC는 기존 에디터 Python API를 사용했다.
- 첫 검수는 적재/꺼내기 성공, 견인 응답 실패. 레벨의 초기 카트 Z40cm/반경60cm라
  충돌 구체가 지면 아래20cm 들어간 상태였다. 실패 시도는 `011-cart-use-attempt-*.json`에 보존했다.
- 재검수는 **PIE에서만** 시작 카트를 Z62cm로 올리고 동일 상호작용을 실행했다.
  [결과](../evidence/011-cart-use.json): 1월드 계란 싣기/꺼내기, 연결 순간 수평 이동 없음,
  캐릭터 위치 보조 이동에 따른 견인 반응, 해제 후 따라오지 않음 확인.
  캐릭터를 제어된 위치로 옮긴 테스트이므로 실제 걷기 입력/2인/견인 시각 완료 주장이 아니다.
- [원래 데이터 참조](../evidence/011-cart-data-backup.json)로 검수 후 복구했다.
  레벨의 시작 위치/게임 수치/C++/PIE 인원 설정은 저장·변경하지 않았다.

## 남은 결함과 범위

- **적재 바닥 불일치:** 원점 기준 실제 슬롯(-23,-26,81)cm에서 계란이 부착되며,
  메시의 적재 바닥보다 계란 하단이65.948cm 높다. 현재 코드가 적재 앵커를 읽지 않는다.
- **바닥 표현:** 메시와 구체 하단의 간격은28.651cm. 초기 배치 지면 침투 보정만으로 해결되지 않는다.
- **견인 수직 이동:** 재검수에서 카트 Z가60.697→117.204cm로 올라갔다. 원인 미확정/미통과.
  수평 견인 응답 검사 통과를 전체 이동/충돌 통과로 확대하지 않는다.
- 현재 엔진은 Static Mesh 한 개를 소비하며 바퀴 회전/조향 표현을 갱신하지 않는다.
  현 연결 리그/클립 N/A 근거를 보존하되, 회전/손잡이 표현 의존성은 남긴다.
- 실제 그립/이동 화면, 연속 적재/반납, 2인 표현, LOD 시각/성능과 최종 연결 미완료.

필수45개/최종 완료0개 유지. 다음 제작은 standing_lamp. 전체 맵 배치·조립은 제외.
