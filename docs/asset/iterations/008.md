Blender MCP로 날것·익음·탐 3개 Static Mesh를 제작했다. 같은 원점/바운드,
67.10×34.60×34.00cm, 각 2,992 tris/1,506 vertices, VertexColor 1재질/UV0.
외부 자산 없이 만든 살 덩어리/돌출 뼈와 상태별 지방·구이·탄 표면 무늬다.
원본 `ArtSource/item/meat_states/meat_states.blend`, 각 FBX, manifest를 저장했다.
중립·야간·손전등 비교 렌더를 직접 확인했다. 리그/클립은 정적 상태 교체이므로 N/A.

## UE 증거와 미통과 항목

- [임포트](../evidence/008-meat-imports.json): UE5.8.1, `/Game/CL9Art/Items/MeatStates`.
  세 상태 모두 치수 오차 <0.000001cm, 3단계 LOD 생성, 중심 바운드와 동일 SphereRadius 확인.
  LOD의 실제 화면 전환/성능은 아직 미검수. MCP 에셋 이미지에서 버텍스 색 무늬를 확인했다.
- 실제 Radius30 배율0.89063455, 표시 크기 약59.76×30.82×30.28cm.
- 실제 meat 3행을 임시 연결하고 Native Unreal MCP로 PIE 시작/종료했다.
  정밀 샘플링은 에디터 Python API로 수행했다. 현재 설정은 **1개 PIE 월드**였으므로 2인 통과가 아니다.
- [PIE 수치](../evidence/008-meat-pie.json): 기존 레벨의 고기 3개와 치트 스폰 3개 모두
  해당 상태의 새 메시/배율을 사용한다. 기존 3개는 메시 하단 Z≈14.36cm,
  충돌 구체 하단 Z≈-0.50cm. **메시와 충돌 하단 차이14.859cm로 바닥 표현 미통과**.
  속도는 0이 아니므로 완전 정지/물리 안정성을 통과했다고 주장하지 않는다.
- 치트 스폰 뒤 배치 보조 코드에서 API 오류가 발생하여 새 3개는 서로 쌓인 상태로 측정됐다.
  보조 코드의 get_player_pawn 호출은 수정했지만 그 수정 후 별도 배치 검수는 아직 하지 않았다.
  Native CaptureViewport는 에디터 충돌선만 보여 PIE 시각 증거로 쓰지 않는다.
- [원래 행 참조](../evidence/008-meat-data-backup.json)를 보존하고 테스트 후 세 원래 메시로 복구했다.
  새 art 임포트는 남아 있다. C++/밸런스/레벨 배치를 바꾸지 않았다.

현재 최종 연결, 바닥/운반/요리 전환, 2인 표현, LOD 시각/성능은 미완료다.
구체 충돌과 다른 종횡비의 아이템 간 바닥 차이는 소비 경로 의존성으로 남긴다.
이 문제를 숨기려고 피벗을 어긋나게 하거나 모델을 구체로 대체하지 않는다.
