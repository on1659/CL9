# 022 — 트럭 회복 패드와 장비 패널

Blender MCP로 개별 패드/패널을 제작했다. [제작 카드](../map/truck_parts.md),
원본 `ArtSource/map/truck_parts/pad/pad.blend`, `panel/panel.blend`.
패드400×400×20cm/784 tris/504 vertices, 패널15×80×120cm/868 tris/474 vertices.
각각 바닥 피벗/+X 정면/UV0/3상수 재질/UCX1. 정적 파츠로 리그/클립 N/A.
패드는 네 방향 경사와 회복 표시, 패널은 구매 그림/보호 테두리/고정 버튼이며 외부 그림 의존성이 없다.

- 두 원본 각각 중립·야간·손전등6렌더와 Native UE 에셋 이미지2개 확인.
- [패드 임포트](../evidence/022-pad-imports.json), [패널 임포트](../evidence/022-panel-imports.json):
  UE5.8.1 치수 오차<0.00007cm/UCX1/LOD3. 두 FBX 해시가 UE 보고서와 일치.
- [기존 소비처](../evidence/022-truck-consumers.json): 패드4/4/.2 배율이 HealZone 상대Z도 줄인다.
  새 자연 치수 원본은 배율1/바닥 배치로 검수했다. 회복 판정400×400×240cm와5초 시간은 변경하지 않았다.
- [1월드 실제 PIE](../evidence/022-truck-pie.json): `cl9.damage 1`로HP3→2,
  패드 밖5초 이상 HP2 유지. 안3초→밖→다시 안3초에서도HP2,
  재진입 후5초 이상 머무른 다음HP3 확인. 전체 시간은 가속하지 않았다.
  입·출입은 검수용 위치 설정이며 실제 키보드 이동/경사 걷기나2인 복제는 검수하지 않았다.
- 실제 TruckPanel BP를 조준하면 장비 구매 안내/포커스 확인, Server_PickPlace RPC 후
  **해당 PIE GameInstance의 UIManager에서 IsOpen(Shop)=true/GetOpenScreen=Shop** 확인.
  이어 화면을 닫았다. 구매/비용 차감/상점 화면의 렌더·레이아웃 검수는 하지 않았다.
- Python에는 SubsystemBlueprintLibrary/WidgetBlueprintLibrary가 노출되지 않아 실행 전 조회가 실패했다.
  실재 API를 조회하고 ObjectIterator(CL9UIManager)에서 해당 GameInstance 소유자만 선택해 검사했다.
  도구 준비 실패 중에는 회복/상점 동작을 실행하지 않았다. 현재 스크립트에는 정상 경로만 남았다.
- 최종 HealZone 중심Z1120/400×400×240cm, 패드·패널 바닥Z1000.
  패드 구체 지지 오차<0.000001cm/속도0. 패드 평면/충돌 상면 차이 최대1mm를 기록했다.
- [정리](../evidence/022-truck-fixtures.json): 검수4액터만 제거/원래29액터 목록 확인,
  검수 맵만 저장 후 Lvl_Flat 복귀/PIE 종료. 원래 BP/사용자 레벨/데이터/게임 코드 변경 없음.

영구 연결/기존 배율·위치 보정/회복 경계·경사 실제 이동/2인/LOD·성능은 미완료.
