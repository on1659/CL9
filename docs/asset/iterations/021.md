Blender MCP로 법랑/푸른 판/금속 받침의 접수 창구를 제작했다. 배송 상자·확인 표시와 측면 서류판으로
조리대/녹색 반납 항아리와 구별한다. [제작 카드](../map/delivery_counter.md),
원본 `ArtSource/map/delivery_counter/delivery_counter.blend`.
100×100×100cm/1,552 tris/854 vertices/UV0/3상수 재질/UCX6/바닥 피벗/+X 정면.
정적 시설이고 재고는 데이터로 관리하므로 리그/클립 N/A. 외부 이미지/글꼴 의존성 없음.

- [실제 소비처](../evidence/021-counter-consumer.json): Lvl_Flat의100cm 기본 큐브/중심Z50cm.
  새 바닥 피벗 모델을 영구 연결할 때 기존 인스턴스 위치도 보정해야 한다.
- 중립·야간·손전등3렌더와 Native Unreal MCP 에셋 이미지 확인.
- [UE5.8.1 임포트](../evidence/021-counter-imports.json): 치수 오차<0.00002cm/UCX6/LOD3.
  최종 원본 FBX와 UE 임포트 해시 일치. LOD 전환·성능까지 검수한 것은 아니다.
- [1월드 PIE](../evidence/021-counter-pie.json): 실제 BP_CL9Counter에 새 메시 적용,
  실제 계란을 E에 해당하는 RPC로 줍기→납품→빈손 판매. 납품 후 손 비움/계란 액터 제거,
  판매 가능한 창구 포커스·안내 유지, 판매 후 자금/기간 수입 증가와 안내·포커스 해제 확인.
  추가 빈손 상호작용 후 자금이 다시 증가하지 않는 것도 확인했다.
- Stock은 protected라 Python에서 읽을 수 없었다. 실제 동작을 시작하기 전 확인 단계에서 중단됐고,
  공개된 포커스/프롬프트·액터 제거·자금 결과를 관찰하는 검사로 수정해 같은 PIE에서 실행했다.
  **내부 재고 배열의 직접 비교/주문 완납/수레 납품을 검수한 것으로 쓰지 않는다.**
- 100cm 치수와 바닥Z1000cm, 몸통 캡슐 차단, 상판 검수 구체 간격<0.000001cm/속도0 확인.
  플레이어 위치와 조준은 검수용 설정이며 실제 이동 입력이나 손 시각/2인 테스트는 아니다.
- [정리](../evidence/021-counter-fixtures.json): 검수4액터만 제거/원래29액터 목록 확인,
  검수 맵만 저장 후 Lvl_Flat 복귀/PIE 종료. 원래 BP/레벨/데이터/C++ 변경 없음.
