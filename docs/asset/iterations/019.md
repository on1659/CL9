# 019 — 반납 항아리

Blender MCP로 열린 입구·두께 있는 옹기 몸통·고정 손잡이·반납 그림 표식을 제작했다.
[제작 카드](../map/return_jar.md), 원본 `ArtSource/map/return_jar/return_jar.blend`.
94.4×99.9409×100cm/1,980 tris/1,046 vertices/UV0/3상수 재질/UCX17/바닥 중앙 피벗.
현재 반납은 아이템 소모이며 가동부가 없어 리그·클립 N/A. 입구 최소 내부 지름58cm.

- 중립·야간·손전등3렌더와 Native Unreal MCP 에셋 이미지를 확인했다.
  유약과 흙 몸체를 큰 색면으로 구분하고, 앞면 반납 그림에는 별도 글꼴/이미지를 쓰지 않았다.
- `static_meshkit.py`에 선택적 볼록 충돌 정점 묶음 지원을 추가했다. 기본 박스 경로는 유지된다.
  벽16구역과 바닥1개로 입구를 비웠다. 구역별 볼록 근사는 곡선 안쪽보다 보수적이다.
- [실제 소비처](../evidence/019-jar-consumer.json): Lvl_Flat의 BP_CL9Jar는100cm 기본 원통,
  Z49.5cm에 놓여 있다. 새 원본을 이 인스턴스에 교체할 때 바닥 피벗 위치 보정이 필요하다.
  `PointToWorld`의 생성 지점은 층 바닥Z이므로 새 원본의 바닥 피벗과 맞는다.
- [UE5.8.1 임포트](../evidence/019-jar-imports.json): 치수 오차<0.000001cm, UCX17/LOD3.
  원본 FBX 해시와 임포트 보고서 해시 일치. 실제 LOD 전환·성능은 미검수.
- [1월드 PIE](../evidence/019-jar-pie.json): 격리된 실제 BP_CL9Jar 인스턴스에 새 메시 적용,
  실제 계란 E에 해당하는 Server_PickPlace RPC로 줍기→반납. 손 비움/계란 액터 제거/
  ReturnedItems0→1 및 egg/None 기록을 확인했다. 플레이어 위치·조준은 검수용으로 설정했다.
  몸통 캡슐 차단/입구 중심 비차단, 반지름10cm 물리 구체 내부 바닥 간격-0.000070cm/속도0.
  구체는 충돌 검사용이고 실제 아이템 물리 투입 기능을 검수한 것은 아니다.
- 준비 때 미지원 empty_override_materials를 override_materials 속성으로 교체했다.
  생성했던2검수 액터를 정리하고 준비를 다시 실행했다(`019-jar-fixtures-setup-api-fix.json`).
  반납 검수의 unreal.is_valid 호출도 미지원이라 실제 액터 목록 부재로 수정했다.
  성공한 줍기/반납은 반복하지 않고 같은 PIE에서 확인 후 나머지 충돌 검사를 마쳤다.
  최초 결과는 `019-jar-pie-before-harness-fix.json`에 보존되어 있다.
- [최종 정리](../evidence/019-jar-fixtures.json): 검수4액터 제거/원래29액터 목록 일치,
  검수 맵만 저장하고 Lvl_Flat 복귀. 원래 BP 기본값/레벨/게임 데이터·코드 변경 없음.

영구 BP 연결/기존 인스턴스 위치 보정/수레 반납/2인/LOD·성능은 미완료다.
전체 필수45행 최종 완료0개, 조립 참고17행 제외 유지. 다음은 조리대:
실제 몸체 바운드가 HeatZone과 GetTopLocation을 결정하므로 상판 위에 돌출 장식을 두지 않는다.
