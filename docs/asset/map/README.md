# 맵 조각과 소품 제작 규격

정본: [조각 배치](../../systems/asset-swap.md), [모듈](../../plan/data/module.md),
[사이트](../../plan/data/site.md). **Blender에서는 조립용 메시를 만들고, 방 배치는 모듈 표가 정한다.**
완성된 방 통째를 FBX로 내보내서 생성기에 넣는 방식은 현재 계약이 아니다.

2026-09-11 사용자 재확인: 이 제작 작업은 **맵에 들어가는 개별 파츠 제작**에 집중한다.
파츠를 붙여 실제 맵으로 구성하는 작업은 Unreal에서 한다. Blender의 조립 샘플은 치수·연결면·
분위기 검사용이며 완성 레벨 납품물이 아니다. 이 작업을 맵 생성기 개편이나 방 배치 설계로 확대하지 않는다.
토큰 사용을 줄이기 위해 파츠별 제작 스크립트를 재사용하고, 대표 연결부만 작은 UE 테스트 공간에서 검수한다.
이미 통과한 검수는 원본 변경이나 새로운 결함이 있을 때만 반복한다.

## 격자와 치수

- 양계장 **CellSize=500cm**. 벽 길이는 500cm의 약수에 맞춘다. 폭·두께·높이는 각각 측정한다.
- 현재 팩 벽 실측 예시는 **500×40×400cm**. 이는 기존 조각의 크기이며 모든 방의 천장 높이가 아니다.
- 층 높이는 최신 모듈 문서의 실측 조합을 따른다(2026-09-10 문서 예시 610cm).
  과거의 “단층”이나 630cm 벽 높이를 전체 에셋에 고정 적용하지 않는다.
- 문 폭은 현재 조각 바운드에서 읽는다. 옛 통로 255cm나 문 250cm를 임의로 새 문 규격으로 확정하지 않는다.
  새 문을 바꾸면 생성기 개구부에도 영향이 있으므로 실제 데이터·캐릭터 통과를 같이 확인한다.
- 신규 벽은 로컬 X=길이, Y=두께, Z=높이, 피벗은 바닥 중앙. 배치 코드는 바운드 중심을 보정하지만
  신규 제작물끼리는 피벗을 통일한다. 회전하는 문짝은 별도 힌지 원점을 쓰고 액터에서 검수한다.

## 타일링 계약

`Tile`: 길이는 장수에 맞춰 소폭 보정, 두께는 자연 두께, 높이는 여러 단 중 맨 위 단이 잔여 높이를 받는다.
`Stretch`: 바닥·천장 등 늘어나는 형태에 사용한다. 베이크 무늬 대신 재질 타일링이 적절한지 확인한다.

016 실측 보완: 현재 `CL9SiteMap.cpp`의 일반 Stretch 분기는 바운드 자동 보정이 아니라
`Size/100` 배율과 셀 중심을 사용한다. 해당 경로용 납품은 **100cm 큐브 바운드/중심 피벗**이어야 한다.
편집용 자연 치수 모델과 구분해서 내보내고, 복원 배율로 형상·충돌을 확인한다.
[천장 납품과 검수](henhouse_structure.md)는 자연500×500×30cm + Stretch100 변형을 제공한다.
공용 box를 전역 교체하기 전에 종류별 역할 분리를 확인한다. Tile·FlapIn 계약과 혼동하지 않는다.
연결면에서 틈/돌출이 없어야 하고, 0/90/180/270도 회전과 2장·4장 반복으로 검사한다.

돌출 장식 때문에 바운드가 실제 연결 폭보다 커지면 틈이 생긴다. 반복 구조물과 장식을 분리한다.
색/낡음 변형 A/B/C는 같은 규격과 연결면을 공유한다. 부서진 벽·끝단·문 구멍은 같은 변형 풀에 섞지 않는다.

| 역할 | 납품 형태 | 주의 |
|---|---|---|
| `wall` | 실내 반복 벽 | 아래쪽 비율과 끝단 이음매 유지 |
| `fence` | 반복 울타리 | 틈이 보여도 게임에서 통과/시야가 같은 규칙인지 확인 |
| `door` | 문짝 | 문틀과 구분. 문틀 개구부를 충돌로 채우지 않음 |
| `box` | 늘릴 바닥/천장 조각 | 판 두께와 층 높이에 영향 |
| 소품 | 건초·사료통·상자·둥지 등 | 방 껍데기와 분리. PropSets 연결 여부 확인 |

125cm·250cm 짧은 벽은 현재 눌리는 벽 토막을 개선할 **제작 후보**다. 메시만 만들면 생성기가
자동 선택하는 기능은 없다. 역할/seg kind 연결을 먼저 정의해야 한다.
층간 계단은 현재 `floor` 조각을 디딤판으로 배치한다. 통짜 계단 메시로의 교체는 별도 연결 작업이다.

## 충돌과 배치

환경 메시의 단순 충돌이 필요한 경우 닫힌 볼록 UCX를 만들고 `UCX_<메시명>_00` 형식으로 납품한다.
문틀은 좌·우·상단을 나누어 개구부를 비운다. 실제 사용 여부는 맵 액터의 충돌 설정에서 검수한다.
[Epic Static Mesh 문서](https://dev.epicgames.com/documentation/en-us/unreal-engine/fbx-static-mesh-pipeline-in-unreal-engine)

소품은 바닥 중앙 피벗, 평평한 받침, 명확한 바운드를 기본으로 한다. 소품의 존재와 배치가
이동/시야를 막으면 시드로 동일하게 생성되는 데이터 경로에 넣어야 한다. 클라이언트별 무작위 배치 금지.
모듈의 열린 경계·계단 착지·통로를 소품이 막지 않는지 확인한다.

새 테마는 조각 표와 모듈 표가 함께 필요하다. 조각 표에는 공용 폴백이 있지만 모듈 표에는 없다.
Blender 분위기 샘플은 조명/재질 검토용이고 게임 모듈 연결 완료를 뜻하지 않는다.
