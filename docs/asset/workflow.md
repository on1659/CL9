# 모델 생성·Blender 제작·내보내기·검수

## 컨셉 승인부터 시작하거나 재개할 때

`$cl9-model-concept`는 [범위·승인·재개 절차](model-concept.md)를 적용한다.
컨셉 이미지와 실제 Blender 외형 검토를 유지하며, 전체 제작 요청은 짧은 동작 시험·리깅·클립·엔진 검수까지 이어간다.
컨셉/모델만 요청된 경우 해당 범위에서 끝내며, 전체 제작을 인계서만으로 완료 처리하지 않는다.
이미 승인된 모델의 후속 제작은 해당 승인 근거와 현재 인계서를 읽고 이어간다.

## 1. 제작 카드부터 작성

[양식](brief-template.md)을 분류 폴더에 복사한다. 대상의 Alias/SubAlias, 판정 크기, 피벗,
동작 목록, 사용 중인 리그와 UE 연결 위치를 채운다. 외형이 미결이면 초안 치수를 명시한다.
사용자 레퍼런스나 기존 팩과 어울리는지 작은 샘플로 확인한다.
이미 모델별 현재 인계서가 있으면 그 문서를 갱신하고 제작 카드를 중복 작성하지 않는다.
공통 규격은 [common.md](common.md), 도구 사용법은 `tools/`, 모델별 요구와 상태는 해당 제작 카드/인계서가 관리한다.

## 효율적인 제작·검수

모델·리그·애니메이션의 신규 제작과 수정·재개에 적용한다. 사용자가 요청한 범위와 최종 품질 조건을 유지하면서 반복 호출과 재작업을 줄인다.

- **재개는 현 상태에서:** 기존 카드/인계서 하나에서 승인 외형, 편집 원본, 실행 중 작업, 통과한 검사, 실패 구간을 확인한다. 이미 검증된 단계나 실행 중인 생성·베이크·렌더를 중복 시작하지 않는다. 현재 단계·작업 ID/로그·실패 프레임·다음 행동을 그 문서에 짧게 갱신하여 긴 대화 전체를 다시 읽지 않고 이어갈 수 있게 한다.
- **구조를 짧게 검증:** 새로 만들거나 구조를 바꾸는 동작은 가장 어려운 약 2~3초에서 손 접촉, 몸의 통과 공간, 승인 실루엣, 관절 경로를 함께 확인한 뒤 긴 클립으로 확장한다. 같은 구조의 검증 증거가 있으면 재사용한다. 수납 공간 확보를 위해 승인된 겉모양을 임의로 부풀리지 말고 내부 자세·개구부·접촉 경로부터 해결한다. 정지 소품·외형만 요청된 작업에 동작 시험을 강제하지 않는다.
- **실패 원인부터 수정:** 같은 관통·외형 붕괴·관절 튐이 재발하면 실패 프레임과 원인 가설을 기록하고 통로·웨이트·회전 보간·리그·천 제어 중 원인을 좁힌다. 수치만 조금씩 바꾸어 전체 베이크/렌더를 반복하지 않는다. 주요 포즈 사이의 움직임과 회전 연속성도 같은 짧은 시험에서 검사한다.
- **변경 구간부터 검수:** 수정한 구간과 앞뒤 전환을 먼저 검사하고 저해상도·정상 속도 프리뷰로 움직임을 확인한다. 위험 프레임은 측면/근접 비교 시트로 묶는다. 확인 후 요청된 전체 범위의 최종 수치 검사·시각 검수·납품 해상도 렌더를 수행한다. 전역 리그/토폴로지 변경처럼 영향 범위가 넓으면 관련 전체 검사를 다시 한다. 부분 검사 통과를 전체 합격으로 표시하지 않는다.
- **실행·조회 묶기:** 수정과 실행에서 독립적인 작업은 묶고, 의존하는 단계는 완료 결과를 받은 뒤 실행한다. 베이크·렌더·QA는 기존 프로세스 핸들/작업 ID로 완료·실패를 기다리고 최종 요약을 받는다. 필요하면 실행 스크립트가 내부에서 진행을 감시하게 한다. 변화 없는 로그 꼬리·프로세스 조회를 모델 호출로 연속 반복하지 않는다. 중간 조회는 진단이나 의미 있는 진행 확인이 필요할 때 묶어서 한다.
- **필요한 결과만 읽기:** 코드는 변경할 함수/줄과 의존 부분을 읽고, 로그·QA는 실패 원인·프레임 범위·대표 표본·결과 경로를 요약해서 받는다. 전체 코드·장면 목록·대량 정점/프레임 데이터를 반복 출력하지 않는다. 원본과 상세 증거는 파일에 보존하고 원인 파악에 필요한 경우 범위를 넓혀 읽는다.
- **GPU 작업 조율:** 무거운 Blender 렌더와 Unreal 촬영을 같은 GPU에서 겹치지 않게 순차 실행한다. 다른 채팅의 실행 작업과 공유 에디터 잠금을 확인하며, 자기 작업만 조율한다. 실패 시 저장 원본과 완료 프레임을 보존하고 실패 구간부터 복구한다.

## 2. Blender 작업

1. 연결된 씬·오브젝트·열린 파일을 조회한다. 현재 사용자의 작업 파일을 임의로 지우지 않는다.
2. 에셋별 `.blend` 또는 전용 컬렉션에서 시작하고, 처음부터 `ArtSource`에 저장한다.
3. 크기 가이드 → 블록아웃 → 메시/UV/재질 → 리깅 → 클립 순으로 진행한다.
4. 중립광 정면·측면·3/4와 게임의 어두운 조명으로 확인한다. 조명으로 형상 오류를 감추지 않는다.
5. MCP 실행 스크립트는 자신의 오브젝트만 수정하게 하고, 다시 실행할 때 중복 생성하지 않도록 한다.
   파괴적 수정 전 원본을 보존한다. 실행 오류와 현재 씬 상태를 확인한 후 다음 단계로 간다.

여러 세션이 작업하거나 사용자 씬이 열려 있으면 에셋 전용 파일과 별도 background Blender 프로세스를 사용한다.
같은 라이브 Blender 씬을 여러 세션이 동시에 초기화/저장하지 않는다. 단독 프로세스에서도 자신의 출력만 수정한다.

### 이미지 기반 생성 모델로 시작할 때

1. 카드의 입력 이미지를 직접 보고 출처·해시·버전을 기록한다. TRELLIS는 [검증된 실행 지침](tools/trellis2.md)을 따른다.
2. 원시 GLB·생성 설정·중간 파일은 버전별로 보존한다. 조건을 바꾼 후보는 새 출력 폴더를 쓴다.
3. 실제 GLB를 읽고 정면·측면·뒤·3/4를 확인한다. 이미지 생성 결과와 3D 렌더를 구분한다.
4. 작업 사본에서 축·크기·원점을 확인하고, 생성 오류·UV·재질·관절 토폴로지를 정리한다.
5. 움직여야 하는 부분은 리그·웨이트를 만들고 극단 포즈를 시험한다. 벗는 의상은 내부 공간·입구·두께·잡는 지점이 필요하다.
6. 렌더 성공, 정지 모델 완성, 리그 검수, 동작 검수, 엔진 검수를 각각 기록한다. 생성기는 리깅/애니메이션 완료의 증거가 아니다.

닭 탈의 구체적인 순서·타이밍·접촉 검수는 [현재 인계서](monster/chicken_disguise-animation-handoff.md)에만 둔다.

## 동물·탈 몬스터의 전체 제작

전체 모델·리그·애니메이션·인게임 제작 요청에 적용한다. 아래는 기본 순서이며, 기존 검증 산출물과 실제 요구에 맞게 필요한 단계부터 진행한다. 탈착이 없는 동물·소품에는 의상 제작을 강제하지 않는다.

### 외형·구조 계약과 도구 선택

- 평상시 동물, 괴물 본체, 탈착 중간 모습을 함께 설계한다. 승인된 실루엣·비율·색과 변경 가능한 항목을 카드에 적는다.
- 소의 몸통/뿔/발굽, 닭의 날개/볏, 벌의 날개/다족처럼 종별 구조를 구분한다. 몸이 탈 안에 접히는 자세, 개구부, 손이 잡을 지점, 바닥에 떨어진 형태를 확인한다. 단단한 장식이 천처럼 녹거나 늘어나지 않게 부착 방식을 설계한다.
- 직접 모델링과 이미지 기반 3D 생성 중 외형 재현·편집 가능성·현재 환경에 적합한 것을 선택한다. 생성 모델은 초안이며 관절/손/탈 입구의 변형용 토폴로지·두께·UV/재질은 따로 확인한다. 원시 결과와 수정본을 보존한다.
- 재사용은 제작/검사 스크립트, 명명, 출력/검수 절차 위주로 한다. 뼈대·클립 재사용은 실제 관절 구조·축·기준 포즈·비율이 맞는 경우만 하고 다시 검수한다. 같은 긴 팔다리와 얼굴을 모든 동물에 붙이지 않는다.
- 유료 도구는 사용자의 서비스·횟수·예산 허용 범위에서만 시험한다. 무료/유료 여부나 브랜드로 품질을 추정하지 않는다. 실제 생성/보정 방식과 도구 버전을 기록한다.

### 어려운 약 2~3초부터

외형 검토를 마친 초안과 최소 리그로 가장 위험한 구간 하나를 만든다. 예: 탈 집기·들기, 뿔/머리의 입구 통과, 긴 다리 수납.
정밀 표면·전체 30초 렌더 전에 **같은 탈이 손을 따라 들리는지, 몸이 공간을 통과하는지, 닫힌 외형이 유지되는지** 확인한다.

손/발의 지지와 집기점을 명시하고 접촉 유지·해제 시점을 키로 제어한다. 주요 포즈와 팔다리 이동 경로를 먼저 설계한다.
큰 탈 변형은 뼈·형태 키·직접 변형으로 제어하고, 물리는 필요한 처짐과 잔흔들림부터 보조적으로 시험한다. 전체 탈을 무조건 천 솔버에 넘기지 않는다.
솔버는 겹침이 없는 시작 상태·충돌 두께·고정점을 점검하고 짧게 실행한다. 계산이 성공해도 닭/소의 볼륨이 무너지면 외형 시험 실패다.

이 구간을 목표 엔진에도 작게 왕복시켜 메시·리그·재질·탈 변형을 재현할 경로를 확인한다. Blender의 제약/모디파이어/시뮬레이션이 파일 내보내기만으로 그대로 전달된다고 가정하지 않는다.
몸은 스켈레탈, 탈은 지원되는 스켈레탈/모프/천 방식 등으로 소비 계획을 정한다. 베이크된 GeometryCache가 필요하면 프리뷰/특정 연출 용도와 런타임 제약을 명시한다.
엔진 접근이 없으면 오프라인 제작은 계속할 수 있지만 왕복 미검증 위험과 후속 작업을 남기고 검증된 대량 제작으로 확장하지 않는다.

실패하면 원인과 수정할 구조를 좁혀 같은 구간을 재시험한다. 무작정 긴 렌더·유료 재생성 횟수를 늘리지 않는다. 반복 실패 시 탈 입구·수납 자세·접촉 방식 또는 리그를 재설계한다.

### 게임용 모델·리그와 전체 클립

짧은 시험에서 확인한 구조를 유지하여 변형용 메시·UV·재질/베이크·성능 예산을 정리한다.
단일 루트, 관절 체계, 기준 포즈, 고정 길이 팔다리, 손가락/날개/꼬리 등 필요한 제어를 만든다. 사족·이족·다족·비행형은 종별로 설계한다.
극단 포즈에서 웨이트, 관절 부피, 좌우/축, 발·손 지지, 단단한 장식 부착을 검수한다. 편의상 뼈 스케일로 길이를 늘려 탈을 통과시키지 않는다.
스타일상 축소가 요청됐다면 적용 시점·배율을 명시하고 정상 관절 변형과 분리한다. 닭에서 쓴 “숨은 뒤 축소”를 모든 동물의 필수 동작으로 만들지 않는다.

탈착은 **별도 행동**으로 저작한다. 벗기는 실밥/입구 열림 → 몸 통과 → 탈의 낙하/접지, 입기는 몸 숙임 → 같은 탈 집기 → 펼치기 → 팔다리/몸 넣기 → 여밈의 목표를 해당 종에 맞춘다.
입기를 벗기의 단순 역재생으로 대신하거나, 요청에 없는 메시 숨김/교체로 접촉 실패를 감추지 않는다.
손 집기/지지 전환, 무게중심, 발 미끄러짐, 천 부속 지연을 보정한다. AI 모션은 시작 후보일 수 있지만 “들기” 프롬프트가 실제 들기를 구현했다는 증거는 아니다.

카드의 요청 목록에 따라 대기·걷기·달리기·벗기·입기 등 클립을 분리한다. 요구하지 않은 공격/죽음 세트까지 자동 확대하지 않는다.
각 클립에 이름·길이·fps·프레임 범위·루프·루트 이동 방식·속도·전환/이벤트를 기록한다. AI 이동용 제자리 동작과 연출용 이동 경로를 구분한다.
외형 동일성, 루프 경계, 입기/벗기 전후 상태, 시작·중단·재시작을 확인하고 공통 절차로 내보낸다.

### 검수 판정

|---|---|
| 형태 | 승인 외형과 열린/닫힌 탈 볼륨·후면·밑면·장식 유지 |
| 몸–탈 | 손가락·손톱·뿔 등 포함 범위를 명시한 교차/내부 노출 검사 |
| 탈 자체 | 자기 교차·뒤집힘·과도한 신장·의도한 봉제 겹침 구분 |
| 접촉 | 손 표면–집기점 거리와 미끄러짐, 잡고 놓는 시점, 발/지지 손 접지 |
| 움직임 | 관절 길이·갑작스러운 포즈 튐·무게 이동·발 디딤·속도·전환 |
| 화면 | 1배속·중립광 정면/측면/후면의 위험 구간과 실제 게임 조명 |

수치 검사는 모델의 실제 단위/크기에 맞는 허용치와 검사 대상·프레임 범위를 먼저 기록한다.
전체 프레임 검사와 시각 표본을 구분하고, 삼각형 교차 0을 자연스러움·모든 내부 충돌 0으로 확대하지 않는다. 의도한 봉제 접촉과 명백한 관통을 구별한다.
손 집기 불일치·몸의 관통·닫힌 상태의 본체 노출 등 중요한 실패는 시간/프레임·부위·증거와 다음 수정을 남긴다.
**내보내기 성공, 보기 좋은 스틸, 3배속·야간 영상만으로 합격시키지 않는다.**

## 3. FBX 내보내기 프로파일

**아직 CL9에서 신규 제작 모델의 UE 왕복 검수를 마친 공통 프리셋은 없다.** 다음 설정은
첫 왕복 테스트의 출발점이며, 성공한 Blender/내보내기 도구/UE 임포터 버전과 옵션을 카드에 저장한다.
프로파일 변경 시 기준 큐브와 짧은 리그 클립을 먼저 재검수한다.

| 설정 | 신규 자체 리그/메시의 시작값 |
|---|---|
| 파일 | FBX, 선택한 납품 오브젝트만, 내보내기 Scale 1 |
| 축·단위 | +X Forward / Z Up, Apply Unit 활성화; UE 임포트 결과 +X 정면·실제 cm 확인 |
| 변환 | 스켈레탈의 실험적 Apply Transform은 기본 끔; 리그에 사후 변환 적용 금지 |
| Static Mesh | Mesh + 필요한 충돌만. 카메라·조명·가이드 제외. Animation 끔 |
| Skeletal Mesh | Mesh + Armature. 기준 포즈. Animation 끔. Add Leaf Bones 끔 |
| Skeleton | 단일 root·필요한 변형 뼈·명시한 부착 뼈를 보존. Only Deform 사용 시 root/부착 뼈 유실 검사 |
| Animation | 같은 리그, 현재 클립만 Bake. All Actions/NLA 전체 내보내기 끔. 샘플 간격 1, Simplify 0부터 검수 |
| 텍스처 | FBX에 묻어두지 않고 export/textures에 명시적으로 납품 |

기존 Manny/구매 리그는 그 리그의 검증된 프로파일이 우선이다. 뼈 축을 새 프로파일에
억지로 맞추거나 새 Skeleton을 자동 생성해서 호환됐다고 처리하지 않는다.

Epic의 FBX 파이프라인은 FBX 2020.2 기반이다. Blender의 FBX 출력이 같은 버전이라고 가정하지
않으며 실제 임포트 호환성을 확인한다. [Epic FBX 안내](https://dev.epicgames.com/documentation/unreal-engine/fbx-content-pipeline?lang=en-US)
와 [Blender FBX 안내](https://docs.blender.org/manual/en/5.2/files/import_export/fbx_legacy.html)를 참고한다.

## 4. Unreal 왕복 검수

1. 테스트 위치로 임포트. 1m 큐브=100cm, Actor Scale=1에서 크기·정면·원점 확인.
2. 원본 바운드, 실제 액터에 적용된 크기, 충돌을 각각 확인. 특히 아이템은 자동 배율 적용 후 확인.
3. 머티리얼 슬롯 순서, UV, 노멀 방향, 텍스처 채널, LOD 전환을 확인.
4. 스켈레탈은 뼈 이름/부모/기준 포즈와 기존 Skeleton 호환 확인. 1배속 이동, 경직, 죽음 클립 확인.
   애니메이션 임포트는 **Interchange 로만** — 레거시 FBX 경로(`Interchange.FeatureFlags.Import.FBX 0` + `force_front_x_axis`)로 넣은 클립은
   런타임에서 요가 −90° 돌아 있었다(2026-09-21, 동물 반응 클립 17개 — `docs/asset/evidence/032-creature-react-clips.json`·`034-execute-clips.json`
   의 옛 판이 그 경로였다; `docs/asset/monster/README.md`). 같은 에셋을 덮을 땐 임시 폴더 임포트 → consolidate → rename(참조 유지).
5. 데이터 행/BP에 연결. 몬스터 Yaw, 플레이어 기존 메시 회전, 아이템 부착 위치를 확인.
6. 1인칭/동료 화면, 걷기/추격, 운반/던지기/요리, 조각 연결 등 분류별 게임 검수를 수행.
7. 2인 PIE에서 호스트·클라이언트의 표현이 상태와 맞는지 확인. 제작 카드는 날짜·환경·실패/미실행을 기록.

UE 연결은 메시·AnimBP·데이터/BP 참조로 한다. C++에 에셋 경로를 넣지 않는다.
에셋이 요구하는 새 기능은 카드의 **연결 필요**로 남긴다. 해당 구현까지 요청된 경우에만 별도 작업으로 처리한다.

## 5. 납품 묶음과 실제 게임 검수 증거

요청 범위에 맞는 편집 가능한 `.blend`, 원본/작업본 구분, 게임용 메시·리그·동작 출력, 텍스처와 필요한 캐시, 제작 카드·manifest·QA를 납품한다.
기반 컨셉·메시·리그·모션의 출처를 각각 기록한다. 생성기 이름만 적어 나중의 직접 보정을 누락하지 않는다.

애니메이션은 동작별 **처음부터 끝까지 1배속 MP4**와 전체 연결 영상, 접촉/통과 위험 구간의 측면·근접 검수 영상을 제공한다.
파일의 해상도·fps·길이·프레임 수·전체 디코딩과 실제 시작/중간/끝 및 실패 위험 장면을 확인한다. 메타데이터/표본 확인을 전체 동작 시청으로 부풀리지 않는다.
가속 영상은 속도를 표시하고 정상 속도 영상을 함께 둔다. 사용자에게 실제 영상 미리보기 또는 절대 경로 링크를 제시한다.

**비교/검수 영상 우측 상단**에 실제 제작 방식·버전·재생 배율·`Blender 렌더 / 인게임 프리뷰 / 게임 연결 검수` 구분을 작고 읽기 쉽게 표시한다.
예: `TRELLIS.2 외형 + Blender 직접 리깅/동작 | v02 | 1x | Blender`.
확인하지 못한 채팅 모델(Astra 등)이나 서비스(Tripo 등)를 출처로 붙이지 않는다. 표시는 원본을 보존한 파생 영상에 넣고 동작을 가리지 않는다.
같은 에셋의 최종 비교 영상은 버전별 납품/preview 폴더 한 곳에서 찾을 수 있게 하고 카드에 경로를 남긴다.

엔진 검수는 다음을 구분해 증거를 남긴다.

- **임포트:** 파일·스켈레톤·변형/재질·크기·축이 엔진에서 맞음.
- **프리뷰:** 테스트 맵의 캐시/시퀀스 또는 애니메이션 미리보기에서 재생됨.
- **게임 연결:** 실제 동물 액터의 기존 상태/AnimBP/데이터 연결에서 요청한 클립과 전환이 작동함. AI 신규 구현이 필요하면 별도 미완료 항목으로 밝힘.
- **실행 검수:** 도구로 실제 플레이를 시작하고 상태 전환·반복·재진입/재시작과 관련 로그를 확인함. 기존 멀티플레이 상태가 범위에 있으면 호스트/클라이언트도 확인함. 저장 후 재열기에서 참조/재생이 유지되는지 점검함.

실제 엔진 조작 전 [공유 세션 잠금](../workflow/sessions.md)을 확인하고 자신의 잠금 범위에서 실행한다. 다른 세션의 에디터·씬·PIE를 임의 종료하지 않는다.
Blender 렌더를 인게임 영상으로 표시하지 않는다. 프레임별 엔진 캡처는 그 촬영 방식을 밝혀 실시간 성능 측정과 구분한다.
관련 로그 조회 없이 “오류 없음”, 실제 플레이 도구 호출 없이 “인게임 검수 완료”라고 쓰지 않는다.

기술 실패/미실행, 사용자 피드백, 바로 다음 수정, 실행 중 작업, 정확한 재개 파일/명령을 같은 제작 카드에 기록한다.
**제작됨 → Blender QA → 임포트 → 프리뷰 → 게임 연결 검수**를 구분하고 요청 범위에 못 미치면 전체 완료로 처리하지 않는다.
