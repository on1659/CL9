# CL9 필요한 모션 — 제작·재사용 우선순위

기준일: 2026-10-13. 게임 기획, 현재 C++ 상태/조작, `Content/`의 클립 파일,
닭 탈 괴물 최신 인계서를 대조한 **제작 논의용 목록**이다. 이 문서 작성 중 게임을 다시 실행한 것은 아니다.
`기존`은 파일과 연결 기록이 있다는 뜻이며, 모든 모션의 최신 외형·멀티 검수를 새로 통과했다는 뜻은 아니다.

## 이 문서의 역할

- **무슨 모션부터 제작·재사용할지**는 여기서 한눈에 본다.
- 모델·리그·완료 상태는 [catalog.md](catalog.md), 개별 동작의 상세·최신 증거는 모델 카드/인계서에서 관리한다.
- 상태 동기화·AnimBP·타이밍 규칙은 [시스템 애니메이션 문서](../systems/animation.md)가 정본이다.
- 게임 행동은 [기획 색인](../plan/README.md), 최신 구현 단계는 [build-order.md](../plan/build-order.md)를 따른다.
- 아래 `신규/보강 제안`은 제작 순서 제안이다. 새 조작·AI 상태·판정 시간을 확정한 것이 아니다.
  `docs/model/`이나 별도 모델 목록을 만들지 않는다.

**핵심 방향:** 동물 상태는 귀엽고 읽히게, 탈 밖 괴물은 같은 몸의 움직임이 불편하게 뒤틀리도록 한다.
위협은 공격 전에 읽혀야 하고, 잡힌 플레이어의 넘어짐은 동료 화면에서도 보여야 한다.
스토리 방향은 [story.md](../plan/story.md), 승인된 닭 외형·동작은 [현재 인계서](monster/chicken_disguise-animation-handoff.md)가 정본이다.

| 닭 `chicken_a` | 10 | Idle / Walk / Run / LookAround / HitReact / PushReact / WakeTelegraph / Death | `PounceWindup → Catch`, 헛침은 Catch 앞부분 재사용 | 공격 예고가 보이는지, 덮침 뒤 복귀, 수색 LookAround 실제 소비 |
| 거위 `goose_a` | 11 | 위 기본 묶음 | Sleep / AlertWindup / Honk | 경보 준비→울음의 구분. **Catch를 새로 복제하지 않음** |
| 돼지 `pig_a` | 10 | 위 기본 묶음 | Execute + 기존 Catch 파일 | 주 공격은 Execute. 피해 농부 짝·접촉·끝 자세 검수; Catch 파일 존재를 주 공격 연결로 오해하지 않음 |
| 너구리 `raccoon_a` | 10 | 위 기본 묶음 | Execute / Catch | 스토킹 중 정지·후퇴·재이동 전환, 등 뒤 처형 짝 검수 |
| 양 `sheep_a` | 9 | 위 기본 묶음 | Catch | 현재 테스트 종. 새 최종 캐릭터 선정을 확정한 것으로 취급하지 않음 |

총 **50개 파일**이다. `HitReact`와 `PushReact`는 다른 경직이므로 하나로 합치지 않는다.
공격 길이·피격 시간·접촉 앵커는 [몬스터 제작 규격](monster/README.md)과 게임 데이터가 정본이다.
옛 `build-order` 5e의 ‘처형 클립 남음’ 문구만 보고 Execute를 다시 만들지 않는다.
현 파일과 후속 [시스템 기록](../systems/animation.md)을 확인한 다음 부족한 연결/품질만 고친다.

## 3. 현재 닭 탈 괴물 — 가장 먼저 만들 게임용 묶음

정본은 [chicken_disguise-animation-handoff.md §21](monster/chicken_disguise-animation-handoff.md#21-원래-괴물과-작은-닭의-걸음-추가--2026-10-13)이다.
승인된 내부 괴물과 귀여운 둥근 닭 외형을 유지한다. 기존 `chicken_a`와는 별도 제작물이다.

현재 결과는 **입기 → 완전 은폐 → 축소 → 작은 닭 걸음 → 복원 → 벗기 → 괴물 걸음**의
GeometryCache/LevelSequence 게임 월드 프리뷰다. 영상과 실제 PIE 검수 기록은 있으나,
새 SkeletalMesh·AnimBP·MonsterTable·AI·멀티 상태 연결이 된 결과는 아니다.
한 타임라인을 틀어 놓는 것과 추격/공격에 맞춰 움직이는 것은 별도 작업이다.

| 제작 묶음 | 필요한 모습 | 현재 상태 | 다음 작업 |
|---|---|---|---|
| 닭 대기 | 완전히 입은 작은 둥근 닭만 남음, 괴물 노출 없음 | 프리뷰의 닫힌 자세 있음 | **P0** 독립 Idle 루프; 호흡에도 실루엣·은폐 유지 |
| 닭 걷기 | 짧은 다리 뒤뚱거림 | 왕복 프리뷰 있음 | **P0** in-place Walk 분리. 루프 이음·발 접지·기준 속도 기록 |
| 닭 달리기 | 날개/몸통 반동이 읽히는 추격 | 현재 새 시안에 독립 Run 미확인 | **P0** Walk 단순 배속보다 추격용 보폭·무게감 저작 |
| 괴물 대기 | 원래 괴물 형상이 보이는 자세 | 정리/대기 자세 있음 | **P0** 독립 Idle 루프; 팔다리 길이·접지 유지 |
| 괴물 걷기 | 긴 팔과 다리의 원래 괴물 걸음 | 왕복 프리뷰 있음 | **P0** in-place Walk 분리, 팔·다리 반대 흔들림 검수 |
| 괴물 달리기 | 탈 밖 모습의 추격 | 현재 독립 Run 미확인 | **P0** 새 달리기 저작. 실제 추격 규칙·속도는 데이터 연결 때 확정 |
| 탈 벗기/밖으로 나오기 | 천을 잡고 벗음, 몸이 단계적으로 드러남 | 프리뷰 있음 | **P0** 독립 원샷·시작/끝 자세 정리; 정밀 그립·접힌 천 겹침 보강 |
| 탈 집기 → 들어가기 → 닫기 → 축소 | 탈을 회수하고 들어간 뒤 **완전히 가려진 다음** 작아져 귀여운 닭이 됨 | 프리뷰 있음 | **P0** 하나의 착용 원샷 안에 논리 구간으로 관리 가능. 은폐 전에 줄어들거나 Hidden 토글로 대체하지 않음 |
| 공격 예고 → 공격 → 복귀 | 닭/괴물 상태에 맞는 읽히는 위협 | 새 시안 전용 공격 미확인 | **P0** 닭 Catch 계열 의미부터 매핑. 괴물의 치명 공격은 해당 게임 규칙 확정 후 피해자 짝과 함께 제작 |
| 피격 / 밀려남 / 쓰러짐 | 두 모습 각각의 반응 | 새 시안 전용 연결 미확인 | **P0** HitReact / PushReact / Death 의미에 대응. 기존 종 클립은 리그 호환 검수 전 복사 금지 |
| 출발·정지·제자리 회전 | 90°/180° 회전에도 발이 순간 이동하지 않음 | 왕복 프리뷰 전환은 후속 다듬기 대상 | **P1** 먼저 블렌드/방향 전환으로 해결하고 부족하면 Start / Stop / Turn 클립 추가 |
| 닭의 알 모으기·쪼기 | 사연이 새는 평상시 행동 | 스토리 초안/후보 | **P2** 알 회수 AI·아이템 판정을 별도로 확정한 뒤. 분위기용 포즈와 실제 알 이동을 구분 |

**1차 제작 단위 제안: 8묶음** — 닭 Idle/Walk/Run, 괴물 Idle/Walk/Run, 벗기, 입기(집기·들어가기·닫기·축소 포함).
이는 게임 플레이 전체 완성 수가 아니다. 뒤이어 공격·피격 묶음과 AI 연결 검수가 필요하다.
행동 수와 실제 파일 수는 같을 필요가 없다. 착용 한 클립의 구간을 각각 중복 파일로 만들지 않는다.

스토리의 광폭화가 그 판 안에 풀리는지, 다시 입는 게임 조건은 [story.md의 미결](../plan/story.md#미결)이다.
사용자가 요청한 입고 벗는 **반복 프리뷰**는 유지하되, 게임에서도 일정 시간마다 자동으로 반복한다는 규칙을 새로 확정하지 않는다.
현재 코드의 죽음 비명 `RageTime`·너구리 격분은 사냥 행동이며, 탈이 터지는 새 변신 구현 완료의 근거가 아니다.

## 4. 후속 몬스터/스토리 동작 — 확정 전에는 제작 분모에 넣지 않음

[스토리 초안](../plan/story.md)의 동물 목록은 기존 런타임 목록과 다르다.
이 문서가 기존 종을 삭제하거나 새 종의 개발을 승인하지 않는다.

| 후보 | 평상시 행동 | 위협/광폭화 표현 후보 | 착수 조건 |
|---|---|---|---|
| 소 | 짚 꾸러미 핥기, 자리로 돌아가기 | 고개 숙여 돌진, 등 갈라짐/뿔 변화 | 종·외형·꾸러미 기믹 확정 |
| 다람쥐 | 선반을 돌며 물건 세기 | 선반 사이 도약·덮침, 꼬리 풀림·천장 이동 | 선반 이동/경로 규칙·공격 확정 |
| 벌 | 벌통 주변 떠 있기·혼자 윙윙대기 | 비행 충돌, 가죽이 터지며 무리로 분산 | 이동·군집·퇴각 규칙 확정 |
| 돼지 새 외형 | 먹이통 앞 행동 | 현재 처형 의미를 유지하는 새 외형 공격, 입 변화 | 새 컨셉 승인; 기존 박치기 클립과 스토리 ‘먹기’의 차이 결정 |
| 거위/너구리 새 외형 | 현재 경보/스토킹에 맞춘 행동 | 탈이 터지는 종별 전환 | 명단·컨셉 승인과 실제 광폭화 규칙 확정 |

## 5. 소품·요리·맵에서 움직일 것

전부 캐릭터 뼈 애니메이션으로 만들 필요는 없다. 현재 물리·재질·코드 표현을 재사용한다.

| 대상 | 필요한 변화 | 방법 / 상태 |
|---|---|---|
| 수레 | 이동·급정지·회전, 바퀴 회전, 짐칸 물건 흔들림 | 몸체/짐은 현재 물리. 바퀴 회전 표현은 제작 규격상 연결 필요; **P1 보강 후보** |
| 계란·고기 | 날것 → 익음 → 탐, 계란 깨짐 | 상태별 메시·재질과 물리. 별도 ‘요리 캐릭터’ 클립을 만들지 않음 |
| 조리대 | 불꽃·열기·김·타기 직전/탄 연기 | 현재 cooking 표현 기록 있음. 놓기/집기 손 모션만 플레이어 공용 동작 후보 |
| 트럭 레버·전원 스위치 | ON/OFF 위치·상태 변화 | 기존 조작/코드 표현 재사용. 손 접촉은 공용 상호작용 보강 후보 |
| 항아리·납품 창구 | 물건 넣기/소비의 읽히는 피드백 | 현재 반납·납품 상태에 맞춤. 전용 전신 모션보다 공용 손짓·효과 우선 |
| 트럭 도착·출발, 회사 이동 | 짧은 이동·시점 연출 | 현재 판 시작/회사 흐름 기록을 먼저 확인. 스켈레탈 모션 제작 수에 합산하지 않음 |
| 맵 등장 실루엣·조명·안개 | 도착 직후 긴장감 | 기존 7j 연출 확인. 공격 가능한 새 몬스터를 연출만으로 추가하지 않음 |

요리는 **놓기·기다리기·집기**다. 칼질·휘젓기·뒤집기·불 조절·우유 짜기는 현재 필수 모션이 아니다.
동료를 일으켜 세우는 구조 모션, 총기·재장전·벽점프도 현재 제작 목록에 자동 추가하지 않는다.
보유 템플릿 파일에 그런 동작이 있다는 사실은 해당 게임 기능이 있다는 뜻이 아니다.

## 6. 제작·검수 결과를 이어서 남기는 방법

각 묶음 작업은 모델별 현재 카드/인계서에만 상세 기록하고 이 문서는 우선순위/링크만 갱신한다.

1. 사용할 모델·리그·게임 상태를 먼저 지정한다. 새 컨셉이면 [승인 파이프라인](model-concept.md)을 따른다.
2. 루프/원샷, 시작·끝 자세, 기준 속도 또는 상태 시간, 물건 접촉 구간을 정본 카드에 기록한다.
3. Blender 원본과 실제 내보낸 파일을 저장하고, 발·손·몸–탈/의복 관통을 검수한다.
4. **움직이는 영상을 반드시 제출한다.** Blender 검수 영상과 UE 연결 뒤의 인게임 영상을 구분한다.
